## Outcome
Retrieval does not rebuild its index on every query: a persistent i8 working set with version invalidation, a wired document embedding cache with a stable key, indexed one-hop expansion, and prompt formats aligned with the Phase 2 spec. Today every search loads all notes and scans them, and cache_doc_embedding has no caller. Source: Phase 2 and shared plan section 4.


## Scope
crates/memb-rag, memb-embed, memb-store expansion.


## Plan (Todo Tree)
- [ ] A1 [START] [lane:main] Persistent i8 hot working set per store with a project_kb_version invalidation key, f32 top-20 rescore; no full re-embed or full scan per query
- [ ] A2 [lane:main] [after:A1] Wire DOC_EMBED_CACHE writes (cache_doc_embedding has no caller) with a stable hash key (title + desc + model + mrl) instead of note id plus DefaultHasher
- [ ] A3 [lane:main] [after:A1] Adjacency index (IN/OUT edges) for 1-hop expansion, or a recorded replacement; per-knowledge claim cap
- [ ] A4 [lane:main] [after:A1] Reconcile prompt formats: query prefix and document format on the server path, query truncation (Phase 2 says 512 tokens, code uses 128), or record approval
- [ ] T1 [lane:test] [after:A2,A3,A4] [ACCEPTANCE:MANDATORY] Measured: hot set under 5 MB for the test corpus, unchanged notes never re-embed, cache hit under 1 ms, expansion without loading all notes

## Prove
cargo test --workspace --locked --offline plus recorded measurements (hot set size, cache hit time).
