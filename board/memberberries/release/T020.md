## Outcome
The 2 GiB cap is a job-wide limit with kill-on-close, the memory governor thresholds (1200/1550/1750 MiB) actually gate background work, the in-process embedding model unloads when idle, and the hardware tier is chosen by a prober, or each is recorded as replaced. Source: shared plan section 1, Phase 1 section 2, Phase 2.


## Scope
crates/memb-win, daemon, memb-embed/memb-rag model lifecycle. Today the limit is per process (JOB_OBJECT_LIMIT_PROCESS_MEMORY), applied only by the daemon, and classify_pressure has no caller.


## Plan (Todo Tree)
- [ ] A1 [START] [lane:main] Job Object: job-wide memory limit and JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE (today only a per-process limit, daemon only); decide whether hook and MCP processes attach
- [ ] A2 [lane:main] [after:A1] Wire classify_pressure (no caller today) into the daemon: allow_background_jobs gating at the 1200/1550/1750 MiB thresholds, with budget tests
- [ ] A3 [lane:main] [after:A1] Idle unload of the in-process EmbeddingGemma model (300/600/900 s by tier) and optional session-start warm-up
- [ ] A4 [lane:main] [after:A3] Hardware prober (AVX-512/AVX2, physical cores, GPU) choosing the CpuLite/Balanced/GpuHigh tier, or a recorded replacement
- [ ] T1 [lane:test] [after:A2,A4] [ACCEPTANCE:MANDATORY] Tests: a child dies when the job closes; pressure above a threshold pauses background work; the model unloads after idle and reloads; tier chosen from a faked CPU report
