## Outcome
The curator works from evidence packets and its validated decisions (KNOWLEDGE_UPSERT, CLAIM_ADD, CLAIM_SUPERSEDE, RETRACT, DEFER) are applied to the memory graph AUTOMATICALLY, all kinds, with source_chunks on every node and rollback of every curation edit as the safety net. DECIDED by the user on 2026-11-25: full auto-apply (not a restricted set). The current build instead waits for a typed APPLY on every proposal; `memb proposals` stays as the manual path (for example when auto-apply is off). Depends on the linking/packets ticket (T016). Because every kind is applied automatically, rollback of creations, supersessions and retractions is a prerequisite, not an extra.


## Scope
memb-curator apply path, memb-store/memb-ops rollback for creations, supersessions and retractions (including grouped revisions), a daemon step behind curator.daemon_enabled (a separate switch decides auto-apply, off by default until rollback exists), safety rails (per-run limits on edits, no cascade retract, secret check, kill switch, audit list of what the last run changed).
