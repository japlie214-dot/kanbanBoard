# T001 — Recreate .venv at the repo's new location

## Outcome
`repos/etoroNightwatch/.venv` is a fresh venv created at its current path, with the same package set as before, and the full test suite runs through it.

## Why
Repo moved from `C:\Users\10102721\Documents\ClaudeFiles\etoroNightwatch` to `hq/repos/etoroNightwatch`. Every later ticket depends on trustworthy test runs on both interpreters (plan §12.2).

## Context
- `.venv/pyvenv.cfg` `command =` names the old path. Console launchers (`pytest.exe`, `pip.exe`, ...) embed the old interpreter path.
- Base interpreter: `C:\Users\10102721\AppData\Local\Programs\Python\Python313\python.exe` (3.13.4).
- `.venv` holds packages beyond `requirements.txt` (e.g. `curl_cffi`, `numpy`, `websockets`, `peewee` launchers present). Some code or probe may import them. Rebuilding from `requirements.txt` alone may drop them.
- Observed 2026-09-25: `.venv/Scripts/python.exe -m pip freeze` works (38 packages, incl. `curl_cffi`, `numpy`, `pandas`, `yfinance`, `peewee`). `.venv/Scripts/pytest.exe --version` and `pip.exe --version` print nothing: launchers broken. `fastapi`/`uvicorn`/`jinja2` from requirements.txt are NOT installed; keep it that way (freeze is the contract).
- Last known suite: 15 failed, 761 passed on both interpreters (doc/plan.md §2.1). Those failures are known and out of scope.

## Scope
Only `.venv/`. Scratch output under `hq/.runs/tmp`.
## Out of scope
Any product code, tests, `requirements.txt`, `.gitignore`, fixing the 15 known failures.

## Requirements
- Same package names and versions as the old venv.
- Old venv kept until the new one is proven.

## Design
Freeze-then-rebuild. The freeze is the contract: exact package list, not requirements.txt.

## Plan
1. `.venv/Scripts/python.exe -m pip freeze > ../../.runs/tmp/nw-venv-freeze.txt`. Verified to work.
2. Rename `.venv` to `.venv.old` (do not delete).
3. `C:/Users/10102721/AppData/Local/Programs/Python/Python313/python.exe -m venv .venv`
4. `.venv/Scripts/python.exe -m pip install -r ../../.runs/tmp/nw-venv-freeze.txt`
5. Run full suite both ways: `.venv/Scripts/python.exe -m pytest -q` and `.venv/Scripts/pytest.exe -q`. Also base interpreter `.../Python313/python.exe -m pytest -q`.
6. Diff `pip freeze` new vs old file.
7. Leave `.venv.old` in place; PM deletes after verification.

## Ripple effects
- `.venv` rebuild -> tests -> different package versions change results -> containment: exact freeze pins; diff in step 6.
- `.venv.old` in repo root -> git -> not ignored (`.venv/` pattern only) -> containment: never stage; PM removes after verify.
## Watch
- Freeze may contain `-e` or `file://` lines with old path: report them, do not guess.
- Do not background any server. Do not read `secrets/` or `config/.secrets.env`.
## Acceptance
- `.venv/pyvenv.cfg` `command` names the new path.
- `pytest.exe` launches without "Fatal error in launcher".
- Suite result equals 15 failed / 761 passed baseline or differences listed exactly.
## Prove
Paste: `pyvenv.cfg`, freeze diff, last line of each pytest run.
## Dependencies
none
## Done when
PM reruns step 5 and sees same result; freeze diff empty.
