# T013 — S5h: preflight gate 2 checks power and permissions through `Host.power_status()`; gate 3 polls eToro reachability for up to 90 s

## Outcome
`gate_2_power` and `gate_3_network` exist in `engine/preflight.py`, so all 12 gates are built. On the PC they pass via `DesktopHost` and a real HTTPS probe. On the Z10, the Android `Host` supplies real power data later. The gate logic is the same.

## Why
S6 (the dry-run session) needs a full 12-gate list. Without these two gates, preflight fails closed with "not implemented" every run. `DesktopHost.power_status()` (host.py:120–141) already reports the desktop as satisfied. Its docstring: "Preflight gate 2 is therefore a no-op off-device, which is correct".

## Context (PM read 2026-10-02; P = `app/src/main/python/nightwatch`)
- `P/host.py`: `PowerStatus` dataclass with fields `battery_percent: int | None`, `is_charging: bool`, `ignoring_battery_optimizations: bool`, `can_schedule_exact_alarms: bool`, `wake_lock_held: bool` (around lines 50–58; read for the exact definition). `Host.power_status() -> PowerStatus`.
- `P/config.py`: `RiskConfig.min_battery_percent: int = 40`.
- `doc/DESIGN.md` gate table:
  - gate 2 fails when on battery and < 40%, or the battery-optimization exemption is lost, or `canScheduleExactAlarms()` is false, or the wake lock could not be acquired;
  - gate 3 fails when there is "No DNS/HTTPS to `public-api.etoro.com` after 90s of polling (Wi-Fi re-associates lazily coming out of Doze)".
- The stub comments for gates 2 and 3 are at `P/engine/preflight.py:34–37`.
- PM observed 2026-10-02: `httpx.get("https://public-api.etoro.com/")` from the PC returns HTTP 302 in about 0.5 s. eToro connects are intermittently slow: one 120 s timeout was seen today.

## Requirements
**Gate 2.** `gate_2_power(*, status: PowerStatus, min_battery_percent: int) -> GateResult`, number 2, name `"power"`.
- Check these in order. The first failing one gives the reason:
  1. `not status.is_charging and (status.battery_percent is None or status.battery_percent < min_battery_percent)` → `f"on battery at {status.battery_percent}% (< {min_battery_percent}%)"`. Not charging with an unknown percent fails, printing `None`.
  2. `not status.ignoring_battery_optimizations` → `"battery-optimization exemption not granted"`.
  3. `not status.can_schedule_exact_alarms` → `"exact alarms not permitted"`.
  4. `not status.wake_lock_held` → `"wake lock not held"`.
- Pass with reason `"power ok"`.
- `details = asdict(status)` in every case. Add `asdict` to the existing `from dataclasses import dataclass, field` (preflight.py:114).

**Gate 3.** `gate_3_network(*, probe: Callable[[], None], timeout_seconds: float = 90.0, interval_seconds: float = 5.0, sleep: Callable[[float], None] = time.sleep, clock: Callable[[], float] = time.monotonic) -> GateResult`, number 3, name `"network"`.
- Loop:
  - call `probe()`. If it returns, pass with reason `f"reachable after {attempts} attempt(s)"` and `details = {"attempts": attempts, "elapsed_seconds": round(elapsed, 1)}`;
  - if it raises any `Exception`, record `f"{type(exc).__name__}: {exc}"` as `last_error`;
  - if `clock() - start + interval_seconds > timeout_seconds`, stop;
  - else `sleep(interval_seconds)` and try again.
- On stop, fail with reason `f"no network after {attempts} attempt(s) in {elapsed:.0f}s: {last_error}"`.
- Add a module function `etoro_reachability_probe(base_url: str = "https://public-api.etoro.com", timeout: float = 10.0) -> Callable[[], None]`. It returns a closure that does `httpx.get(base_url + "/", timeout=timeout, follow_redirects=False)`. **Any** HTTP response counts as reachable, so a 302 passes. It sends no credentials.
- Import `httpx` and `time` at module level. Both are already dependencies, httpx via the etoro client.

## Design
- Inject the probe, sleep and clock, so tests run instantly and with no network. Gate 3 is the only gate that waits, so making time injectable is mandatory.
- Gate 2 takes `PowerStatus`, not `Host`. S6 binds `host.power_status()` and `config.risk.min_battery_percent`. The gate stays a pure function.

## Plan
1. `preflight.py`: add `gate_2_power`, `gate_3_network` and `etoro_reachability_probe` after `gate_1_halt`. Update the stub comments and the built-gates lists (all 12 built; drop the "remain comment-only stubs" wording accordingly, and say "all twelve gates are built").
2. `tests/test_preflight_gates_2_3.py`:
   - gate 2: `DesktopHost().power_status()` with min 40 → pass; each of the 4 failure conditions on its own, by building `PowerStatus` directly; charging at 5% → pass; not charging at exactly 40 → pass; not charging at 39 → fail; not charging with `None` → fail;
   - gate 3, with a fake clock that advances only on `sleep`:
     - probe succeeds first time → pass, 1 attempt, `sleep` never called;
     - fails twice then succeeds → pass, 3 attempts, 2 sleeps of 5.0;
     - always fails, with timeout 90 and interval 5 → fails, the reason contains the last error text, and the attempt count is exactly 19 (attempts at t=0,5,...,90; at t=90, 90+5>90 stops), with 18 sleeps;
   - `etoro_reachability_probe` with `httpx.MockTransport` is not possible through `httpx.get`. Instead monkeypatch `httpx.get` in the preflight module namespace to return a 302 response → the probe returns without raising; to raise `httpx.ConnectError` → the probe raises.
3. Run Prove.
