# T006 — S5d: preflight gate 9 checks that today is an XNYS session and resolves its close

## Outcome
`gate_9_calendar` exists in `engine/preflight.py`. It passes only when the trading date is an XNYS session according to `exchange_calendars`. When it passes, it reports that session's real close, with early closes resolved. It also reports whether `market/calendar.py` agrees. That agreement is a cross-check only and never decides the result.

## Why
project.md S5. DESIGN_market_data.md §6 "Gate 9 — Calendar". `market/calendar.py` misses ad hoc closures, such as 2025-01-09 (DESIGN_market_data.md §2.3). `exchange_calendars` carries them in `adhoc_holidays`. Gate 9 is the authority that stops a session on a day the exchange is closed.

## Context (PM read 2026-10-02; repo `repos/etoroNightwatch`, P = `app/src/main/python/nightwatch`)
- `P/engine/preflight.py`:
  - `GateResult(gate, name, passed, reason, details=field(default_factory=dict))`.
  - `gate_1_halt` and `gate_4_clock` are the style to follow: one small function plus a test file.
  - Imports are at lines 112–135. `exchange_calendars` is not imported there and must not be (see Watch).
  - The stub comment for gate 9 is at lines 47–50.
- `requirements.txt:18` pins `exchange_calendars==4.13.2` for desktop. Android pins 4.11.1 (§2.6). Both have zero differing XNYS sessions for 2015–2027.
- Observed on `.venv` (pandas 3.0.5, xcals 4.13.2):
  - `xcals.get_calendar("XNYS")` works;
  - `cal.sessions` is a DatetimeIndex of tz-naive midnight `pd.Timestamp`;
  - the last default session is 2027-10-01;
  - `pd.Timestamp("2026-11-27") in cal.sessions` gives True;
  - `cal.session_close(pd.Timestamp("2026-11-27"))` gives `2026-11-27 18:00:00+00:00` (13:00 ET, an early close).
- `cal.is_session()`: DESIGN_market_data.md §2.6 recorded it raising `DateOutOfBounds` for every date under pandas 3.0.5. Precheck 2026-10-02 could NOT reproduce that: with pandas 3.0.5 and xcals 4.13.2 it returned True/False. The ban stays anyway, because the API differs across the pandas versions we ship (desktop 3.0.5, Python313 2.2.3, Chaquopy 2.1.3), and membership in `.sessions` is the single path the design names. Never call it.
- `P/market/calendar.py` has `is_trading_day(d: date) -> bool`, `session_close(d: date) -> time` (ET; 16:00, or 13:00 on an early-close day), and `EASTERN`.

## Requirements
1. Signature: `gate_9_calendar(*, trading_date: date, calendar: object | None = None) -> GateResult`, with gate number 9 and name `"calendar"`.
   - If `calendar` is None, the gate does a lazy `import exchange_calendars` inside the function and calls `exchange_calendars.get_calendar("XNYS")`.
   - Tests pass a real calendar, or a small fake with `sessions`, `first_session`, `last_session` and `session_close(ts)`.
2. Build `ts = pd.Timestamp(trading_date)`, which is tz-naive. Test membership only with `ts in calendar.sessions`. Never call `is_session`.
3. If `ts` is before `calendar.first_session` or after `calendar.last_session`, fail with reason `f"trading date {trading_date.isoformat()} outside calendar range {first.date()}..{last.date()}"`.
4. If `ts` is in range but not in `sessions`, fail with reason `f"{trading_date.isoformat()} is not an XNYS session"`. `details` includes `crosscheck_is_trading_day` (from `market.calendar.is_trading_day`).
5. If `ts` is a session, pass with reason `f"XNYS session; close {close_et:%H:%M} ET"`. `details` holds:
   - `close_utc`: ISO string of `calendar.session_close(ts)`;
   - `close_et`: `"HH:MM"`, converted with `ZoneInfo("America/New_York")`;
   - `early_close`: True when the ET close ≠ 16:00;
   - `crosscheck_is_trading_day` and `crosscheck_close_et` (`market.calendar.session_close(trading_date)` as `"HH:MM"`);
   - `crosscheck_agrees`: True if calendar.py says it is a trading day AND its close equals `close_et`.
6. Cross-check disagreement never changes `passed`. `exchange_calendars` is the authority.
7. The gate does no network calls and no DB access.

## Design
- One function in `preflight.py`, placed after `gate_4_clock`. Inside it, lazy-import `pandas` and `exchange_calendars`, so that importing `preflight` stays light and a broken wheel surfaces as a gate failure (the orchestrator turns the exception into `exception: …`), not as an import crash.
- Import `from ..market import calendar as market_calendar` inside the function too, because of the module-import tz hazard noted in §6.
- The `calendar` parameter exists for test injection. It follows the same closure style as the other gates: S6 binds `trading_date`.
