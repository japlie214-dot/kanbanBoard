# T056: Durable fill finalization (audit G06)

## Outcome
A buy intent is resolved only after its position is verified and its lot annotation is committed. Missing identity or annotation failure stops further sends in that session and HALTs.

## Why
Intent is marked filled/resolved before verification (executor.py:387-394), annotation errors become follow-up prose (executor.py:205-251), recovery scans only pending/sent (repo.py:1036-1046), and execute_buys continues after a tp_failed verification (executor.py:450-460).

## Context
Context cites readiness audit 2026-11-06 at HEAD 21c06ba (project.md). Builder re-verifies every line before editing. Do not touch android_entry.py, Kotlin or doc/ (T054 in flight).

## Scope
app/src/main/python/nightwatch/engine/executor.py, app/src/main/python/nightwatch/db/repo.py (new intent status filled_unannotated + migration 012), app/src/main/python/nightwatch/engine/session.py (veto handling), tests/test_executor.py, tests/test_executor_recovery.py, tests/test_schema_migrations.py.

## Out of scope
TP-clear semantics (T053 stands); close executor.

## Design
1. On fill: status filled_unannotated (unresolved). After verified position + annotation commit in one transaction: filled.
2. Recovery selects filled_unannotated and completes verification/annotation read-only; never resubmits.
3. Verification failure, missing position id or annotation exception: append to tp_failed (verification list), stop execute_buys loop immediately.
4. Recovered fill without position id follows the same HALT rule as fresh.

## Plan
migration 012 → repo → executor → session veto → tests → suites.

## Ripple effects
Limits/reservation queries must count filled_unannotated as reserved (repo.py:1015-1026).

## Watch
Migration number may collide with other tickets: take the next free one at build time.

## Acceptance
1. Annotation insert raises: intent stays filled_unannotated, no further buy sent, HALT, no final save.
2. Crash between fill and annotation: next recovery annotates, resolves, no resubmission.
3. Missing position id in recovery: HALT.
4. Clean path unchanged; reservations include the new status.
5. Both suites pass; migration fresh and from previous head.

## Prove
Both interpreters' full suites, offline fakes.

T055.
