# T034 — A session can store a phase A and a phase B decision, and a confirmed close is applied to its lot exactly once

## Outcome
- Migration `009_decision_phase_close_observations.sql` changes two things:
  - `decisions` gets `phase` ('A' | 'B' | 'single') with UNIQUE(session_id, phase). Existing rows become 'single'.
  - A new table `close_observations` records each observed close.
- `Repo.apply_confirmed_close(...)` marks the lot annotation closed and records exit evidence. It does this once only; a repeat call is a no-op.

## Why
- Consultant 2026-10-24 (ticket B): two-phase needs both decisions stored. A confirmed sale must survive a later failure and be applied exactly once.
- Precheck T033: `decisions.session_id` is UNIQUE (`db/schema.sql:106-123`), so a second `insert_decision` conflicts.

## Design (PM decisions)
1. **Decisions table rebuild** (SQLite cannot drop a UNIQUE constraint):
   - `CREATE TABLE decisions_new (... same columns ..., phase TEXT NOT NULL DEFAULT 'single' CHECK (phase IN ('A','B','single')), UNIQUE (session_id, phase))`;
   - `INSERT INTO decisions_new (all old columns, phase) SELECT ..., 'single' FROM decisions`, keeping ids;
   - `DROP TABLE decisions`, then `ALTER TABLE decisions_new RENAME TO decisions`;
   - recreate any index that existed on decisions.
2. **`Decision.phase: str = "single"`.** `insert_decision` writes it.
3. **`get_decision(session_id, phase: str | None = None)`:**
   - With `phase`, return that row or None.
   - With `phase=None` (all existing callers), return the authoritative decision: 'B' if present, else 'single', else 'A', else None.
   - `_decision_spy` therefore gets phase B's SPY context, which equals phase A's (§5: SPY is derived once). That is correct.
4. **`close_observations` table:**
   - `id INTEGER PK`;
   - `intent_id INTEGER NOT NULL REFERENCES intents(id)`;
   - `order_row_id INTEGER REFERENCES orders(id)`;
   - `order_id TEXT`;
   - `position_id TEXT NOT NULL`;
   - `observed_status TEXT NOT NULL CHECK (observed_status IN ('confirmed_closed','still_open','unresolved'))`;
   - `units_closed REAL`, `close_price REAL`, `closed_at TEXT`;
   - `raw_json TEXT NOT NULL DEFAULT '{}'`;
   - `observed_at TEXT NOT NULL`, `applied_at TEXT`;
   - index on `position_id`;
   - partial unique index `CREATE UNIQUE INDEX ux_close_obs_applied ON close_observations(position_id) WHERE applied_at IS NOT NULL` (one application per position, enforced by the DB).
5. **Repo methods:**
   - `record_close_observation(*, intent_id, order_row_id, order_id, position_id, observed_status, units_closed=None, close_price=None, closed_at=None, raw=None) -> int`: commits and returns the id.
   - `apply_confirmed_close(observation_id) -> bool`, in one transaction:
     - Load the observation. It must be `confirmed_closed`; otherwise raise ValueError.
     - If an observation for that `position_id` is already applied, return False and change nothing.
     - Else: UPDATE `lot_annotations SET is_open=0, exit_order_id=:order_row_id, updated_at=now WHERE position_id=:pid AND is_open=1`. Set `applied_at=now` on the observation and return True.
     - If no open annotation row matches, raise LookupError and roll back. A missing sidecar is a reconcile problem, not something to paper over.
     - Never touch entry_* columns, `entry_amount` or `book`.
   - `list_close_observations(position_id=None) -> list[dict]`.
   - `unapplied_confirmed_closes() -> list[dict]`: confirmed and not applied, ordered by id. Restart recovery uses it to finish an interrupted application.


### Precheck amendments (PM, 2026-10-24; binding, override anything above)
1. **Baseline:** `schema.sql` is the version-1 baseline. Do NOT edit it. Migration `009_*.sql` is additive and runs through the existing runner (`db/migrations/__init__.py:63-126`), exactly as 002–008 do.
2. **Decisions rebuild:** create the new table and copy the rows with the same ids. Keep the FK to `sessions(id)` with its existing ON DELETE behaviour, AUTOINCREMENT, defaults and every CHECK. Add `phase TEXT NOT NULL DEFAULT 'single' CHECK (phase IN ('A','B','single'))` and `UNIQUE(session_id, phase)`. Drop the old table and rename the new one, all inside the runner's transaction. The test must assert the copied ids, the FK cascade (delete a session and its decision goes), the sqlite_sequence continuation, and the CHECKs.
3. **Phase-B SPY:** `get_decision(session_id)` with no phase prefers B, then single, then A. B does not exist until a later ticket. The SPY fields are identical across phases by construction (decided once from one signal); the later two-phase ticket must assert this. T034 only documents it.
4. **Full-close contract:** `apply_confirmed_close` may set `is_open=0` only when the observation has `status='confirmed_full_close'`. That status is written only by T036, only after an `OrderStatus.FILLED` close plus a strict portfolio read showing the position absent. Any other observation status is stored but never applied. Partial closes are out of scope: storing a partial observation is allowed, applying one raises.
5. **Ownership:** the ledger covers app-owned close intents only (`intent_id` is required). Manual closes remain reconciliation discrepancies (unchanged).
6. **Exactly once:** enforce it with the partial unique index on the applied rows plus a transaction. A second apply for the same position returns False. Concurrency: a single writer is assumed (one session at a time, DESIGN_session §10); document this in the docstring.
7. **Entry-field wording:** apply touches only `is_open` and exit evidence. Do not claim that `update_lot_annotation`'s other mutable fields are immutable.
