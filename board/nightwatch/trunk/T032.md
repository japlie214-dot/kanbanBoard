# T032 — A new `execute_closes` sends the ladder's close intents one at a time, persists every step, confirms each close against the portfolio and never resends

## Outcome
New module `P/engine/close_executor.py` (P = `app/src/main/python/nightwatch`) with `execute_closes(...) -> CloseReport`. For each close intent, in order:
1. resolve it to concrete positions;
2. persist the intent;
3. call `client.close_position`;
4. persist the order and poll it to terminal;
5. confirm in the portfolio;
6. update `lot_annotations`.

An ambiguous outcome stops execution. An unrecognised close result goes into `unverified`, so the session can HALT. Nothing is ever resubmitted. Partial closes are built but only sent when `allow_partial=True`.

## Why
- S7 plan item 6 (project.md, Boss-approved 2026-10-10): S7-3b closes + two-phase. This ticket is the close half; T033 wires the session.
- `doc/DESIGN_session.md` §4.6.1 (live SCHG lot algorithm), §4.8 (bounded sell loop), §3.4 (non-terminal/partial at session end), §7.2 (intent before HTTP; annotations after terminal).
- The partial-close response shape is unobserved (§4.6.1 flags the field as "needs verifying against a live payload"). So the design fails closed.

## Design (PM decisions)
1. **Signature:** `execute_closes(*, repo, client, session_id, trading_date, intents, instrument_ids, prices, spy, allow_partial: bool = False, max_orders: int, deadline, now, sleep) -> CloseReport`. `prices` holds this session's fetched prices per symbol, for market value.
2. **`CloseReport`** (frozen): `results: tuple[ExecutedClose, ...]`, `stopped: str | None`, `deferred`, `unverified: tuple[str, ...]` (position ids), `followups`, `proceeds_usd: float` (sum of confirmed MARKET-value closes).
   **`ExecutedClose`** fields: intent, intent_id, request_id, position_id, units_to_deduct (None = full), outcome (filled | rejected | unresolved), detail.
3. **Resolution:**
   - UPRO: one full close of `position_ref`. A missing position in the portfolio means outcome rejected with "position not in portfolio", and the intent is not sent.
   - SCHG: walk the open SCHG positions from one `get_portfolio()`, sorted by `entry_price` descending then `position_id` ascending. Size by market value (`units * prices["SCHG"]`), never cost basis, per §4.6.1 steps 1–3.
   - Where step 2 calls for a partial close: if `allow_partial` and `partial_close_leaves_legal_remainder(...)`, send a partial close; otherwise close that lot **whole** (bounded overshoot, §4.6.1) and add a followup "partial disabled: whole close".
   - The loop is bounded by `max_orders` (§4.8). When it is hit, the rest goes to `deferred`.
4. **Per close:**
   - New request id; `insert_intent` (side `close`, symbol, amount = market value to raise, position id), committed **before** `close_position`.
   - Then insert the order and poll it to terminal.
   - Exception on send, lost response, or non-terminal at timeout → `unresolved`, intent left `sent`, stop execution (`stopped`). Never resend.
5. **Confirm** (fail closed). After a filled close, read the portfolio with `READ_TRIES` × `READ_SLEEP`:
   - Full close: confirmed when the position is absent. Then `update_lot_annotation` sets `is_open=False` with the exit facts (exit date, price = `prices[symbol]`, SPY context from `spy`), and the intent is `filled`.
   - Partial close: confirmed only when the position is present with `units ≈ old_units − units_to_deduct` (relative tolerance 1e-6 or 1e-4 units, whichever is larger). Then the annotation's units/amount are updated in place and it stays open.
   - Any other observation (still present after a full close, units unchanged or different, vanished after a partial close): add the position id to `unverified` with a followup quoting what was seen, do not update the annotation, mark the intent `filled`, and continue only if nothing is ambiguous. T033 HALTs on `unverified`.
6. **Deadline:** no new close starts at or after `deadline`; the remainder goes to `deferred`.
7. **Never** call `place_buy_order`. Never retry `close_position` with the same or a new request id inside one call.
