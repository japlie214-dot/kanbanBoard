# T014 — S6a: `run_session` dry-run skeleton wires the 12 preflight gates; `nightwatch run` starts a session

## Outcome
`nightwatch run` on the PC does three things:
1. creates today's session row, or no-ops if today already ran;
2. builds the 12 gates with real inputs and runs `run_preflight`;
3. persists the verdict, and prints a one-screen summary.

## Requirements
1. `fetch_server_date(base_url: str, *, timeout: float = 10.0) -> str | None` makes one unauthenticated `httpx.get(base_url + "/", timeout=timeout, follow_redirects=False)` call and returns `response.headers.get("date")`. On `httpx.HTTPError` it returns `None`, which gate 4 then fails on.
2. `build_preflight_gates(*, host: Host, config: Config, repo: Repo, client: EtoroClient, session_id: int, trading_date: date, now: Callable[[], datetime] | None = None) (inside: `now = now or host.now`) -> list[GateSpec]` returns exactly 12 specs, numbered 1–12. Each check is a zero-argument closure. Inputs are fetched **inside** the closure, so a gate that never runs makes no call:
   1. `gate_1_halt(host)`;
   2. `gate_2_power(status=host.power_status(), min_battery_percent=config.risk.min_battery_percent)`;
   3. `gate_3_network(probe=etoro_reachability_probe(config.etoro.base_url))`;
   4. `gate_4_clock(local_now=now(), server_date=fetch_server_date(config.etoro.base_url))`;
   5. `gate_5_database(repo=repo, session_id=session_id)`;
   6. `gate_6_auth(client=client)`;
   7. `gate_7_environment(client=client)`;
   8. `gate_8_instruments(client=client, symbols=config.symbols, order_sizes={s: config.strategy.min_order_size for s in config.symbols.traded})`. Preflight runs before any decision, so it checks at the minimum order; the S7 executor (not built; executor.py is a stub) must re-check each actual amount with `check_eligibility_for_order`. Put that in a comment;
   9. `gate_9_calendar(trading_date=trading_date)`;
   10. `unimplemented_gate(10, "price_data")`, with the comment `# wired in S6b (trunk/T015)`;
   11. a closure: `positions = client.get_portfolio()`; `instrument_symbols = {i.instrument_id: i.symbol for i in repo.list_instruments()}`; return `gate_11_reconciliation(positions, repo.list_lot_annotations(), managed_symbols=config.symbols.traded, instrument_symbols=instrument_symbols, abandoned_intents=repo.abandoned_intents(), reconciliation_config=config.reconciliation)`. Cache `positions` in a one-element holder in `build_preflight_gates`'s scope, so gate 12 reuses it without a second fetch;
   12. `gate_12_risk_caps(risk=config.risk, repo=repo, positions=<cached positions, or client.get_portfolio() if gate 11 did not populate it>)`.

   Note: gate 8 with a repo-backed client caches any missing instrument rows before gate 11 reads `list_instruments`. So construct the client with `repo=repo`: `EtoroClient(config.etoro, role="read", repo=repo)`. That is the CLI's job; document it in the `run_session` docstring.
3. `run_session(*, host, config, repo, client, trading_date: date) -> SessionResult`, where `SessionResult` is a frozen dataclass with `session_id: int | None`, `status: str` (`"already_ran"|"refused_armed"|"preflight_failed"|"preflight_passed"`), `failed_gate: int | None`, `reason: str`:
   1. If `config.is_armed` → return `refused_armed` with reason `"armed execution not built (S7); refusing"`, without creating a session.
   2. If `repo.get_session_by_date(iso)` exists → return `already_ran` with that session's id. Create no row.
   3. `s = repo.create_session(iso, mode="dry_run", environment=config.etoro.environment.value, armed=False, state="preflight")`.
   4. `outcome = run_preflight(build_preflight_gates(...), repo=repo, session_id=s.id)`.
   5. `repo.update_session(s.id, preflight_verdict="pass" if outcome.passed else "fail", preflight_failed_gate=None if outcome.passed else outcome.failed.gate, preflight_at=<utc iso>)`.
   6. On failure: `repo.finish_session(s.id, state="aborted", outcome=f"preflight gate {g} {name}: {reason}")` → `preflight_failed`.
   7. On pass: `repo.update_session(s.id, state="settled")` → `preflight_passed`, reason `"preflight passed"`. S6b continues from here.
   Reasons: `already_ran` → `f"session {id} already exists for {iso} (state {state})"`; `preflight_failed` → the same text as the outcome.
4. `nightwatch run [--date YYYY-MM-DD]`. The default date is today in America/New_York: `datetime.now(ZoneInfo("America/New_York")).date()`. It:
   - loads the config;
   - opens the DB via `default_db_path(host)`;
   - builds `EtoroClient(config.etoro, role="read", repo=repo)`;
   - calls `run_session`;
   - prints `status`, `session_id`, `failed_gate`, `reason`, and and, when `session_id` is not None, one line per row of `repo.get_preflight_checks(session_id)`: `gate N name PASS|FAIL <json.loads(row.detail)["reason"]>`;
   - closes the client;
   - exits 0 for `preflight_passed` or `already_ran`, else 1.
   Remove `run` from `_NOT_YET_IMPLEMENTED`.

## Design
- `run_session` takes constructed dependencies, so tests inject fakes (dependency inversion). The CLI is the composition root.
- Closures fetch lazily, which keeps the preflight's stop-at-first-failure meaningful: no network after a failed gate.
- `refused_armed` comes before session creation. A live mode must never reach this dry-run path silently.
