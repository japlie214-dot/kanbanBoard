# T011 — Fix `compute_hard_deadline`: its cutoff lands at or before the T-30 session start, leaving no order window

## Outcome
`compute_hard_deadline(trading_date, *, margin_minutes)` returns `session close − margin_minutes`. The order time gate then allows orders between the T-30 session start and `margin_minutes` before the close. Today it returns `close − 30 min − margin`, which is at or before the moment the session starts. Every order would be refused.

## Why
- The consultant found it 2026-10-02, and the PM confirmed it by reading the code.
- S6 will wire `check_order_budget` (`engine/order_budget.py`). With the current formula, the session could never place an order once the placeholder latency is replaced.

## Context (PM read 2026-10-02; repo `repos/etoroNightwatch`)
- `app/src/main/python/nightwatch/engine/order_budget.py:265` `compute_hard_deadline` returns `close_dt - timedelta(seconds=T30_BUDGET_SECONDS) - timedelta(minutes=margin_minutes)`. Its docstring says "``hard_deadline`` = T-30 minus a configured margin".
- `app/src/main/python/nightwatch/probes/order_latency.py:601`: `T30_BUDGET_SECONDS = 30.0 * 60.0`.
- The session sleeps until exactly T-30 and then acts (DESIGN_session.md line 901). The T-30 window is the session's whole margin against the close (the order_budget docstring, citing DESIGN_session §3.2).
- **Doc conflict (precheck 2026-10-02):** `doc/DESIGN.md:840` says "`hard_deadline` derives from the market calendar (T-30 minus a safety margin)", which matches the current code. But DESIGN_session.md §3.2 (lines 271–279) and the §5 sequence (sleep until T-30, then fetch, decide and execute) put all order work AFTER T-30, inside the "T-30-to-close window". A deadline before T-30 is incompatible with that sequence. PM decision: DESIGN_session's sequence wins, and DESIGN.md:840 is rewritten.
- The module's own placeholder reasoning (the order_budget.py docstring, around `PLACEHOLDER_P95_LATENCY_SECONDS`, line 139) assumes "no order-placing instant inside the T-30 window can be more than `T30_BUDGET_SECONDS` before `hard_deadline`". That only holds if `hard_deadline` is at about the close, which confirms the intended deadline is close − margin.
- `tests/test_order_budget.py` lines 193–235 encode the bug:
  - `test_hard_deadline_is_t30_minus_margin_on_a_regular_close_day` expects 35 minutes before close;
  - `test_hard_deadline_honors_an_early_close_day`;
  - `test_zero_margin_is_exactly_t30`;
  - `test_compute_hard_deadline_feeds_check_order_budget_end_to_end`.
- No production caller (only tests).

## Design (PM decision)
- `hard_deadline = session_close_datetime(trading_date) − timedelta(minutes=margin_minutes)`. Keep `margin_minutes` keyword-only with no default, and keep it validated ≥ 0.
- Add a guard: `margin_minutes` must also be `< T30_BUDGET_SECONDS / 60`, so the deadline stays strictly after T-30 and the window is non-empty. Otherwise raise `ValueError(f"margin_minutes must be < {T30_BUDGET_SECONDS / 60:g} so the order window is non-empty, got {margin_minutes!r}")`.
- `T30_BUDGET_SECONDS` stays imported. It is now used for the guard, not subtracted.
- Docstring: "``hard_deadline`` = session close minus a configured margin. The order window runs from T-30 (session start) to this deadline."
- Rejected alternative: a fixed latest-submit time derived from measured latency. The latency is already applied per order by `check_order_budget` (`now + p95 < hard_deadline`), so putting it into the deadline as well would count it twice.

## Plan
1. `doc/DESIGN.md` line 840: replace "(T-30 minus a safety margin)" with "(session close minus a safety margin; the order window runs from the T-30 session start to this deadline, per DESIGN_session.md §3.2/§5; corrected 2026-10-02, trunk/T011)".
2. `order_budget.py`: change the formula, add the guard, update the docstring. Also correct any other docstring or comment in this module that says the deadline is "T-30 minus margin" (grep `T-30` in the file).
3. `tests/test_order_budget.py`: rewrite the four tests above so they expect close − margin (16:00 − 5 min = 15:55 ET; early close 13:00 with margin 0 = 13:00). Rename the tests that have "t30" in the name, e.g. `test_hard_deadline_is_close_minus_margin_on_a_regular_close_day`.
4. Add these tests:
   - window non-empty: for 2026-09-11 with margin 5, `deadline − (close − 30 min) == 25 min`;
   - for 2026-11-27 with margin 5, the deadline is 12:55 ET, strictly after 12:30;
   - `margin_minutes=30` → `ValueError`; `margin_minutes=29.9` → ok;
   - end to end: at T-30 + 1 min with `p95_latency_seconds=10`, `check_order_budget` allows the order;
   - with `PLACEHOLDER_P95_LATENCY_SECONDS`, it still refuses at T-30 + 1 min. The placeholder must still fail closed: its value is 3600 s, which exceeds the whole window.
5. Run Prove.
