# T040 — The app's alarm wake runs `nightwatch` `run_session` in dry-run mode through one locked Python entry point, and the result reaches the event log and notification

## Outcome
When the session alarm fires, `WakeService` runs the probe battery as it does today, and then calls one new Python entry point: `nightwatch.android_entry.run_session_dry(base_dir)`. That entry point:
- runs the real `run_session`, **never armed**;
- holds a single-instance lock;
- returns one JSON line.

Kotlin logs that line to `EventStore` as `SESSION_RESULT`, and posts it as a normal notification, or as a failure notification when the status is not `would_have_done`/`already_ran`. Nothing on the phone can send an order after this ticket.

## Why
- Today nothing on the phone calls `run_session`. The app runs only probes: `PyBridge.kt:27-108` calls `probe.checks` / `probe.probe_runner` and nothing else. The "production wiring" gap in project.md is exactly this.
- The smallest safe step is dry run on device: it proves Chaquopy, config, DB, Tiingo, eToro reads, the alarm and the wake lock end to end with zero trading risk. Arming on the device is a separate, Boss-gated ticket.

## Design
1. `android_entry.run_session_dry(base_dir: str, *, now_utc: str | None = None) -> str`:
   1. `os.environ.pop("NIGHTWATCH_ARM", None)` **before** `load_config`. Then, if `config.is_armed` is somehow True, return `{"status":"refused","reason":"armed run not allowed from android_entry"}` without opening a client.
   2. `host = DesktopHost(Path(base_dir))`, then `set_host(host)`. The base dir is the existing `filesDir/nightwatch_config` root, so the config is at `<base>/config/config.toml`.
   3. **Single-instance lock** at `<base>/data/session.lock`, taken with `os.open(O_CREAT|O_EXCL)` and holding pid + UTC ISO. An existing lock younger than 2 h gives `{"status":"busy"}` with no work. An older lock is replaced and `"stale_lock_replaced": true` is reported. The lock is removed in `finally`.
   4. Wiring is identical to `cli._cmd_run`, with `EtoroClient` role `"read"` hard-coded, `trading_date` = today in America/New_York, and `wait=True`.
   5. Return `json.dumps({"status", "session_id", "failed_gate", "reason", "armed": false, "gates": [[gate, name, passed], ...]})`.
   6. Every exception becomes `{"status":"error","reason":"<Type>: <msg>"}`. Never raise into Kotlin. Never put secret values in the reason (`ConfigError` text is already secret-free).
2. `PyBridge.runSessionDry`: `@Synchronized`, `ensureStarted`, then `getModule("nightwatch.android_entry").callAttr("run_session_dry", baseDir).toString()`.
3. In `WakeService`, when `trigger == "alarm"`:
   - acquire a second `PARTIAL_WAKE_LOCK`, `NightwatchProbe:Session`, with a 50-minute timeout, released in `finally`, because `wait=True` can sleep up to ~15 min;
   - call `PyBridge.runSessionDry(this, File(filesDir, "nightwatch_config").absolutePath)`;
   - log `SESSION_RESULT` with the JSON;
   - post a notification: `post` for `would_have_done`/`already_ran`/`busy`, `postFailure` otherwise.

   Errors are caught like steps 2–4. The reschedule (step 6) must still run, so wrap step 5b in try/catch.
4. FCM and boot triggers do **not** run a session.

**Scope (replaces the Scope section):** `app/src/main/python/nightwatch/android_entry.py` (new); `tests/test_android_entry.py` (new); `android-probe/app/src/main/java/com/nightwatch/etoro/probe/PyBridge.kt`; `android-probe/app/src/main/java/com/nightwatch/etoro/probe/WakeService.kt`. **A1 (F1) — narrowed guarantee.** The guarantee is only that the new alarm entry point (`run_session_dry` and its Kotlin caller) can never send a broker write. The existing gated probe routes (real take-profit probe, demo order probes) are unchanged and out of scope; the ticket no longer claims "nothing on the phone can send an order". Add a real-engine test: unmocked `run_session` against a temp root with a fake eToro client whose every write method (open/close/clear_take_profit/any POST/PATCH/DELETE at transport level) raises `AssertionError("broker write")`; assert the call completes with a non-armed status and no write was attempted. Also assert an armed config (via env `NIGHTWATCH_ARM` and live mode) still yields `armed:false` and no write.

**A2 (F2) — invocation window.** Before taking the lock or opening the DB, the entry point uses the existing market calendar to compute today's ET close. If today is not a trading day, or now is outside [close−60 min, close−25 min] ET, return `status:"out_of_window"` (routine, no failure notification). If `run_session`/its wait accepts a deadline, pass close−5 min; otherwise document that the in-window start bounds the T−30 wait to ≤35 min and that network retries are bounded only by the client's existing timeouts. Explicit statement: current alarm timing is not market-calendar/DST-aware production scheduling; that is a later ticket.

**A3 (F3) — lock.** Replace the age-based exclusive-create lock with a kernel-held nonblocking lock on an fd kept open for the whole run: `fcntl.flock(fd, LOCK_EX|LOCK_NB)` on POSIX/Android, `msvcrt.locking(fd, LK_NBLCK, 1)` on Windows. Never unlink the lock file; release by unlocking/closing the fd in `finally`; process death releases it. Failure to acquire → `status:"busy"`. Tests: a second acquirer gets busy; release on close lets the next acquire succeed; a child process (`subprocess`) that takes the lock and is killed releases it.

**A4 (F4) — restart semantics.** After the lock and before `run_session`, read the persisted session row for today's trading date. If one exists and is not finished-successfully (`would_have_done`/`already_ran` completed), return `status:"previous_unfinished"` (failure notification). No repair, no deletion, no status rewrite. A prior-date unfinished session is left to fail gate 5 as today. Manual recovery procedure (documented, not automated): stop alarms, copy the phone DB off-device, inspect the session row and its preflight/decision rows, and mark it via a reviewed PM ticket; never delete rows on the phone.

**A5 (F5) — rescheduling.** In nightly mode, `WakeService` registers the next saved-state alarm before the long work starts. All earlier steps (checks, snapshot construction/push, session step) are each wrapped so an exception is logged and execution still reaches the reschedule/finalization path. One-shot modes are unchanged (still no reschedule). Process death is not covered by this and is stated as such.

**A6 (F6) — service lifecycle.** `WakeService`: an `AtomicBoolean sessionRunning` coalesces session steps (a start while one runs skips the session step and logs `SESSION_SKIPPED_BUSY`); each invocation owns its own wake-lock handle and releases only that handle; an active-invocation counter calls `stopSelf()` only when it reaches 0. `PyBridge.runSessionDry` is not `@Synchronized` on the object monitor; it uses a dedicated lock object so other probe methods stay usable during the session wait. Document that Python-level contention (the GIL, shared interpreter) remains and that probe calls during a session may run slower.

**A7 (F7) — honest host claim.** Label this "desktop-host simulation on Android": `DesktopHost(base_dir)` reports power gates as satisfied, so power gating is unproven, and the Kotlin HALT (SharedPreferences) is disconnected from the Python HALT file. Both are stated as known gaps for a later AndroidHost ticket. Prerequisite: the phone root `filesDir/nightwatch_config` gets a fresh, separately migrated DB; it does not hold the desktop book, so reconciliation against existing positions may legitimately fail.

**A8 (F8) — sanitized output.** Every `reason` leaving the entry point is an allowlisted `reason_code` plus `error_type` (exception class name only); never raw `str(exc)`, including reasons already inside `SessionResult`. Tests: malformed config with synthetic secret markers (e.g. `SECRET_MARKER_123` as an invalid enum value), a caught gate failure, a session exception and a cleanup exception; assert the marker never appears in the returned JSON.

**A9 (F9) — one envelope.** Every return, including refusals, busy and errors: `{"status", "armed": false, "session_id": int|null, "failed_gate": int|null, "reason_code": str, "error_type": str|null, "gates": [...]}`, where `gates` lists only persisted attempted preflight rows (`[]` if none). Routine (no failure notification): `would_have_done`, `already_ran`, `busy`, `out_of_window`. Everything else gets a failure notification. `now_utc` is removed from the public signature; it is kept only as a keyword-only test hook that must be an aware datetime (`ValueError` otherwise). Setup, serialization and cleanup failures still return the envelope. Kotlin treats interpreter/module/call failure and malformed JSON as `status:"bridge_error"` with a failure notification.
