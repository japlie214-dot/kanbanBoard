# T021 — Gate 10 judges freshness from eToro's real-time 1-minute candles. The delayed `/rates` feed no longer fails the gate.

## Outcome
During market hours on a normal day, gate 10 passes when:
- every managed symbol (SPY, UPRO, SCHG) has an eToro **OneMinute** candle no more than `max_candle_age_minutes_intraday` (20) old;
- the Tiingo provisional close is within `provisional_close_deviation_pct` (1%) of that candle's close;
- an eToro rate is present and positive.

The eToro rate's age is reported as advisory text and never fails the gate. Nothing that the decision or the signal uses changes: provisional closes and daily candles stay as they are.

## Why
- 2026-10-09, live, market open: gate 10 failed every session.
  - `/rates` is delayed ~22 min for SPY and ~43 min for UPRO, with identical timestamps on demo **and real** (boss-approved read-only real call). The lag grows during the day. SCHG is real time.
  - Evidence: `.p1-test-tmp/g10_samples.jsonl` in the repo, and T015's note.
- Tiingo's free IEX tier has no observed-at timestamp (`market/source.py:16–25,177–184`), so it cannot prove freshness.
- PM live probe 15:24:58 UTC: eToro `get_candles(id, count=2, interval="OneMinute")`, latest bar 15:24:00Z (61 s) for all three; SPY close 777.47 ≈ Tiingo. FiveMinutes was 301 s. **OneMinute candles are real time.**
- Boss decision 2026-10-09: A′.

## Design (PM decisions)
1. **`MarketInputs`** gains `minute_candles: dict[str, Candle | None]`.
   - `fetch_market_inputs` fetches, per symbol, `client.get_candles(instrument_id, count=1, interval="OneMinute")`, takes `[-1]` (or None if empty), next to the existing daily fetch.
   - Errors propagate exactly like the existing eToro candle fetch.
   - `candles` (daily) is unchanged.
2. **`gate_10_price_data`** gains the keyword `minute_candles: Mapping[str, Candle | None]`. The existing `candles` parameter stays in the signature, unused by the checks below, so callers stay simple. Its docstring says "daily candles; not used for freshness since T021".
3. **New check order:**
   1. `_check_rate_sanity`: unchanged.
   2. **Rate vs minute candle:**
      - Rate age ≤ `max_rate_age_minutes`: compare the rate price with the **minute** candle close at `rate_vs_candle_deviation_pct`, and fail on disagreement (existing message, with "eToro's own candle close" → "eToro's 1-minute candle close").
      - Rate age > bound: **no failure**. Add an advisory string `f"{symbol}: eToro rate delayed {age_minutes:.0f} min (advisory, T021)"` to a list and skip the value comparison.
      - An unparseable or missing rate timestamp: add advisory `"{symbol}: eToro rate timestamp unusable (advisory, T021)"` **and still run the value comparison** against the minute candle (we cannot know it is delayed, so the deviation check stays as a safety). `test_gate_10_would_also_fail_on_deviation_alone_if_timestamp_were_missing` (`test_preflight.py:154–177`) must keep FAILING. Change only its candles to minute candles if needed.
   3. **Provisional close vs minute candle:** run the existing `_check_provisional_close` logic with the **minute** candle in place of the daily candle.
      - A missing minute candle fails ("no eToro 1-minute candle available to establish freshness").
      - Interval `OneMinute` gets the intraday age bound (20 min).
      - A Tiingo-sourced close is compared with the minute close at 1%.
      - An eToro-candle-sourced provisional close still needs a fresh minute candle, and gets no value check, as today.
4. **The result:**
   - On pass, the reason is **new** success text `"provisional close and eToro 1-minute candles fresh and mutually consistent for all managed symbols (...)"` (keep the existing parenthesised symbol list), plus `"; advisory: " + "; ".join(advisories)` if there are any. The old text "live rates fresh" would be false (precheck).
   - On fail, the advisories are appended after the failures in the same way.
   - `GateResult.details` (`preflight.py:193–210`, a dict) gets `"rate_advisories": [...]`.
5. **Why this shape:**
   - Freshness needs a real timestamp, and `/rates` cannot provide one today.
   - Tiingo's value is still cross-checked, now against a real-time eToro price.
   - Every price the strategy uses stays unchanged, so the blast radius is gate 10 only.
