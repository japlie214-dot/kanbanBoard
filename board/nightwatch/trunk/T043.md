# T043 — A units drop between two snapshots that one confirmed app partial close fully explains is no integrity breach. All other positions keep the full loss and residual checks, including alert C.

## Outcome
`compute_interval` takes optional partial-close evidence. A held position whose units drop is "app partial close" only when exactly one confirmed T041 ledger leg matches that position, with `units_before` equal to the previous snapshot's units and `units_after` equal to the current snapshot's units, each within 2e-6. Such a position is left out of the residual and alert C computation and gets a per-position note. Every other position is evaluated exactly as today. An unexplained residual on the other positions still sets `alert_c`, and the session HALTs.

## Why
This was split out of T041 by the precheck (FIX-FIRST, 2026-10-30):
- **Finding 1, blocker:** T041's draft D6 set a global `incomplete` state. That sets `residual_usd` to None and `alert_c` to False (`P/engine/interval_pnl.py:175-193`; HALT at `P/engine/session.py:752`), so an unrelated UPRO loss would not HALT.
- **Finding 2, high:** binding the evidence by `confirmed_at` lets a late recovery mask an unrelated drop.

## Context
P = `app/src/main/python/nightwatch`.
- `compute_interval` is at `P/engine/interval_pnl.py:69`. Its held branch sets integrity at :108-113.
- At :175-193: `state` is integrity, incomplete or complete; `explained_usd` and `residual_usd` are only set when the state is complete; `alert_c` requires complete.
- `observe()` is at :46. Snapshots carry `taken_at` and `raw["pnl"]`.
- Session HALT is at `P/engine/session.py:752`. `_interval_for` is at :304.

## Design
1. Add the type `PartialCloseEvidence(position_id: str, units_before: float, units_after: float)` and the parameter `compute_interval(..., partial_closes: Sequence[PartialCloseEvidence] = ())`. With the default `()` the behaviour is identical to today.
2. **Binding**, decided per held position `id` with `p0`, `p1` and `p1.units < p0.units`. A position is `app_partial` when exactly one evidence item `e` has:
   - `e.position_id == id`;
   - `abs(e.units_before - p0.units) <= 2e-6`;
   - `abs(e.units_after - p1.units) <= 2e-6`.

   If several evidence items match, or none do, or units rose, keep today's behaviour: integrity. Chained reductions inside one interval (8→6→4) match no single item, so they are integrity. The executor only does one leg per position per session, and that limit is documented.
3. **`app_partial` handling:**
   - The position is left out of `pnl_parts` and `expl_parts`.
   - Add a line `"{id} app partial close {p0.units}->{p1.units}: excluded from residual"` and the reason `"position {id}: app partial close excluded"`.
   - It does **not** set `incomplete` or `integrity`.
4. **The rest of the computation is unchanged.** `state` is complete when no other position is incomplete or integrity. A complete state computes residual and alert C over the remaining positions.
   - Add a field `excluded_positions: tuple[str, ...] = ()` to `IntervalResult`. It is a new trailing default field.
   - `format_interval` mentions the excluded positions when there are any.
   - If **all** positions are excluded, `pnl_usd` is 0 and the state is complete with residual 0. That is acceptable: nothing unexplained remains.
5. **Base for the percentage:** excluded positions are left out of `base` the same way skipped positions are.
6. **Session.** `_interval_for` gets `repo` as a keyword argument. It builds the evidence from `repo.confirmed_partial_closes(ids in prev ∩ cur)`. Stale evidence is harmless, because it only matches when the exact before/after units equal the two snapshots, so there is no time window.
   - The binding is purely by the units at the two endpoints, so delayed recovery and already-reflected effects are handled.
   - An effect already reflected in an earlier interval has `units_before` that no longer equals `p0.units`, so it matches nothing.

## Acceptance
1. **Legit:** an SCHG position goes 3.621089→1.810544 with matching evidence, and the UPRO residual is small. The state is complete, the position is excluded, there is no integrity, and `alert_c` is False.
2. **Mixed, the precheck blocker:** a legit SCHG reduction plus an unrelated UPRO residual of -$60 against a threshold of $50. The result is `alert_c` True, and the session HALTs (`test_session_interval.py`).
3. **Delayed recovery:** the evidence was confirmed in a later session, but the units endpoints match this interval. It is accepted.
4. **Already reflected:** evidence with `units_before` 3.62 and `units_after` 1.81, while this interval runs 1.81→1.81. It is not used, and nothing changes.
5. **Stale evidence masking:** old evidence for 8→6 cannot excuse a new unrelated 6→4. The result is integrity.
6. **Chained 8→6→4 in one interval** with two evidence items: integrity.
7. **Mismatched units** (evidence after 1.80, observed 1.81): integrity.
8. **No evidence (the default):** every existing test is unchanged.
9. Both full suites pass with 0 failures.

## Amendments after second precheck (2026-10-30, PM decisions)
These amendments override C3, C4 and the sections above where they conflict.

**D1 (notifications and the HALT reason; scope widened).**
- **Scope** now also covers two blocks in `P/engine/session.py`:
  - the HALT reason block at `:752-756`;
  - the notification block at `:847-862`.
- **Alert C from `modelled_residual_usd`** (state `incomplete`):
  - the alert text shows that value, labelled "modelled-subset residual". It never shows "n/a".
- **HALT reason:** when alert C triggered, the reason names the alert-C cause with its value (for example `alert C modelled-subset residual $-60.00`), not `interval.reasons[0]`.
- **No contradictory message:** never send an "INCOMPLETE ... no HALT" style message when a HALT was set in the same session.
- **Notifier-backed session test:** -60 modelled residual with state `incomplete` gives:
  - a HALT file persisted with the alert-C reason;
  - a captured message showing -60.00 with the "modelled-subset residual" label;
  - no captured message containing "no HALT".

**D2 (the compatibility promise changes).**
- C4 changes the Design 1 / acceptance 8 promise. Incomplete intervals now evaluate alert C over the fully modelled subset **even without partial-close evidence**. "Default call behaviour identical" no longer holds for that path.
- **Eligibility rule:**
  - **Snapshot-level incompleteness:** when `prev.raw["complete"]` or `cur.raw["complete"]` is not True, or `closed is None` (no trade history), **no** row is eligible. `modelled_residual_usd` is None and `alert_c` is False, as today.
  - **Row-level incompleteness:** when incompleteness comes only from row reasons (a missing mark on another row, a round trip or closed-since row without independent marks, an unknown slice, a short or leveraged skip), fully modelled held, opened-since and closed-since rows **remain eligible**.
- **Test expectations:**
  1. `tests/test_interval_pnl.py:157-162` (snapshot marks incomplete) is unchanged: no alert C, `modelled_residual_usd` None.
  2. History not supplied (`closed=None`): `modelled_residual_usd` None, no alert.
  3. One row missing its mark, other rows fully modelled with residual -60: state `incomplete`, `modelled_residual_usd` -60, `alert_c` True.
  4. The same case with residual -10: `alert_c` False.
  5. State integrity: `alert_c` False (integrity HALTs on its own).
  6. State complete: `modelled_residual_usd == residual_usd`.

**D3 (the accumulator).**
- `modelled_residual_usd` is its own accumulator:
  - sum over eligible rows of `(pnl_c - expl)`;
  - only rows where both `pnl_c` and `expl` were computed count;
  - a row contributes both terms or neither.
  - Excluded app-partial rows, skipped rows, incomplete rows and integrity rows contribute nothing.
- **`IntervalResult` field order:**
  - `excluded_positions: tuple[str, ...] = ()`;
  - then `modelled_residual_usd: float | None = None`, both trailing.
- **Regression test:** a modelled UPRO row with residual -60, plus an unmodelled round trip of +100 P&L with no independent marks. Expected: state `incomplete`, `modelled_residual_usd` -60 (the +100 is not counted), `alert_c` True, and the session HALTs.
