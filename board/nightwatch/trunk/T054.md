## Outcome

It does so only when the Boss has provisioned a dedicated demo home on the phone and created a device arm flag. Without that flag the phone behaves exactly as today (dry run). A real-account config is refused in code, whatever the config or flags say.

## Design
1. **Python entry** `run_session_armed_demo(base_dir, *, now_utc=None) -> str`.
   - Refactor the body of `run_session_dry` into `_run_entry(base_dir, *, armed: bool, now_utc)`. `run_session_dry` keeps its exact current behaviour and envelope.
   - Before loading config, the armed path checks:
     a. `Path(base_dir).name == "nightwatch_demo"`; otherwise refuse `wrong_home`.
     b. The arm flag file `Path(base_dir)/"ARM_DEMO"` exists; otherwise refuse `not_armed_on_device`. Its content is ignored, so it can never hold secrets.
     c. Set `os.environ["NIGHTWATCH_ARM"] = "1"` only for this call, and restore the previous value in `finally`. Then load config.
     d. Hard refusals after load, in this order:
        - `config.environment is not EtoroEnvironment.DEMO` or `config.etoro.is_real_money` → `real_not_allowed`;
        - `not config.is_armed` (TOML mode isn't live) → `config_not_live`.

     All refusals return `status="refused"` and place no network call.
   - Armed run: `EtoroClient(..., role="write")`, then the same `run_session(...)` call and the same window, lock and Telegram notifier.
   - Same-date dedupe in armed mode: any existing session row for the date returns `already_ran` if `previous.state == "finished"` and `previous.armed`; otherwise `previous_unfinished`. Never run twice in a day. An unfinished armed session blocks the next session at gate 5 (amendment 5).
   - Envelope: same keys; `armed` = true only when the armed run actually started; `status` is the session status (`executed`, `executed_partial`, `halted_before_execution`, and so on). Add the armed statuses to `_STATUSES`; unknown → `error`.
   - No exception text in the envelope, as today.
2. **Dedicated demo home.**
   - The base dir is `filesDir/nightwatch_demo`, so its DB, lock and HALT are separate from `nightwatch_config` (probes and dry runs).
   - The DB starts empty: the existing migrations create it, and nothing is copied from production.
3. **Kotlin selection** in `WakeService`.
   - If `File(filesDir, "nightwatch_demo/ARM_DEMO")` exists, call `PyBridge.runSessionArmedDemo(this, File(filesDir,"nightwatch_demo").absolutePath)`. Otherwise call the existing dry call.
   - Envelope validation: in the armed branch, `armed` may be true or false (refusals are false). In the dry branch, `armed == false` stays required.
   - The HALT check and the T046 power gate run before either call, unchanged.
   - Log `SESSION_MODE armed_demo|dry` (no secrets). The notification title includes "DEMO ARMED" when armed.
4. **HALT.** The Python HALT written under `nightwatch_demo` must be the latch Kotlin's `HaltFlag` reconciles. If HaltFlag uses a fixed path (for example `filesDir/nightwatch_config/HALT`), make it check both paths, or set it from whichever path the envelope reports. Pick the minimal change and test it. The Telegram `/halt` and `/resume` flows keep working.
5. **Secrets.** Superseded by amendment 4. Originally: the Boss alone places `config/config.toml` (environment demo, mode live) and `config/.secrets.env` (demo keys plus Telegram) under `nightwatch_demo`, using the runbook. Workers and the PM never read, create or log secret values. Tests use fake config and fake secrets in tmp dirs.

## Runbook: install and provision (PM-run; superseded in part by amendments 2-4)
1. Plug in the Z10 with USB debugging on, then run `adb install -r android-probe/app/build/outputs/apk/debug/app-debug.apk`.
2. Create the demo home and push the config. The debug build allows `run-as`.
   - `adb push <your demo config.toml> /data/local/tmp/nw_cfg.toml`, then `adb push <your demo .secrets.env> /data/local/tmp/nw_sec.env`
   - `adb shell run-as com.nightwatch.etoro mkdir -p files/nightwatch_demo/config`
   - `adb shell run-as com.nightwatch.etoro cp /data/local/tmp/nw_cfg.toml files/nightwatch_demo/config/config.toml`
   - `adb shell run-as com.nightwatch.etoro cp /data/local/tmp/nw_sec.env files/nightwatch_demo/config/.secrets.env`
   - `adb shell rm /data/local/tmp/nw_cfg.toml /data/local/tmp/nw_sec.env`
   - config.toml must say environment demo and mode live. The .secrets.env holds the demo keys and the Telegram token/chat.
3. Arm: `adb shell run-as com.nightwatch.etoro touch files/nightwatch_demo/ARM_DEMO`.
4. Press "Schedule market session" (opening the app alone does not schedule; amendment 3). Keep the phone charging, with Wi-Fi on, and confirm the phone can reach eToro and Telegram (see blocker B2).
5. Disarm any time: `adb shell run-as com.nightwatch.etoro rm files/nightwatch_demo/ARM_DEMO`, or send `/halt` on Telegram.
(The PM verifies the package name and paths against the built manifest before the Boss runs this.)

## Amendments after precheck (2026-11-06, PM; latest wins)
1. **Two-home HALT.** `HaltFlag` is in `CommandHandler.kt:191-256` (in scope); there is no HaltFlag.kt.
   - `/halt` creates `HALT` in both `filesDir/nightwatch_config` and `filesDir/nightwatch_demo`.
   - `/resume` deletes both.
   - `isHalted`/reconcile and the WakeService alarm suppression check return true if either exists.
   - A Python HALT written in the demo home therefore suppresses the next alarm and survives process death.
   - JVM tests cover create, delete, either-file detection and reconcile.
2. **Package** is `com.nightwatch.etoro` (build.gradle.kts:33; packaged manifest line 3, debuggable). Every `run-as` and adb command uses it. `com.nightwatch.etoro.probe` is only the Kotlin namespace.
3. **Scheduling.** Opening the app only restores UI selections (MainActivity:522-529). The runbook must:
   - press **"Schedule market session"** (MainActivity:129-140, calls `scheduleMarket`);
   - grant the exact-alarm permission if prompted;

4. **Provisioning (Boss approved 2026-11-06).** The PM transfers the Boss-provided existing demo config and secrets files via adb into app-private storage. Workers never do this. The PM never opens, prints, logs or recreates their contents.
   - Primary: `adb push <file> /data/local/tmp/<name>`, then `adb shell run-as com.nightwatch.etoro cp /data/local/tmp/<name> files/nightwatch_demo/config/<target>`.
   - Fallback, if run-as cannot read the shell-staged file: `adb shell "run-as com.nightwatch.etoro sh -c 'cat > files/nightwatch_demo/config/.secrets.env'" < <localfile>`, a binary-safe pipe that is never echoed.
   - Afterwards: `adb shell rm /data/local/tmp/<name>`.
   - Verify by existence and byte size only (`run-as ... ls -l`), never by content.
   - Before pushing, the PM confirms the secrets file is demo-only by variable *names* only, never values. If real-account key names are present, stop and ask the Boss.
5. **Unfinished session.** Gate 5 fails on a prior unfinished session (preflight:360-366), and gate 5 runs before gate-11 recovery (session:128-167).
