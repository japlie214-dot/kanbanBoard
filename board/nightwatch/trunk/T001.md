# T001 — S1a: order-latency probe follows the lookup policy and labels every route

## Outcome
Every status observation in the order-latency probe names the exact lookup route that produced it. The open-leg route order matches the operator policy (project.md §3). A 404 on one poll does not change the route of later polls.

## Why
T5's latency number is meaningless while it cannot be tied to a route (project.md §2.3). First step of the critical path; 4 of the 15 red tests sit here.

## Context (read 2026-09-25; paths under `repos/etoroNightwatch`, package root `app/src/main/python/nightwatch/`)
- Policy (operator, 2026-09-19): (1) v2 `GET /api/v2/trading/info/{demo/}orders:lookup?orderId=` → (2) DEMO ONLY, only after (1) returns 404: v1 `GET /api/v1/trading/info/demo/orders/{orderId}` → (3) only if both miss: v2 `orders:lookup?referenceId=`. GET only. No write, no resubmit. Not sticky. Every observation records its route.
- `etoro/client.py` `lookup_order` (about lines 1522-1548) already does steps 1→2 internally: on `EtoroValidationError` with `status_code == 404`, only when `self.is_demo` and `order_id is not None`, it calls the v1 path. Real env re-raises the 404. `tests/test_etoro_client.py::test_order_lookup_never_uses_deprecated_fallback_for_real_or_reference_id` (line 568) covers "v1 never on real". **Do not change `client.py`.**
- `client._request` appends `{"method","path","params","status_code","body"}` to `response_capture` for each HTTP response (`client.py` about lines 329-332).
- `probes/order_latency.py`:
  - `StatusObservation` (line 55) fields: `status`, `observed_at`, `elapsed_since_submission_s`, `raw_lookup_body`. No route.
  - `_poll_with_transitions` (about lines 120-236): inner `lookup()` uses `nonlocal using_reference_id`, set True on the first escaping 404, never reset (sticky). Observations built at about line 222.
  - Close leg calls `client.lookup_close_order(order_id)` without `response_capture`.
- Failing now (4): `test_open_lookup_404_uses_reference_id_and_traces_both_responses`, `test_persistent_open_lookup_404_times_out_with_submission_and_raw_trace`, `test_open_lookup_rejects_response_for_a_different_order`, `test_persistent_close_lookup_404_fails_at_deadline_and_never_falls_back_or_resubmits`. Causes: they expect the probe to go to `referenceId` on the first v2 404, but on demo the client now tries v1 first; one expects error text `expected 'o-open'` but the client now says `expected o-open` (quoting dropped 09-18; test-only).

## Scope
`app/src/main/python/nightwatch/probes/order_latency.py`, `tests/test_probes_order_latency.py`.
## Out of scope
`etoro/client.py`, `take_profit_probe.py`, `demo_cleanup.py`, anything under `android-probe/app/build/`, any device run, T5 itself.

## Requirements
1. Open leg, each poll: call `client.lookup_order(order_id=order_id, response_capture=captured)` first (covers steps 1 and 2 inside the client). Only if that raises `EtoroValidationError` with `status_code == 404` AND `reference_id_on_404 is not None`: call `client.lookup_order(reference_id=reference_id_on_404, response_capture=captured)` in the same poll (step 3).
2. The next poll starts again at requirement 1. No state carries over between polls.
3. Each `StatusObservation` has `route: str`, one of `"v2_order_id"`, `"v1_order_id_demo"`, `"v2_reference_id"`, `"close_order_lookup"`.
4. Open-leg route comes from the last `captured` entry appended by the successful call: `path` contains `/api/v1/` → `"v1_order_id_demo"`; else `params` has key `referenceId` → `"v2_reference_id"`; else `"v2_order_id"`. If `captured` gained no entry during the successful call, raise `EtoroValidationError("lookup produced no captured response; route unknown")`. A measurement without a route is a failure to measure (standing rule 3).
5. Close leg: `route="close_order_lookup"`.
6. Existing identity checks stay: order_id match; reference_id match; a referenceId-route result must confirm `reference_id_on_404`.
7. No POST/PUT/DELETE from any lookup path.

## Design
- Add `route: str` to `StatusObservation`, after `elapsed_since_submission_s` and before `raw_lookup_body`. Required, no default. Update every constructor call.
- New private helper in `order_latency.py`: `def _route_from_capture(entry: Mapping[str, Any]) -> str`. One job: map one capture entry to one label (rule 4).
- `lookup()` returns `tuple[result, str]` (result, route). Record `before = len(captured)` before each call; after success require `len(captured) > before` and label from `captured[-1]`.
- Delete `using_reference_id` and the `nonlocal`.
- Why this shape: the label comes from the HTTP request actually sent, so it cannot drift from reality like a separate flag did.
- Wherever `StatusObservation` is serialized to output JSON (`dataclasses.asdict` or a manual dict), `route` must appear.
