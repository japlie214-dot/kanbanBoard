# T053: A failed TP clear alerts only

## Outcome
When the app cannot clear eToro's broker-set take-profit on a position it has observed, matched and annotated, the session keeps going:
- it does not set HALT;
- it does not skip execution;
- it still saves the strategy state.

The operator gets one redacted `tp_not_cleared` alert naming the position(s). There is no automatic retry and no new command.

Two cases keep today's HALT and save veto:
- a filled buy with no confirmed position id;
- a position-verification failure: the position was never observed, or its instrument does not match.

## Why
Boss decision, 2026-11-06. T049 is rejected.

A broker TP can only close a position early, at a profit. Halting over it costs more than it protects. Whether eToro places it far above entry is a live-market assertion, not yet verified: see Notes.

The real downside is the case where the TP fires. That leaves a lot the app thinks is open while the broker has closed it. Gate 11 already catches that as `unmatched_open_lot` and aborts the session before execution, without selling. This is a session abort, not a HALT-latch write. It stays.

## Amendments after precheck (2026-11-06, PM; latest wins)
Precheck verdict was FIX-FIRST, with 4 FAILs. Fixes:

1. **Split the executor report (FAIL 1).**
   - Add `tp_uncleared: list[str]` to the executor report, for the clear-failure outcomes of `_clear_take_profit` only: PATCH error, refusal, or TP still present after read-back. These come from E:248, and from E:672 when the recovery outcome is a clear failure.
   - E:213 and E:218 (verification failures) stay in `tp_failed`.
   - In `session.py`:
     - `tp_failed` keeps exactly today's handling: `halt_for_tp`, the recovery skip at S:654-657, and the save veto.
     - Only `tp_uncleared` gets alert-only handling.
   - The helpers become `halt_for_tp(items)`, unchanged in meaning but only for verification failures and unconfirmed, and `note_tp_uncleared(items)`, which records the ids and does not HALT.
   - Save veto: `elif report.tp_failed or unconfirmed:`, unchanged, with a label naming the actual cause. `tp_uncleared` never vetoes.
2. **Transport (FAIL 2).**
   - Add `tp_uncleared_positions: tuple[str, ...]` to `SessionResult`, deduped and sorted. It is populated on every return path, including early returns and aborts after recovery.
   - The notifier names positions from this field only, through `_redact_reason`.
   - `SessionResult.tp_failed` keeps its meaning (verification HALT). Add a boolean `tp_uncleared` if the notifier needs one.
3. **Alert wording (FAIL 3).**
   - Trigger: `result.tp_uncleared_positions`.
   - Text: `"[ENV] TP still set on: <ids>; session continued. Clear it in eToro if wanted."`, with no `/resume` tail and no HALT claim.
   - Fallback: `tp_not_cleared; details omitted`.
   - If another condition set the latch, or failed to write it, in the same run, the existing HALT alert and tail are sent unchanged and stay truthful. The TP alert never says "no HALT".
   - The old TP-triggered alert for verification failures stays as today.
4. **Evidence claim (FAIL 4).** Corrected inline: the preflight logs the count plus the first position's rate and multiple only.
5. **Wording.**
   - Close-recovery is `halted_before_execution` with no latch.
   - The gate-11 `unmatched_open_lot` stop is a session abort, not a latch write.
   - "Every filled buy without a position HALTs" applies to newly executed results only.
6. **Tests.**
   - Acceptance 9 is a new explicit executor-recovery test (failed row, zero PATCH).
   - Acceptance 10 is a new session-level regression through `run_session`.
   - Rename the instrument-mismatch test only if its name becomes inaccurate; it still HALTs.
