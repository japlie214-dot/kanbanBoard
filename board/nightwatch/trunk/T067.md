# Phone probes load config from the wrong home since T060

## Outcome

The in-app live probe (and every probe runner entry) loads config from files/nightwatch_config regardless of what was imported earlier in the process.

## Scope

android-probe/app/src/main/python/probe/probe_runner.py (and any sibling runner using NIGHTWATCH_HOME), plus tests.

## Acceptance

Observed 2026-11-07 07:31 and again after force-stop on Z10 build 5b5f246: 'FATAL: load_config() failed', E1-plus 'config file not found: /data/data/com.nightwatch.etoro/config/config.toml'. Cause: T060 PyBridge.redactDiagnostic (called by EventStore/SnapshotPusher at app start) imports nightwatch.host before probe_runner sets NIGHTWATCH_HOME, so the env var is ignored. Fix: probe runner entries call set_host(DesktopHost(home)) explicitly (as android_entry.py:105-106 does) and restore the previous host afterwards; a test imports nightwatch.host first, then runs the runner entry, and asserts config loads from the given home. Armed session path (android_entry) unaffected.

## Prove

Both pytest suites green; Gradle :app:testDebugUnitTest; phone probe log shows A,C,D,E1,F END ok.
