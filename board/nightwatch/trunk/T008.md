# T008 — S5f: preflight gates 6–8 wrap the eToro auth check, the environment probe, and instrument eligibility

## Outcome
Three gate functions in `engine/preflight.py`:
- `gate_6_auth` passes when an authenticated read succeeds.
- `gate_7_environment` passes only when the credential is **positively** probed as bound to the configured environment.
- `gate_8_instruments` passes when SPY, SCHG and UPRO resolve, and when the traded pair SCHG and UPRO is open-able at the amount the session will actually order for each.

Each gate is a thin wrapper over `EtoroClient` methods that already exist. No new HTTP code.

## Requirements
**Gate 6.** `gate_6_auth(*, client: EtoroClient) -> GateResult`, number 6, name `"auth"`.
- Call `client.get_balance()` once.
- On success, pass with reason `"authenticated read ok"`, and `details = {"environment": client.environment}`.
- `EtoroAuthError` → fail with reason `f"auth refused: {exc}"`.
- Any other `EtoroError` → fail with reason `f"auth check inconclusive: {type(exc).__name__}: {exc}"`.
- Non-`EtoroError` exceptions propagate (the orchestrator handles them).

**Gate 7.** `gate_7_environment(*, client: EtoroClient) -> GateResult`, number 7, name `"environment"`.
- `detected = client.probe_environment()`; `configured = client.environment`.
- `detected is None` → fail with reason `"credential environment could not be confirmed"`.
- `detected != configured` → fail with reason `f"config says {configured}, credential is bound to {detected}"`.
- Otherwise pass with reason `f"credential bound to {detected}"`.
- `details = {"configured": configured, "detected": detected}` in every case.
- Errors: `probe_environment` maps `EtoroError`s from its two GETs to `None` (`_probe_segment_access` catches `EtoroError` only). A non-`EtoroError` can still propagate; let it, because the orchestrator turns it into an `exception:` failure. Any `EtoroError` that escapes anyway → fail with reason `f"environment probe error: {type(exc).__name__}: {exc}"`.

**Gate 8.** `gate_8_instruments(*, client: EtoroClient, symbols: SymbolConfig, order_sizes: Mapping[str, float]) -> GateResult`, number 8, name `"instruments"`.
1. For each `s` in `symbols.all`, in order: `ids[s] = client.resolve_instrument_id(s)`. An `EtoroError` → fail with reason `f"{s} unresolvable: {type(exc).__name__}: {exc}"`.
2. For each `s` in `symbols.traded`, in order: `client.check_eligibility_for_order(ids[s], order_sizes[s])`.
   - `EtoroEligibilityError` → fail with reason `f"{s} not orderable: {exc}"`.
   - Any other `EtoroError` → fail with reason `f"{s} eligibility check error: {type(exc).__name__}: {exc}"`.
   - SPY is signal-only and is NOT eligibility-checked.
3. Pass with reason `"instruments ok"`, and `details = {"instrument_ids": ids, "order_sizes": dict(order_sizes), "min_position_exposure": {s: elig.min_position_exposure for s in traded}}`.
4. Before any call, raise `ValueError` if `set(order_sizes) != set(symbols.traded)` or any value is `<= 0`. The caller (S6) computes the per-symbol amounts. The gate never caps them: no cash ceiling (audit constraint).

**All three.** Stop at the first failure inside the gate. Never retry beyond what the client already does. Never call order, close or write endpoints.

## Design
- Thin wrappers. The policy (which errors fail the gate, and how) lives in the gate. The HTTP mechanics stay in the client (single responsibility). The gates take a constructed client (dependency inversion), so tests inject a `MockTransport` and S6 injects the real one.
- Gate 7 deliberately does not use `verify_environment`, because that method treats "unknown" as OK. A gate needs positive confirmation (DESIGN §6.F "probed, not trusted").
- Gate 6 uses `get_balance`, not `/balances`. DESIGN says `GET /balances` 200, but `get_balance` is the authenticated read the session actually depends on (the cash formula). Record this deviation in the docstring.
- Imports at module level: `EtoroClient` from `..etoro.client`, the errors from `..etoro.errors`, `SymbolConfig` from `..config`, plus `Mapping` (already imported from typing) (`MarketDataConfig` and `ReconciliationConfig` are already imported from there). Check for a cycle: `client.py` must not import `engine.preflight`. If importing `EtoroClient` at module level causes a cycle, use `TYPE_CHECKING` for the annotation only, and say so in the report.
