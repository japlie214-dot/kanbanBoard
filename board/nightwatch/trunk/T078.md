# Retention for device event log and daily logs

## Outcome

Device event rows and daily Python logs are bounded so months of operation can't fill storage.

## Scope

EventStore.kt, logging_setup.py, tests.

## Acceptance

Audit device-ops: EventStore has no retention (EventStore.kt:49-112); logging_setup.py daily files never rotate. Keep e.g. 90 days; export unaffected.

## Prove

Both pytest suites green; git diff --check clean; QA observes acceptance; device proof where the ticket says so.

## Design
- EventStore.kt: on each insert (cheap: at most once per app process, guarded by a static flag) run `DELETE FROM events WHERE ts < now-90d`. Retention days is a constant `RETENTION_DAYS = 90`.
- logging_setup.py: at logger setup, delete `log_YYYY-MM-DD.txt` (and the Python daily log files it creates) older than 90 days in the log dir; ignore unparseable names; never raise (log a warning).
