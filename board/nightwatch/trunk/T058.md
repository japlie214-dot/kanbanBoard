# T058: Session-wide order ceiling (audit G08)

## Outcome

isk.max_orders_per_session bounds the total of buy, UPRO close and SCHG close-leg submissions in one session. Excess intents are deferred (not submitted) with a reported reason.

## Why
Today it caps buys only (session.py:814); closes run uncapped (session.py:722-725, 768-775; close_executor.py:184-199, 417-429). A real pilot needs "at most N broker orders".

## Context
Context cites readiness audit 2026-11-06 at HEAD 21c06ba (project.md). Builder re-verifies every line before editing. Do not touch android_entry.py, Kotlin or doc/ (T054 in flight). config.toml:154-164 sets the ceiling.

## Scope
app/src/main/python/nightwatch/engine/session.py (shared counter), app/src/main/python/nightwatch/engine/close_executor.py (accept remaining budget), app/src/main/python/nightwatch/engine/executor.py (consume shared budget), tests/test_session_two_phase.py, tests/test_close_executor*.py.

## Out of scope
Notional cap semantics (buys only, recorded policy).

## Design
A durable per-session counter derived from submitted orders rows (not in-memory). Closes consume first (phase A), buys get the remainder. A deferred close leaves its intent pending for next session; strategy save follows existing veto rules for deferred work.

## Plan
counter helper → close executor → buy executor → session → tests.

## Ripple effects
Deferred closes may defer strategy save (existing conservative rule).

## Watch
Recovery submissions do not count (they never send new orders).

## Acceptance
1. Ceiling 1, one close + one buy planned: close sent, buy deferred with reason.
2. Ceiling 1, two SCHG legs: one leg sent, second deferred.
3. Crash/restart same session: counter from DB, no extra send.
4. Unset ceiling: existing arming refusal unchanged.
5. Both suites pass.

## Prove
Both full suites, offline.

## Dependencies
T057.

## Done when
QA observes acceptance.

## Amendments after precheck (2026-11-06; latest wins)
- Scope paths are under `app/src/main/python/nightwatch/` (engine/session.py, engine/close_executor.py, engine/executor.py). Config is `config/config.toml`. Add `tests/test_schg_sell.py`.
- Counter (replaces the orders-row design): count this session's intents with status in (sent, filled, recovered, unknown, abandoned-uncertain). Every executor marks the intent `sent` before the HTTP call, so a crash after broker acceptance and before the order row is still counted.
- A deferred close is NOT persisted. The next session re-decides from the strategy; the deferral is reported with a reason and vetoes the final save as today.
- Buys accept `max_orders=0` when the shared budget is exhausted (no sends, deferred with reason) instead of raising.
- Acceptance 3 is a direct executor test with a pre-seeded `sent` intent for the session and ceiling 1: zero new sends. Not a session rerun (that returns `already_ran` before counting).
- Recovery sends no new orders; a historical order row inserted by recovery for an earlier send does not count as a new send.
- PM amendment 2026-11-06 (builder block, latest wins): the counter is this session's intents with `sent_at IS NOT NULL`, any status (covers rejected, filled_unannotated, abandoned after send). The builder verifies every path that marks `sent` stamps `sent_at` before the HTTP call; if one does not, it fixes that path in the same change and tests it. Intents never sent (pending, or abandoned before send) do not count.
