# T042 — An armed session runs SCHG sells after UPRO closes, rereads cash, and passes confirmed partial closes to the interval check

## Outcome
An armed session whose phase-A intents include `LadderIntent(symbol="SCHG", side="close", amount>0)` no longer returns `armed_refused_intents`. It runs UPRO closes (T036/T038, unchanged), then the SCHG sell through `execute_schg_sell` (T041) with a fresh strict portfolio, blocks buys on any doubt, rereads cash as T038 does, then buys. The post-session interval passes `expected_unit_reductions` from the T041 ledger so app partial closes do not HALT.

## Design
1. `_supported_intent`: also accept `side=="close" and symbol=="SCHG" and amount is not None and amount > 0 and not position_ref`. Remove "SCHG sells unsupported in S7-3b" from the refusal text (other unsupported intents still refused).
2. At most one SCHG close intent per decision; more than one ⇒ `armed_refused_intents` "multiple SCHG sells".
3. Order: UPRO closes (unchanged) → if `blocks_buys`, stop as today → SCHG sell: `positions = client.get_portfolio_strict()` (fresh; exception ⇒ no send, buys blocked, reason "SCHG sell portfolio read failed"), `price = prices["SCHG"]`, `allow_partial = instrument.allow_partial_close is not False`, same `deadline` as UPRO closes → `execute_schg_sell(...)`. `blocks_buys` ⇒ no buys, `executed_partial`, strategy state not saved, reason includes the detail. Plan shortfall (notes) is appended to the reason; it does not block buys.
4. Proceeds: no sale_effects/recyclable-cash credit for SCHG (T038 sale effects are UPRO only); the existing cash reread after closes covers SCHG proceeds. Cash reread must run after the SCHG sell too.
5. Interval: `_interval_for` passes `expected_unit_reductions=repo.confirmed_unit_reductions(prev.taken_at, snap.taken_at)` (empty when `prev` is None).
6. Recovery result handling unchanged (T041 makes SCHG rows block buys via `blocks_buys`).
