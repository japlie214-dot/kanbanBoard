# T029 — At the start of a session the app resolves buys and TP clears left unfinished by a crash, without sending any buy twice

## Outcome
New `recover_unfinished(...) -> RecoveryReport` in `P/engine/executor.py` (P = `app/src/main/python/nightwatch`). For every intent with `side == "buy"` and status `pending` or `sent`, and every `tp_clears` row in status `pending` or `sent`, it looks up the broker's real state, completes the recorded steps (order row, annotation, TP clear) and reports. **It never calls `place_buy_order`.** Intents it cannot resolve stay `sent`, and after N sessions become `abandoned`.

## Why
- Consultant (2026-10-10): recover before ordinary reconciliation refuses the account; a timeout is not permission to spend again; restart must resume unfinished TP remediation, not buy again.
- `doc/DESIGN_session.md:1111–1121`: recover by referenceId, never resubmit. `:1404–1417`: N=3 sessions before abandoned.
- Without recovery, a crash after the broker fills but before the local write leaves a broker position with no annotation, and gate 11 then fails every later session.

## Context
- `Repo.pending_intents()` (`repo.py:1019`) returns pending and sent rows of all sides. `get_order_by_reference_id(reference_id) -> Order | None` (:1117). `insert_order(order) -> int` (:1083). `update_order_status(order_row_id, last_status, ...)` (:1124). `set_intent_status(intent_id, status, resolved=False)` (:1049). `get_decision(session_id)` (:943). T028 added `insert_tp_clear`, `set_tp_clear_status`, `list_tp_clears`, `next_intent_sequence`.
- Schema: `intents.session_id REFERENCES sessions(id)`; `sessions.trading_date TEXT UNIQUE`; intents status CHECK allows pending, sent, filled, rejected, recovered, abandoned; `intents.symbol` NOT NULL, `instrument_id` nullable.
- `EtoroClient.recover_by_reference_id(reference_id) -> OrderResult | None` (`client.py:1693`): None only for a real HTTP 4xx (broker has no record); auth, rate-limit, 5xx, timeout, network errors raise. Its docstring says None means "safe to resubmit": **this ticket never follows that**. `OrderResult.order_id` may be None.
- `poll_order_to_terminal(order_id=..., reference_id=...)` accepts either id and does not catch exceptions. Non-terminal statuses: 1, 2, 5, 6, 11 (`etoro/models.py`).
- T028 `executor.py`: `_buy_one` steps 6–9 (position read, annotation, TP clear) at about lines 283–346; helper `_tp_absent(pos)`; `_clear_take_profit` makes up to `TP_ATTEMPTS = 3` PATCHes, inserting a **new** `tp_clears` row per attempt.
- Config key `reconciliation.non_terminal_order_sessions_before_abandoned` (`config.py:568`, default 3) is the abandon age.
- `reserved_buy_usd(trading_date)` is **per trading date** and counts `abandoned`. So an unresolved or abandoned buy reserves cap only for its own date. That is the accepted limit; a late fill after abandonment is picked up by reconcile adoption (`engine/reconcile.py:441`, `DESIGN_session.md:369–380`), not by recovery.

## Out of scope

## Requirements
- No code path in recovery calls `place_buy_order`.
- A missing broker record never marks an intent `rejected` and never permits a resend.
- Handled rows are never reprocessed (idempotent).

## Design (PM decisions)
1. **Refactor first, behaviour unchanged.** Extract T028 steps 6–9 of `_buy_one` into `finish_filled_buy(*, repo, client, intent: LadderIntent, request_id: str, order_id: str | None, order_row_id: int, trading_date: date, spy, sleep, followups: list[str], tp_failed: list[str]) -> ExecutedBuy`. `order_id` is the already-resolved effective id (`res.order_id or order_id` as `_buy_one` computes it today). It **appends in place** to `followups` and `tp_failed` (same as today) and returns the `ExecutedBuy` with outcome `filled`. `update_order_status` and `set_intent_status(..., "filled")` stay in `_buy_one`, **outside** the helper. Signature is what the existing code needs; if the extracted body needs one more value, add it and say so in the report, never change behaviour. The 25 existing T028 tests must stay green and unmodified.
2. **`_clear_take_profit` and the `pending` row:** no change to attempts (still up to 3 PATCHes). `recover_unfinished` handles the original row itself (Design 5).
3. **`RecoveryReport`** (frozen dataclass): `resolved`, `still_unresolved`, `abandoned`, `tp_failed`, `followups`, each `tuple[str, ...]` of human lines (`tp_failed` holds position ids).
4. **Repo additions:**
   - `unresolved_buy_intents() -> list[tuple[Intent, str]]`: `SELECT i.*, s.trading_date FROM intents i JOIN sessions s ON i.session_id = s.id WHERE i.side='buy' AND i.status IN ('pending','sent') ORDER BY i.id`; build `Intent` like `pending_intents` does.
   - `sessions_since(trading_date: str) -> int`: `SELECT COUNT(*) FROM sessions WHERE trading_date > ?`.
   - `pending_tp_clears() -> list[dict]`: `SELECT * FROM tp_clears WHERE status IN ('pending','sent') ORDER BY id`, rows as dicts.
5. **`recover_unfinished(*, repo, client, abandon_after_sessions: int, sleep=time.sleep) -> RecoveryReport`** (no default for the age: T030 passes the config value). For each `(intent, trading_date_str)`:
   1. `res = client.recover_by_reference_id(intent.request_id)` in try/except. An exception = "cannot tell". `None` = broker has no record.
   2. **`res` is an `OrderResult`:**
      - `row = repo.get_order_by_reference_id(request_id)`; if None, `insert_order` one (order id from `res`, may be None; fields as T028 step 3 does).
      - Status: if `res.status` is not terminal, `poll_order_to_terminal(order_id=res.order_id, reference_id=request_id)` in try/except (pass both; `order_id` may be None). On exception, or timed out and still non-terminal: `update_order_status(row, last_status)` with the last known status, add to `still_unresolved` (then apply the age rule of step 3), and if the last status is 5 add a followup "partial fill: a live partial position may exist without an annotation". Stop for this intent.
      - Terminal and **not filled**: `update_order_status`, `set_intent_status(intent_id, "rejected", resolved=True)`, resolved line "recovered rejection".
      - Terminal and **filled**: `update_order_status`. Build `spy` from the intent's own session decision: `repo.get_decision(intent.session_id)`; map its SPY close/ATH fields to the same `SpyContext` that `execute_buys` receives (precheck pointers: `decisions` columns `schema.sql:106–121`, written at `engine/session.py:435`, class `strategy/ladder.py:186`). **If there is no decision row or no SPY close in it: do not stamp today's SPY.** Add a followup "no SPY context for intent <id>; annotation skipped", leave the intent `sent`, add to `still_unresolved`, stop for this intent. Otherwise call `finish_filled_buy(...)` with `trading_date = date.fromisoformat(trading_date_str)` and a `LadderIntent` rebuilt from the intent row (symbol, side open, amount, book catapult, reason from the row). Then:
        - if the position was **not visible** (the helper added the "position not visible" followup, no annotation written): leave the intent `sent` (so the next session retries) and add to `still_unresolved`;
        - else `set_intent_status(intent_id, "recovered", resolved=True)`, resolved line "recovered fill". TP failure does not block this: the `tp_clears` rows track it.
   3. **`res is None` or cannot tell:** leave the status as is (`pending` or `sent`). `age = repo.sessions_since(trading_date_str)`. If `age >= abandon_after_sessions`: `set_intent_status(intent_id, "abandoned", resolved=True)`, add to `abandoned`; else add to `still_unresolved`. Never resubmit.
   4. **TP clears**, after the intents. For each `pending_tp_clears()` row: `get_portfolio()` (one read per row; exception → leave the row, add a followup, continue); find the position by `position_id`.
      - Position found and `_tp_absent(pos)` → `set_tp_clear_status(id, "cleared", "confirmed at recovery")`.
      - Found with a TP (including `take_profit_rate is None` with `is_no_take_profit` False: not confirmed absent) → first `set_tp_clear_status(id, "failed", "superseded by fresh attempt")`, then run `_clear_take_profit` (new request ids, rows persisted first, as T028). Success → nothing more (its own row is `cleared`); failure → add the position id to `tp_failed`.
      - Position absent → `set_tp_clear_status(id, "failed", "position not in portfolio")` and a followup.
      - Every handled row ends in `cleared` or `failed`, never `pending`, so recovery never loops.
6. **Why:** recovery reads the broker first and only completes bookkeeping. A missing record never frees anything or permits a resend; age only escalates visibility. Old fills use their own session's SPY, never today's.

   1. `sent` intent, broker returns a filled order, position visible → intent `recovered`, order row terminal, annotation with the **original session's** SPY close, TP cleared; resolved contains "recovered fill".
   2. Broker returns a non-terminal order (status 11); poll reaches terminal rejected → intent `rejected`.
   3. Broker returns None, age 1 → stays `sent`, in `still_unresolved`.
   4. Broker returns None, age 3 (`abandon_after_sessions=3`) → `abandoned`, in `abandoned`; `reserved_buy_usd` for **that intent's own date** still counts it.
   5. `recover_by_reference_id` raises `EtoroTimeoutError` → cannot tell, stays `sent`.
   6. `pending` intent with no order row (crash before send), broker None → stays `pending` (not changed to sent), `still_unresolved`.
   7. Filled but position not visible → followup, no annotation, intent stays `sent`, in `still_unresolved`; a second call after the position becomes visible → annotated, `recovered`.
   8. Filled but the intent's session has no decision row → followup "no SPY context", no annotation, stays `sent`.
   9. Non-terminal poll timeout at status 11 → order row `last_status` updated, intent `sent`, `still_unresolved`; same with status 5 → followup mentions a possible partial position.
   10. Found order with `order_id` None → poll called with `order_id=None, reference_id=rid`, flow continues.
   11. `tp_clears` row `sent`, broker already shows no TP (`is_no_take_profit` True) → `cleared`.
   12. `tp_clears` row `pending`, broker shows TP → the original row `failed` ("superseded by fresh attempt"), a new row `cleared`, one PATCH with a **new** request id; if read-back stays dirty after 3 attempts → new rows `failed`, `tp_failed` has the position.
   13. Position with `take_profit_rate=None` and `is_no_take_profit=False` → NOT cleared (PATCH is called).
   14. `tp_clears` row whose position is absent → `failed`, followup.
   15. Second `recover_unfinished` call on the same state → zero extra broker writes, no handled row reprocessed.
   16. Two intents, one filled and one None → handled independently.
5. Prove.
