# Write SCHG daily values so the annual budget uses prior-year history

## Outcome

Each session records the SCHG position value so the yearly budget rollover uses prior-year values instead of always 0.4 x current equity.

## Scope

engine/session.py, db/repo.py, tests.

## Acceptance criteria (audit basis)

Audit S7/G13: `db/repo.py:2304` defines a date-keyed upsert but the production session has no caller. `strategy/ladder.py:483–513` already uses a prior-year mean when supplied at rollover, falls back with a warning if absent, uses sleeve equity at bootstrap, and holds the established budget within the year. The gap is recording and explaining the actual inputs, not the rollover formula.

## Paired delivery design — 2026-11-18

This remains backlog pending the exact shared rule-record contract in T082 and independent precheck of the complete slice. Do not ship the write without its dashboard view. Do not add override behavior here: `engine/session.py:659–660` explicitly warns that it is not honored, so give that its own observable rule and never label an override as applied for this slice.

- Record the same pre-decision managed-long SCHG value that the engine used for the sleeve, measured with the validated provisional SCHG close, once per trading date after a matching session snapshot is durably inserted. Do not derive it from post-execution broker holdings. The pre-decision input and post-decision snapshot are different observations. Require a successful authoritative portfolio read, validated SCHG units and mark, finite nonnegative aggregate, and the matching snapshot. Incomplete unrelated PnL fields do not turn a separately validated input into zero. A verified empty managed SCHG book may record zero; missing, invalid, aborted or not evaluated inputs must not write zero. Test those distinctions. Preserve previous valid rows if a later attempt has no validated value; no historical backfill under this ticket.
- Keep the current budget calculation and state semantics. Display the number and mean of observed prior-year samples, not a claim of complete calendar coverage. For a nonempty partial sample label it `Observed history; coverage not established`; the current engine accepts any nonempty sample. No new minimum coverage threshold is implied. For zero samples and a rollover display the sleeve-equity fallback warning. For bootstrap and same-year retention, show the actual reason the engine selected that path even if history exists. An available history sample is not proof it drove the budget.
- Persist the evaluation at the engine decision point: source path (`bootstrap`, `prior_year_mean`, `missing_history_fallback`, or `retained`), trading date and evaluation time, target and input year, sample count and mean, sleeve equity, configured fraction and rounding step, output budget, sizing floor, order size and cash target, with an explicit status/reason. Record successful or skipped daily sampling separately; budget sizing is not an order or fill. Project only those explicitly named fields in the Nightwatch dashboard, with source age, unknown/stale and not-evaluated states, and without raw positions, order IDs, private data or remote controls. The view uses persisted inputs rather than recomputing the rule or parsing human reason strings.
- Confirm the same evidence in seeded local engine and browser fixtures: applied nonempty rollover, empty-history fallback, known zero vs missing, bootstrap with available history, same-year deposit/retained budget, abnormal snapshot and write failure, and older sessions without records. No device or cloud action, no broker test, and no conversion of the current T081 payload into rule telemetry.
