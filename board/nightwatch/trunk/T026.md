# T026 — Before any order is sent, the app trims the ladder's intents to the session limits. Buys count against a per-trading-date cap that includes in-flight orders.

## Outcome
`apply_submission_limits(...)` is a pure function in a new module `P/engine/limits.py`. It takes the ladder's intents and returns `(accepted, dropped)`, where each dropped item carries a reason. Sells always pass. Buys pass **in ladder order** until the first buy that would break a limit; that buy and every later buy are dropped (a strict prefix).

The limits are:
1. buy notional per trading date ≤ `max_notional_per_session_usd`, counting what is already reserved that date;
2. running cash;
3. open lots ≤ `max_open_lots` after the new UPRO/SCHG opens;
4. the per-instrument broker minimum.

A Repo query returns the reserved buy notional for a trading date.

## Why
- Boss decision A (2026-10-10): the cap counts **buys only**. When over the cap, take whole buy intents in ladder order up to the cap and re-decide next session. In-flight buys count across restarts (consultant: an unresolved submission is never free money).
- Today nothing enforces `max_notional_per_session_usd` or `max_open_lots` against intents: gate 12 marks them `evaluated_elsewhere` (`engine/preflight.py:463–486`). The 2026-10-09 demo decided about $90.7k of buys.

## Design (PM decisions)
1. `@dataclass(frozen=True) class Dropped: intent: LadderIntent; reason: str`.
2. `apply_submission_limits(intents: Sequence[LadderIntent], *, cap_usd: float, reserved_usd: float, cash_usd: float, open_lots: int, max_open_lots: int, min_order_usd: Mapping[str, float]) -> tuple[list[LadderIntent], list[Dropped]]`:
   - Walk the intents in order. `side == "close"` → always accepted (sells reduce risk, boss A).
   - For `side == "open"`, with `amt = intent.amount`:
     - `amt is None or amt <= 0` → drop, reason `"buy without amount"` (continue: it does not stop the prefix).
     - `amt < min_order_usd.get(symbol, 0.0)` → drop, `"below broker minimum ${min:.2f}"` (continue).
     - Once **stopped**, every later open → drop, `"after cap stop"`.
     - `reserved + used + amt > cap_usd + 1e-9` → drop `"session buy cap ${cap:,.0f} (reserved ${reserved:,.2f} + accepted ${used:,.2f})"` and **stop**.
     - `cash_left − amt < −1e-9` → drop `"insufficient cash ${cash_left:,.2f}"` and **stop**.
     - `open_lots + new_lots + 1 > max_open_lots` → drop `"max_open_lots {max}"` and **stop**.
     - Else accept: `used += amt`, `cash_left −= amt`, `new_lots += 1`.
   - Return `(accepted, dropped)`, both in input order.
   - Note: each open creates one broker position, so one lot. Sells are not credited back to cash here: phase B re-decides with real cash.
3. `Repo.reserved_buy_usd(trading_date: str) -> float` = `SUM(amount_usd)` over `intents` joined to `sessions` on `session_id`, where `sessions.trading_date = ?`, **`side = 'buy'`** (precheck: the persisted schema uses `buy`/`close`, `schema.sql:191–195`; the ladder says `open`, so the S7-3 executor maps open→buy), and `status IN ('pending','sent','filled','recovered','abandoned')`. Only `rejected` frees the cap. Abandoned stays reserved until broker evidence shows it is final (consultant). Return 0.0 when there are none.
4. **Why:** a pure function is fully testable. The reservation query makes the cap survive restarts. The strict prefix keeps the ladder's priority and avoids cherry-picking smaller later buys.
