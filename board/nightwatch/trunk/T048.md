# T048 — Redact every session outcome reason at its choke points

## Outcome
Every reason the session persists (`sessions.outcome`, `sessions.error`), returns (`SessionResult.reason`) or sends (notifier text) goes through one config-seeded redaction helper, with redaction before truncation and a type/count-only fallback when the sanitizer fails. Nothing else about statuses, HALT behaviour or control flow changes.

## Why
T047 QA (2026-10-31) reproduced a pre-existing leak with a synthetic config-known secret:
- a read-only recovery annotation failure followed by normal completion gives `executed`;
- a reconciliation failure plus a HALT-persistence exception followed by completion gives `executed_partial`.

In both cases the secret appeared in the DB outcome, `SessionResult.reason` and the notification. T047 only redacts its two new abort statuses.

## Context (HEAD 8174e66, `app/src/main/python/nightwatch/engine/session.py`)
- T047 redaction lives inline in `abort()` at :468-484. It strips config secrets (etoro/telegram/tiingo `secrets.values()`, longest first), then calls `RedactionFilter.redact`, then truncates. On failure it falls back to `prefix + recovery_counts`. This applies only to `market_data_failed`/`aborted_before_orders`. Every other status gets `reason += recovery_text + halt_text` unsanitized (:482).
- `halt()` at :426-432 appends `f"{text}; HALT persistence failed: {type(exc).__name__}: {exc}"` to `halt_text`, and stores `halt_error = str(exc)`, which is persisted to `sessions.error` unsanitized at :483 and :886.
- Recovery followups build `recovery_text` at :499-502, including verbatim exception text (e.g. from `executor.py:241-242`).
- The finish path appends the suffix at :837 and persists at :886 (`repo.finish_session(... state="finished", outcome=reason, error=halt_error)`).
- `format_session_report` is at :894. Notifier sends are at :940, :954, :965 and :995. The HALT reason written by `write_halt(host, reason=halt_reason, ...)` at :876-879 is internal interval text.
- `android_entry.py` envelopes carry status/reason_code/error_type only (A80-A154). Check that no free-text reason is forwarded; if one is, it must use the same helper.

## Scope
- `app/src/main/python/nightwatch/engine/session.py`: extract one helper, e.g. `_redact_reason(text, *, config, fallback) -> str`, from the T047 inline code. Use it at every choke point:
  - `abort()` for all statuses;
  - the finish path at :837/:886;
  - `halt_error` before it is persisted;
  - the `halt()` HALT-persistence-failure text;
  - every string passed to `notifier.send` (or `format_session_report` output once).
- `app/src/main/python/nightwatch/android_entry.py`: only if it forwards free-text reasons.
- Tests: a new `tests/test_session_redaction.py`, plus minimal expectation updates in existing session tests if truncation or fallback wording changes.

## Out of scope
- Executor/recovery message generation (`executor.py`), logging configuration, Telegram client internals, Kotlin.
- Any status, HALT, save or control-flow change.
- Live runs.

## Design
1. The helper composes first, then strips config secrets longest first, then calls `RedactionFilter.redact`, then truncates. The T047 limits are kept: 300 characters of free text after the prefix for exception reasons, unchanged otherwise.
2. When the sanitizer raises, the helper returns a caller-supplied fallback with no foreign free text: the exception type, recovery counts, and `"; HALT details omitted"` when HALT text exists.
3. `halt_error` is redacted before persistence. On fallback it becomes the type name only.
4. Notification text is redacted once, immediately before each `notifier.send`, or `format_session_report` returns redacted text and every send path uses it. Choose one and state which.
5. The T047 behaviour for `market_data_failed`/`aborted_before_orders` is unchanged. Its tests must pass untouched.

## Acceptance
1. Both QA scenarios (`executed`, `executed_partial`), with a synthetic secret registered in config: the secret is absent from `sessions.outcome`, `sessions.error`, `SessionResult.reason` and every captured notification.
2. The same two scenarios with `RedactionFilter.redact` forced to raise: no foreign free text remains, and the fallback text is present.
3. One `abort()` status other than T047's (e.g. a `preflight_failed` path with a recovery suffix) is also redacted, under both sanitizer modes.
4. A HALT-persistence failure whose exception contains the secret: the secret is absent from `halt_text`-derived reasons and `sessions.error`.
5. The T047 abort-status tests pass unchanged. No status, gate or save-count assertions change.
6. Both full suites pass: `.venv/Scripts/python.exe -m pytest -q -rs` and `C:/Users/10102721/AppData/Local/Programs/Python/Python313/python.exe -m pytest -q -rs` (baseline 1814).
