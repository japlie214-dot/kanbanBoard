# Cloud dashboard shows real session figures and Telegram links to it

## Outcome

The cloud dashboard page shows the phone's latest session, decision, portfolio and recent session history instead of dashes, and a Telegram command replies with the dashboard address.

## Why

Review 2026-11-12, finding N1 (reproduced): the cloud page reads `account`, `sleeve`, `positions` and an environment field; the phone pushes `probe`, `device`, `halt`, `recent_events`, `latest_checks`. No key overlaps, so every figure shows a dash. Boss, 2026-11-12: one dashboard, the cloud page. Boss, 2026-11-13: wants to reach the dashboard from Telegram, and the PM may only read evidence after the close without the phone plugged in; the page is that evidence.

## Requirements

1. The pushed snapshot keeps every key it has today and gains the page's keys.
2. Only allowlisted fields leave the phone. Nothing from the raw broker payload, no account identifier, no order id, no credential, no free text other than the decision reason, which goes through the existing redaction.
3. An export failure never blocks the push of the existing keys, the session, or the alarm.
4. The page shows, for the latest session: date, environment, armed or dry, state, preflight verdict and the failed gate if any, the decision reason, the number of intents, and the seed status when a seed result file exists (status word only).
5. The page shows the last 30 sessions as a table: date, armed, state, decision reason, orders.
6. A snapshot is pushed after the session ends, so the page reflects the session that just ran.
7. Telegram `/dashboard` replies with the configured address, or says plainly that none is configured.
8. The page renders an old-shape snapshot (today's keys only) without errors, as it does now.

## Design

**`notify/dashboard_export.py`**

```python
MANAGED = ("UPRO", "SCHG")

def dashboard_snapshot(repo, *, history: int = 30) -> dict:
    """Page-shaped, allowlisted view of the latest session. Empty dict when there is no session yet."""

def export_json(home: str) -> str:
    """Kotlin entry: open this home's database read-only, return json.dumps(dashboard_snapshot(...)); '{}' on any failure."""
```

Fields, taken from the prototype, plus:

- `last_session`: `{trading_date, state, armed, preflight, failed_gate, next_run_at}`.
- `last_decision`: `{reason, intents, cone_z, spy_drawdown, tier, budget_usd, order_size_usd}`.
- `recent_sessions`: up to `history` rows, newest first: `{trading_date, armed, state, reason, orders}`.
- `seed`: `{"status": <status word>}` read from `SEED_DEMO.adopt.done` if present, else `SEED_DEMO.done`, in the home; only the `status` string, and only if it matches `^[a-z_]{1,40}$`.
- `sleeve.cash_reserve_usd` from the stored sleeve block (the page shows it where "cash allocation" was). `sleeve_realized_pnl_usd` is omitted; the page shows a dash.

Database access: open read-only (`mode=ro` URI, as `adopt_apply._open_for_apply` opens `mode=rw`); never create or migrate. Missing database: `{}`. `export_json` wraps everything; it never raises and never prints values.

**Kotlin**

- `PyBridge.dashboardSnapshot(context, home): String?` under `bridgeLock`, returning `null` on any exception.
- `SnapshotPusher.buildSnapshot`: after building today's map, pick the home (`nightwatch_demo` when `ARM_DEMO` exists, else `nightwatch_config`), call the bridge, parse as `JSONObject`, and copy **only** these top-level keys when present: `environment`, `trading_date`, `account`, `sleeve`, `positions`, `last_session`, `last_decision`, `recent_sessions`, `seed`. The decision `reason` strings (in `last_decision` and each `recent_sessions` row) are passed through the same `redact` function as events; a `null` from redaction drops the field. Any failure leaves today's snapshot unchanged and logs `SNAPSHOT_EXPORT_FAILED` with the exception class only.
- `WakeService`: after the alarm branch's session block (after `sessionRunning.set(false)`), one more `SnapshotPusher.pushNow(this, checkResults)` in its own try/catch. Nothing else moves.

**Telegram `/dashboard`** (`notify/commands.py`): add `"/dashboard"` to `SUPPORTED_COMMANDS` and a `_dashboard_reply(config)` returning `Dashboard: <url>` when `config` carries a non-empty `dashboard_url` that starts with `https://`, else `Dashboard address is not configured.` The setting is a plain, non-secret string in the config file (`[notify] dashboard_url = "..."`), default absent. Add `dashboard` to the Worker's `ALLOWED_COMMANDS` so the two lists stay in step, and to `/help`.

**Page**: a "Last session" card (date, environment, armed or dry, state, verdict and failed gate, decision reason, intents, seed status) above the account card; "Cash reserve" replaces "Cash allocation"; a "Recent sessions" table under positions. All values with `textContent`. Missing blocks render as dashes or "No sessions yet". `stub-snapshot.json` gains the new blocks.

Why this shape: the export is one read-only Python function over rows the session already stores, so no new broker call and no new write; Kotlin copies named keys only, so the allowlist is enforced twice; the extra push is the only change to the wake path.

## Watch

- Allowlist, not blocklist: copy named keys; never forward a dict wholesale from the database or the broker payload.
- No position id, order id, CID, token or key in the export. Test with a seeded payload containing marker strings in every raw field and assert none appears in the output.
- The export must not create, migrate or lock the database for writing: open read-only, and test against a missing and an outdated database.
- Do not move the existing first push or the session call.
- The export runs under `bridgeLock` on the wake thread: it must be fast (one session, one snapshot, 30 rows) and must not hold the session lock.
- Never read or print `.secrets.env`, the push secret or the read token. No deploy, no `wrangler` command that publishes. No device commands. No git state changes.
- Decision reasons are free text written by the strategy; they pass through redaction and are capped at 300 characters.

## Acceptance

1. `dashboard_snapshot` on a seeded database returns the page's keys with the values from the seeded rows; with no session it returns `{}`.
2. Marker strings planted in raw broker fields, ids and config never appear in the export or in the Kotlin-merged snapshot.
3. Missing database, outdated schema, corrupt seed result file: `export_json` returns `{}` (or omits `seed`), raises nothing, writes nothing; the database file's bytes and modification time are unchanged.
4. Kotlin merge: only the nine named keys are copied; today's five keys are unchanged; an export of `null`, `{}`, invalid JSON or a JSON array leaves the snapshot exactly as today.
5. `WakeService` pushes once before and once after the session; a failure of the second push does not affect the session result handling (source wiring test).
6. `/dashboard` with a configured `https://` address replies with it; unset, empty or non-https replies "not configured"; an unauthorised chat gets what every other command gives it. `/help` lists it. The Worker's allowed list contains `dashboard`.
7. Page with the new stub: last-session card, account, sleeve with cash reserve, positions, recent sessions all filled. Page with today's old-shape snapshot: renders as today, no console error. Page with an export from the seeded database: real figures.
8. Builder report states when Telegram commands are read on the phone, the Worker's snapshot limits, and the measured snapshot size.
9. Both Python suites, Gradle unit tests, the Pages and Worker test suites pass; `git diff --check` clean.
