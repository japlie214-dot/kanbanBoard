# T007 — S5e: preflight gate 5 checks DB integrity, schema version, and that no prior session is unfinished

## Outcome
`gate_5_database` exists in `engine/preflight.py`. It fails when any of these holds:
- the database fails SQLite's quick integrity check;
- the applied schema version differs from the latest version the code ships;
- a session other than the current one never reached a terminal state.

Otherwise it passes.

## Why
project.md S5. DESIGN.md gate table line 716: "Cannot open, schema version mismatch, or an unfinished prior session exists". An unfinished prior session means yesterday's run died midway. It may have left an intent in flight, so trading again on top of it is unsafe until a human looks.

## Context (PM read 2026-10-02; repo `repos/etoroNightwatch`, P = `app/src/main/python/nightwatch`)
- `P/db/repo.py`:
  - `Repo.open(path, host)` (line 524) connects AND runs `migrate()`. So by the time preflight holds a `Repo`, "cannot open" has already either raised or succeeded.
  - `Repo.schema_version()` (line 534) returns `migrations.current_version(conn)`, the MAX of the `schema_version` table.
  - `Repo.unfinished_sessions()` (line 823) returns sessions whose `state NOT IN ('finished', 'aborted', 'failed')`, ordered by trading_date.
  - `Repo.conn` is a public `sqlite3.Connection`.
  - `repo.finish_session(id, state="finished")` exists (used in `tests/test_repo.py:131`).
- `P/db/migrations/__init__.py`: `discover()` returns every migration, baseline first, in version order. `tests/test_schema_migrations.py:120` asserts `repo.schema_version() == migrations.discover()[-1].version`, so the "expected version" is `migrations.discover()[-1].version`. Migrations are forward-only.
- **Trap:** `run_preflight(gates, *, repo, session_id)` runs inside the CURRENT session, whose row exists with a non-terminal state (`create_session` defaults to `state="started"`). `unfinished_sessions()` therefore always contains the current session. Gate 5 must exclude `session_id`, or it fails every day.
- `P/engine/preflight.py` already imports `Repo` from `..db.repo`. Follow the style of `gate_1_halt` and `gate_4_clock`. The stub comment for gate 5 is at lines 40–41.

## Scope
- `P/engine/preflight.py`: add `gate_5_database`, and update the gate 5 stub comment and the built-gates comments (currently "1, 4, 9, 10 and 11").
- New file `tests/test_preflight_gate_5.py`.

## Out of scope
- Recovering or auto-closing an unfinished session. A human does that.
- Changing `Repo`, migrations, the schema, or `session.py`.
- Telegram.

## Requirements
1. Signature: `gate_5_database(*, repo: Repo, session_id: int) -> GateResult`, with gate number 5 and name `"database"`.
2. Run the checks in this order and return at the first failure:
   1. `repo.conn.execute("PRAGMA quick_check").fetchall()` must be exactly `[("ok",)]`, compared by value as `[tuple(r) for r in rows] == [("ok",)]`. Otherwise fail with reason `f"database quick_check failed: {first_row_text}"`, and put up to 5 row texts in `details["quick_check"]`.
   2. `actual = repo.schema_version()` and `expected = migrations.discover()[-1].version`. If they differ, fail with reason `f"schema version {actual}, code expects {expected}"`.
   3. `others = [s for s in repo.unfinished_sessions() if s.id != session_id]`. If `others` is non-empty, fail with reason `f"{len(others)} unfinished prior session(s): " + ", ".join(f"{s.trading_date} (id {s.id}, state {s.state})" for s in others)`. Also set `details["unfinished_ids"] = [s.id for s in others]`.
3. On pass, the reason is `"database ok"`, and `details` = `{"schema_version": actual}`.
4. An `sqlite3.Error` from any check propagates. `run_preflight` turns it into an `exception: …` failure. Do not catch it inside the gate.
5. The gate writes nothing to the DB.

## Design
- Import `migrations` at module level (decided): `from ..db import migrations`, since `preflight` already imports `..db.repo`, which imports `migrations`. So there is no new edge.
- Excluding the current session is the one non-obvious rule. Put a one-line comment on it that cites this ticket's trap.

## Plan
1. `preflight.py`: add the import, then add `gate_5_database` after `gate_4_clock`, before `gate_9_calendar`. Update the comments.
2. `tests/test_preflight_gate_5.py`, using the `repo` fixture from `tests/conftest.py`. Cases:
   - fresh DB plus the current session only (`create_session("2026-10-02", mode="dry_run", environment="demo", armed=False)`): passes, and `details["schema_version"] == migrations.discover()[-1].version`;
   - a prior session `2026-10-01` left `started` plus the current one: fails, the reason contains `2026-10-01` and `state started`, and `unfinished_ids == [prior.id]`;
