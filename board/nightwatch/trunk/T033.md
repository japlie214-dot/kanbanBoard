# T033 — An armed session sells first, re-derives cash, decides again and buys, saving strategy state exactly once with `bars` advanced once

## Outcome
The armed path in `P/engine/session.py` follows `doc/DESIGN_session.md` §5 steps 6a–9b:
- phase A decide → execute closes (T032) → persist the phase A sell outcome;
- re-read the balance → phase B decide → execute SCHG and UPRO buys;
- one final state save and the snapshot.

It no longer refuses decisions that contain closes or UPRO buys (T030 Design 4).

## Why
- S7 plan item 6 (Boss-approved 2026-10-10).
- §7.1: `bars` must advance once per session. Phase B gets phase A's `new_state` with `bars` held at the pre-phase-A value.
- §7.2: the final `strategy_state` is written last, once.

## Context
- T030 armed path (`P/engine/session.py`, commit 55da9bb): the Design 4 refusal of non-SCHG-open intents, `apply_submission_limits`, `execute_buys`, `halt_for_tp`, the narrow save rule, and `orders_sent`/balance re-read.
- `strategy/ladder.py` `LadderDecision` (:460): intents, new_lots, updated_buckets, closed_lots, new_state, reason, warnings.
- `execute_buys` accepts **SCHG opens only** (`engine/executor.py:404–407`). UPRO buys need either an executor extension or a refusal; see Design 4.
- Bucket persistence: `Repo.upsert_bucket` (`db/repo.py:1742`). The `strategy.state` load/save pair.
- `build_ladder_inputs` (`session.py`, around :209) builds cash/equity/open_lots from positions and balance.

## Scope
`P/engine/session.py`, `tests/test_session_armed.py` (extend), and `P/engine/executor.py` only for Design 4.

## Out of scope
Real-account, config, Telegram format beyond the reason text, the `allow_partial` default (stays False).

## Design (PM decisions)
1. **Phase A:** `d_a = decide(inputs_a, state0, cfg)`; persist the decision row with reason prefix "phase A". Close intents = `[i for i in d_a.intents if i.side == "close"]`.
2. **Execute closes** with `execute_closes(..., allow_partial=False, max_orders=config.risk.max_orders_per_session, deadline=close − 5 min)`.
   - If the report has `unverified`, `stopped` or any `unresolved` result: write HALT on `unverified` (same pattern as `halt_for_tp`, reason "close not confirmed on position(s) ..."), **skip phase B**, do not save state, status `executed_partial`, then the snapshot.
3. **Persist phase A** (§7.2 row 3), only when every close was confirmed: upsert `d_a.updated_buckets`. Do not save strategy state yet.
4. **Phase B:**
   - `positions`/`balance` re-read; `inputs_b` built with the same prices.
   - `state_b = replace(d_a.new_state, bars=state0.bars)` (§7.1).
   - `d_b = decide(inputs_b, state_b, cfg)`, persisted with "phase B, authoritative".
   - Buys = `[i for i in d_b.intents if i.side == "open"]`. Any close in `d_b` is executed with a second `execute_closes` call (§3.1 step 11, no phase C).
   - UPRO opens: this ticket extends `execute_buys` validation to accept `symbol in config.symbols.traded`. Annotation book: `catapult` for UPRO, `core` for SCHG. Precheck that `finish_filled_buy` handles UPRO; if it needs more than the validation change, stop and report rather than guess.
5. **Limits:** phase B buys go through `apply_submission_limits` as in T030. Recovery `tp_failed` still skips all execution (T030 5b).
6. **Save:** `save(repo, d_b.new_state)` once, only when all closes were confirmed, all buys filled per the T030 narrow rule, nothing was dropped, stopped or deferred. Otherwise "strategy state not saved: ..." (§7.3 re-decide is the fallback).
7. **Statuses:** `executed` (both phases complete), `executed_partial` (stopped after phase A, or any not-saved case after execution), `halted_before_execution` (T030). CLI: exit 0 for `executed` only.
