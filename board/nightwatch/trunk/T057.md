# T057: Persist gate-11 reconciliation (audit G07)

## Outcome
When gate 11 resolves a discrepancy through abandoned-intent adoption/resolution, the sidecar (lot annotations, intents) is updated in one transaction before gate 11 passes; failure fails the gate.

## Why
Gate 11 returns proposed adoptions in details (preflight.py:1060-1134) and nothing persists them (session.py:128-143, 250-269); adopted UPRO lots lack SPY entry context (reconcile.py:418-438).

## Context
Context cites readiness audit 2026-11-06 at HEAD 21c06ba (project.md). Builder re-verifies every line before editing. Do not touch android_entry.py, Kotlin or doc/ (T054 in flight).

## Scope
app/src/main/python/nightwatch/engine/preflight.py, app/src/main/python/nightwatch/engine/reconcile.py, app/src/main/python/nightwatch/db/repo.py (apply_reconciliation), tests/test_reconcile.py, tests/test_preflight*.py.

## Out of scope
Manual TP-fired lot clearing (separate follow-up).

## Design
Gate 11 calls repo.apply_reconciliation(changes) in one transaction; adoption builds annotation with the original intent's decision context (entry_reference_spy from the intent's session decision). Missing context → gate fails with 
econcile_context_missing, no partial write. Dry sessions compute but never apply.

## Plan
repo API → reconcile context → gate wiring → tests → suites.

## Ripple effects
Annotation counts feed limits.py open-lot input.

## Watch
Idempotent: rerunning gate 11 must not double-apply.

## Acceptance
1. Abandoned buy later found at broker: annotation written with SPY context, gate passes, second run no-op.
2. Context missing: gate fails, no rows changed.
3. Dry: no writes.
4. Both suites pass.

## Prove
Both full suites, offline.

QA observes acceptance.
