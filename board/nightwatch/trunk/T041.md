# T041 — An SCHG dollar-amount sell becomes persisted full/partial close legs that are sent once, confirmed by portfolio units, recorded in a partial-close ledger, and never mistaken for an integrity breach

## Outcome
- `EtoroClient.lookup_close_order` and `poll_order_to_terminal(kind="close")` accept the partial-close payload eToro actually returns (two position IDs), when the caller names the position it closed.
- New `execute_schg_sell(...)` in `P/engine/close_executor.py` turns one `LadderIntent(symbol="SCHG", side="close", amount=X)` into a deterministic plan of full and partial close legs, executes the legs one at a time, and stops on any doubt (`blocks_buys=True`).
- New migration `011_partial_close_effects.sql` and repo methods: every leg's ledger row exists **before** the send; confirmation updates it; recovery finishes it without sending.
- `compute_interval` no longer raises an integrity HALT for a units drop that equals a confirmed app partial close passed in by the caller; such a position is reported `incomplete` (attribution not modelled), never `integrity`.
- Session wiring (letting an armed session run SCHG sells) is **T042**, not this ticket. After T041 the session still refuses SCHG sells exactly as today.

- `project.md` S7-4: partial-close ledger so integrity (T022, `interval_pnl`) does not false-HALT on app partial closes. T038 left SCHG sells refused (`P/engine/session.py:556`).

## Design
**D1 Parser.** `_parse_close_order_result(data, *, expected_order_id, expected_position_id: str | None = None)`:
- 0 or 1 distinct position IDs: unchanged behaviour (fill fields stay as today).
- ≥2 IDs and `expected_position_id is None`: raise `EtoroValidationError("close-orders returned multiple position IDs")` (unchanged; UPRO path keeps refusing).
- ≥2 IDs with `expected_position_id` given: valid only if exactly 2 distinct IDs, `expected_position_id` is one of them and its entry has no `units`, and the other entry ("slice") has numeric `units > 0`. Return `OrderResult(position_id=expected_position_id, fill_units=slice.units, fill_price=slice.rate (if numeric), fill_amount_usd=data.proceeds (if numeric), raw=dict(data))`. Any other shape raises `EtoroValidationError` naming the shape. The slice ID is read by callers from `raw["positions"]`.
- `lookup_close_order(order_id, *, expected_position_id=None)` passes it through. `poll_order_to_terminal(..., expected_position_id=None)`: used only when `kind=="close"`; `ValueError` if given with `kind="open"`.

**D2 404 tolerance (executor side, not client).** The client still raises on 404. The executor's leg finisher treats `EtoroValidationError`/`EtoroError` whose `status_code == 404` as "not yet visible": retry the poll every 2 s while `now() < min(deadline, leg_start + 90 s)`; other exceptions → unresolved immediately. If still 404 at the bound, fall through to portfolio confirmation (D4); never resend.

**D3 Plan (pure).** `plan_schg_sell(positions, *, amount, price, instrument_id, min_position_value=MIN_POSITION_VALUE_USD, allow_partial=True) -> SchgSellPlan(legs, planned_value, shortfall, notes)`; legs = `(position_id, units_before, units_to_deduct | None)`.
- Candidates: positions with `instrument_id == instrument_id`, `units > 0`. Order by `open_rate` descending, tie by `position_id` ascending. Market value = `units * price` (never `amount`).
- Walk: if lot value ≤ remaining + 0.005 → full leg (`units_to_deduct=None`), remaining -= value. Else partial: `u = floor6(remaining / price)`; legal if `allow_partial` and `u*price >= min_position_value` and `partial_close_leaves_legal_remainder(lot_value, u*price, min_position_value=...)`; legal → partial leg, stop. Not legal because remainder would be illegal → full leg of this lot (overshoot ≤ one lot, noted). Not legal because slice < min or `allow_partial` False → stop (shortfall noted).
- `amount <= 0`, `price <= 0`, no candidates → empty plan with note. floor6 = floor to 6 decimals.

**D4 Execute.** `execute_schg_sell(*, repo, client, session_id, intent, instrument_id, positions, price, deadline, allow_partial=True, now=..., sleep=...) -> CloseReport` (reuse `CloseReport`/`CloseOutcome`):
- Refuse before any write unless `intent.symbol=="SCHG" and intent.side=="close" and intent.amount > 0 and not intent.position_ref`; `positions` must be the caller's fresh strict portfolio (documented; T042 guarantees).
- Per leg, in order, stop at first non-confirmed leg (`blocks_buys=True`, later legs listed as not attempted):
  1. `request_id = new_request_id()`; `insert_intent(Intent(symbol="SCHG", side="close", instrument_id, units=units_to_deduct or units_before, position_id=pid, reason=intent.reason, session_id, sequence=next))`; `repo.insert_partial_close(intent_id, position_id=pid, units_before, units_deducted=units_to_deduct (None for full))` with status `pending` — both committed **before** the send; `set_intent_status(intent_id,"sent")`.
  2. `client.close_position(request_id, pid, instrument_id, units_to_deduct)`; send exception → order row with error, ledger `unresolved`, stop. Never resend.
  3. `insert_order(...)`, `repo.set_partial_close_order(ledger_id, order_row_id, order_id)`.
  4. Poll with D2 (`expected_position_id=pid` for partial legs; none for full legs). Terminal non-FILLED → intent `rejected`, ledger `rejected`, stop (blocks buys). Non-terminal/timeout → unresolved.
  5. Confirm with `get_portfolio_strict()` every 3 s up to `min(deadline, leg_start+90 s)`:
     - full leg: confirmed only when the close lookup was FILLED **and** two consecutive successful reads, ≥3 s apart, both lack pid. Record `record_close_observation(status="confirmed_closed")` (no sidecar apply), ledger `confirmed`.
     - partial leg: confirmed when a successful read shows pid with `abs(units - (units_before - units_deducted)) <= 2e-6`. pid absent ⇒ not visible yet, keep polling (T037 lag); pid with unchanged units ⇒ keep polling; pid with any other units ⇒ unresolved "unexpected units". Record ledger `confirmed` with `units_after`, `slice_position_id` (from raw positions, the non-pid entry), `close_price`, `proceeds`.
     - bound reached ⇒ ledger `unresolved`, stop.
  6. Intent `filled` only on ledger `confirmed`.

**D5 Ledger (migration 011).**
```sql
CREATE TABLE partial_close_effects (
  id INTEGER PRIMARY KEY,
  intent_id INTEGER NOT NULL UNIQUE REFERENCES intents(id),
  order_row_id INTEGER REFERENCES orders(id),
  order_id TEXT,
  position_id TEXT NOT NULL,
  units_before REAL NOT NULL,
  units_deducted REAL,            -- NULL = full close leg
  units_after REAL,
  slice_position_id TEXT,
  close_price REAL,
  proceeds REAL,
  status TEXT NOT NULL CHECK (status IN ('pending','confirmed','rejected','unresolved')),
  raw_json TEXT NOT NULL DEFAULT '{}',
  created_at TEXT NOT NULL,
  confirmed_at TEXT
);
CREATE INDEX idx_partial_close_effects_position ON partial_close_effects(position_id);
```
Repo methods: `insert_partial_close`, `set_partial_close_order`, `update_partial_close(id, *, status, units_after=None, slice_position_id=None, close_price=None, proceeds=None, raw=None)` (`confirmed`/`rejected` are final: updating a final row raises `ValueError`), `pending_partial_closes() -> list[dict]` (status pending/unresolved with intent not resolved), `confirmed_unit_reductions(since_iso, until_iso) -> dict[str, float]` (sum of `units_deducted` for confirmed partial legs with `confirmed_at` in (since, until]).

**D6 Integrity tolerance.** `compute_interval(..., expected_unit_reductions: Mapping[str, float] | None = None)`. In the held branch, when units dropped and `abs((p0.units - p1.units) - expected_unit_reductions.get(id, 0)) <= 2e-6` with expected > 0: `incomplete=True`, reason `position {id}: app partial close {p0.units}->{p1.units}, P&L attribution not modelled`, `continue` (no integrity). Units increase or mismatch: unchanged (integrity). Default `None` ⇒ identical behaviour to today. The closed slice ID is ignored by the existing round-trip loop when its `open_date <= prev.taken_at`; if it appears in closed history with a later open_date it is handled as today.

Any unresolved ⇒ `blocks_buys=True` (existing report field).
