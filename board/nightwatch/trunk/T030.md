# T030 — An armed session recovers unfinished work, applies limits, executes SCHG buys, sets HALT on a TP failure and saves state only when the whole decision filled

## Outcome
With `mode = "live"` and `NIGHTWATCH_ARM` set, `nightwatch run` no longer refuses with "armed execution not built". It runs the session armed:
- gate 11 first runs `recover_unfinished` (T029);
- after phase A, it applies `apply_submission_limits` (T026);
- it calls `execute_buys` (T028) with deadline = close minus 5 min and the configured order ceiling;
- it writes HALT if any take-profit is not confirmed cleared;
- it saves strategy state only under the narrow rule in Design 6;
- it takes the post-execution snapshot.

The dry-run path behaves exactly as today.

## Design (PM decisions)
1. **Arming decision, once, at the top.** `armed = config.is_armed`. If armed, compute `refusals = arming_refusals(config) + (["risk.max_orders_per_session unset"] if config.risk.max_orders_per_session is None else [])`. **`arming_refusals` itself is NOT changed**, so the dry-run "arming refused" text and `tests/test_session_decide.py:99-106` stay as they are. If that list is non-empty, return `SessionResult(None, "refused_armed", None, "armed but refused: " + "; ".join(refusals))` without creating a session or making any broker call. `tests/test_session_skeleton.py:73-84` asserts the obsolete text "armed execution not built (S7); refusing". Update that test to the new behaviour: an armed config with max_orders unset gives `refused_armed` and "armed but refused", no session row. This is the only existing test edit allowed.
2. **Session row:** armed → `create_session(iso, mode="live", environment=..., armed=True, state="preflight")`. Dry run is unchanged.
3. **Recovery in gate 11 (armed only).** `build_preflight_gates` gets `recover: Callable[[], RecoveryReport] | None = None`. In `reconciliation()`, if `recover` is set, call it first, store the report in a closure cell, then read the portfolio. If `recover()` raises, gate 11 fails with reason `"recovery: <Type>: <msg>"` (this returns a failing `GateResult`; it is not raised). The session passes `lambda: recover_unfinished(repo=repo, client=client, abandon_after_sessions=config.reconciliation.non_terminal_order_sessions_before_abandoned)`. Expose the report to `_run_session_core` (for example via a returned holder or a mutable list argument; the implementer picks one, and it must not change the gate-list contract for dry run). If the recovery report has `tp_failed`, write HALT (Design 7) immediately after `run_preflight` returns, **before** any early return (preflight fail :367, rerun :387, signal :393, decide :409–434). Add the HALT text to `reason` on every one of those paths, and pass `error=halt_error` to each `finish_session`. Implement this as one local helper used by all paths.
4. **Executable-decision check (armed).** After `insert_decision`, if any `d.intents` item is not `side == "open" and symbol == "SCHG" and amount is not None and amount > 0`: do not execute and do not save state. The reason says `"armed: decision has non-SCHG-open intents, S7-3a refuses: <summary>"`, then continue to the snapshot, finished, status `armed_refused_intents`.
5. **Limits then execute (armed).** `accepted, dropped = apply_submission_limits(d.intents, cap_usd=config.risk.max_notional_per_session_usd, reserved_usd=repo.reserved_buy_usd(iso), cash_usd=inputs.cash, open_lots=len(repo.list_lot_annotations(is_open=True)), max_open_lots=config.risk.max_open_lots, min_order_usd={s: config.strategy.min_order_size for s in config.symbols.traded})`. If `accepted` is non-empty, call `execute_buys(repo=repo, client=client, session_id=s.id, trading_date=trading_date, intents=accepted, instrument_ids=mi.instrument_ids, spy=inputs.spy, max_orders=config.risk.max_orders_per_session, deadline=session_close_datetime(trading_date) - timedelta(minutes=5), now=host.now)`. Any exception from `execute_buys` → reason `"execution error: <Type>: <msg>"`, no state save, continue to the snapshot. The reason lists:
- accepted/dropped counts;
- each `ExecutedBuy` as `<outcome> $<intent.amount requested> filled $<fill_amount_usd or n/a> <detail>`;
- `stopped`, the deferred count and the followups;
- from recovery: the `resolved`, `still_unresolved`, `abandoned` and `followups` counts/lines.

Track `orders_sent = bool(accepted)` before calling `execute_buys`. An exception can escape after a buy was sent, so `accepted` non-empty counts as "an order may have been sent".
5b. **(QA amendment 2026-10-23) No fresh exposure after a recovery TP failure.** If recovery's TP items are non-empty, whether the HALT write succeeded or failed: skip limits and `execute_buys`, do not save state, and add `"; execution skipped: take-profit not cleared at recovery"` to the reason. Status is `"halted_before_execution"` (CLI exit 1). The snapshot still runs, with no balance re-read.
6. **Narrow state-save rule** (PM policy for S7-3a, stricter than §7.2: a partly executed decision is not persisted, and the next session re-decides per §7.3). Call `strategy.state.save(repo, d.new_state)` only when all of these hold: armed, Design 4 passed, no execution exception, `dropped` empty, `report.stopped is None`, `report.deferred` empty, and every `report.results` outcome is `filled` with `len(results) == len(d.intents)`, no result `detail` contains `"partial fill"` (the executor's only partial marker, `executor.py:192-193`), and every result has a non-None `position_id`. A decision with zero intents also saves (nothing to fill; `bars` advances once). Otherwise do not save, and the reason includes `"strategy state not saved: <first failing condition>"`. The save comes after execution and before the snapshot (§7.2). Dry run never saves (unchanged).
7. **HALT on TP failure.** A filled `ExecutedBuy` with `position_id is None` counts as TP not confirmed (`executor.py:201-204` returns before the TP clear without adding to `tp_failed`). Add `"order <order_id>"` to the list of unconfirmed items. If `recovery.tp_failed`, `report.tp_failed` or that list is non-empty: `write_halt(host, reason="take-profit not cleared on position(s) <ids>", source="session")`. Use the same try/except pattern and `halt_error` as the existing snapshot HALT, with reason text `"; HALT set"` or `"; HALT persistence failed: ..."` so `run_session`'s existing HALT text stays correct. Never auto-sell. Do this before the snapshot. The alert is the generic session report, which `run_session` always sends with the reason. Also add to `run_session`: if `"take-profit not cleared"` is in `result.reason`, send one extra `notifier.send(..., event="tp_not_cleared")` with text `"[ENV] TP NOT CLEARED — <HALT set | HALT persistence FAILED ...>. Next session stops at gate 1 until you /resume."`. (QA amendment) When HALT persistence failed, the tail is instead `" Next session is NOT protected."`, matching the interval alert. Use the same try/except as the other alerts.
8. **Post-execution snapshot (armed).** Before building the snapshot, re-read `balance = client.get_balance()` when `orders_sent` (Design 5), including after an execution exception. `build_snapshot` raw `phase` stays `"post_decision"` for dry run. For armed runs, give `build_snapshot` an optional `phase: str = "post_decision"` parameter and pass `"post_execution"`. The `test_session_snapshot.py:56` assertion stays valid. On failure, keep the existing `"; snapshot failed: ..."` path. The snapshot then reflects the post-buy cash. Everything else in the block is unchanged.
9. **Statuses:** armed and finished → `"executed"` (even with zero accepted intents); Design 4 → `"armed_refused_intents"`; preflight/rerun/signal/decide failures keep their current statuses. `finish_session(state="finished", outcome=reason, error=halt_error)`.
An execution exception still finishes with status `"executed"`; the reason carries "execution error" and HALT applies per Design 7.
10. **CLI:** `role="write" if config.is_armed else "read"`. The exit code is 0 for `executed` too: `("would_have_done", "already_ran", "executed")`. `armed_refused_intents` exits 1.
