# T036 — `execute_closes` fully closes UPRO lots one at a time, confirms each against a successful portfolio read, applies it once, and stops on any doubt

## Outcome
A new `P/engine/close_executor.py` with `execute_closes(...) -> CloseReport` and `recover_unfinished_closes(...) -> CloseRecoveryReport`. Only UPRO full closes by `position_ref` are supported. Every other close is refused before any write. `CloseReport.blocks_buys` is True whenever any close is not confirmed and applied.

## Why
- Consultant 2026-10-24 (ticket D): the reduced release supports UPRO full closes and no SCHG sells. A read exception must never count as "absent". An unresolved close stops buying.
- Precheck T032:
  - polling must use `kind="close"` (the default is "open");
  - close referenceId recovery is unverified (`P/etoro/client.py:1398-1432`);
  - partial-close semantics were never observed.

## Design (PM decisions)
1. **`CloseOutcome`** frozen dataclass:
   - `intent: LadderIntent`, `intent_id: int | None`, `request_id: str | None`;
   - `order_row_id: int | None`, `order_id: str | None`, `position_id: str`;
   - `outcome: str`, one of `confirmed` | `rejected` | `unresolved` | `refused`;
   - `detail: str`.

   **`CloseReport`**:
   - `results: tuple[CloseOutcome, ...]`;
   - `stopped: str | None`;
   - `deferred: tuple[LadderIntent, ...]`;
   - `blocks_buys: bool`;
   - `followups: tuple[str, ...]`.
2. **`execute_closes(*, repo, client, session_id, intents, instrument_ids, positions_by_id: Mapping[str, Position], deadline, now=..., sleep=time.sleep) -> CloseReport`.**

   Pre-validation, over all intents **before any write**. Each must be `side == "close"`, `symbol == "UPRO"`, `position_ref` present and in `positions_by_id`, `amount is None`. If any fails: return a report with no writes, every intent marked `refused` with its reason, `stopped="refused: unsupported close"`, `blocks_buys=True`.

   Then, for each intent in order. Before each one, if `now() >= deadline`: defer the rest, `stopped="past deadline"`, `blocks_buys=True`.
   1. `request_id = new_request_id()`. Insert the `Intent` with side 'close', symbol UPRO, instrument_id, book = intent.book, `units = positions_by_id[pid].units`, `position_id = pid`, status 'pending'. Commit, then set status 'sent'.
   2. `order_id = client.close_position(request_id, pid, instrument_id)` (never pass units). On exception: `unresolved` ("close send failed: ..."). Insert an order row with order_id None and error set. Stop, `blocks_buys=True`. **Never resend.**
   3. Insert the order row (side 'close', order_id, reference_id = request_id, position_id = pid).
   4. `poll = client.poll_order_to_terminal(order_id=order_id, kind="close")`, in try/except.
      - On exception, or `poll.timed_out`, or a non-terminal status: update the order row and mark `unresolved`. Record an observation `unresolved` with the raw payload. Stop, `blocks_buys=True`.
   5. Terminal and not filled: `set_intent_status(..., "rejected", resolved=True)`, outcome `rejected`, and continue with the next intent. `blocks_buys` becomes True: the sale did not happen, so phase B must not assume its cash.
   6. Filled: confirm with a **successful** `get_portfolio()` read showing `pid` absent. Up to 10 tries, 3 s apart.
      - A read that raises does not count as a try result. Retry within the same 10-attempt budget.
      - If no successful read ever happened, or the position is still present after 10 successful reads: outcome `unresolved`, observation `unresolved` or `still_open`, stop, `blocks_buys=True`.
      - Absent on a successful read: `obs = record_close_observation(..., observed_status="confirmed_closed", units_closed=poll.order.fill_units, close_price=poll.order.fill_price, raw=poll.order.raw)`, then `repo.apply_confirmed_close(obs)`.
        - LookupError (no open annotation) → outcome `unresolved` with detail "confirmed at broker, no open sidecar", stop, `blocks_buys=True`.
        - Else `set_intent_status(..., "filled", resolved=True)` and outcome `confirmed`.
3. **`recover_unfinished_closes(*, repo, client, sleep=time.sleep) -> CloseRecoveryReport(resolved, still_unresolved, followups, blocks_buys)`.**
   1. For each `repo.unapplied_confirmed_closes()`: `apply_confirmed_close`. LookupError → followup and still_unresolved.
   2. For each close intent in status pending or sent (use `repo.pending_intents()`, `P/db/repo.py:1019`, filtered to `side == "close"`):
      - Order row with an order_id → `poll_order_to_terminal(order_id=..., kind="close")`, then the same confirm/apply path as Design 2.6 (no send).
      - No order id → leave it as is and add to still_unresolved with "close reference lookup unverified; manual check".
   3. **Never call `close_position`.** `blocks_buys = bool(still_unresolved)`.
4. **Why this shape:** buys are funded by confirmed sales only. Any doubt stops the session's buying. A missing record never permits a resend.


### Precheck amendments (PM, 2026-10-24; binding, override anything above)
1. **Order:** T036 builds after T034 is merged; use T034's real repo API as built.
2. **Strict portfolio read for confirmation:** add `EtoroClient.get_portfolio_strict()` in client.py (this one method only; add it to Scope, with tests). It makes the same request as `get_portfolio()` but raises `EtoroValidationError` when the envelope is not a dict or has no `positions` list. Close confirmation uses only this method. A raise means unresolved, never absent.
3. **Fill status:** only `OrderStatus.FILLED` (full) counts as executed. Partial or rejected-partial statuses become `unverified`, with `blocks_buys=True`, a followup line and HALT left to the session.
4. **Apply result:** `apply_confirmed_close` returning False (already applied) means `unverified` with a followup line "close already applied for position X". It never counts as a fresh confirmation.
5. **Prevalidation:** the mapped `Position.instrument_id` must equal `instrument_ids['UPRO']`. Duplicate `position_ref`s in one call: the whole call is refused before any write.
6. **Deadline:** checked before each close, and also before each poll loop and confirmation loop. When the deadline is crossed mid-close, stop polling, leave the intent `sent` and mark it `unresolved` (blocks buys). Never resend.
7. **Recovery branches:** poll exception, timeout or non-terminal → stays `sent`, unresolved. Terminal not filled → intent `rejected`, no observation applied, blocks buys this session. Filled → the same strict confirmation and apply as the live path.
8. **Observation status:** write `confirmed_full_close` only after FILLED + strict read absent; other outcomes are recorded with status `unverified` or `rejected` and never applied (T034 amendment 4).
9. **Observation fields:** fill units and price come from the close parser and are None today. Record None and keep `raw_json`. Do not invent values.
Tests: add one case per amendment (2–7).
