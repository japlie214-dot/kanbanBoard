# Gate 5 vs gate 11: who handles an abandoned-uncertain buy

## Outcome

An abandoned-uncertain buy has one defined path: either gate 11 reconciles it before gate 5 refuses, or gate 5 HALTs for a human with a clear message.

## Scope

preflight gate order/unresolved predicate only.

## Acceptance

PM/Boss decision recorded. Observed 2026-11-06 by T057 builder offline: gate=5 passed=False reason=1 unresolved order intent(s) before gate 11 can adopt (preflight.py:368). Tests pin the chosen order.

## Prove

Both pytest suites green from the repo root (venv and Python 3.13); git diff --check clean; QA probes with seeded intents observe gate 5 and gate 11 outcomes.

## Case for the decision (PM, 2026-11-07, at 5b5f246)

**Facts, from the code:**
- Only one place marks an intent `abandoned`: `executor.py:551-552`.
  - Since T052 it requires `sent_at IS NULL`.
  - T058 QA proved that every send path commits `sent_at` before the HTTP call.
  - So an `abandoned` row is now an order that certainly never reached eToro.
- Gate 5 (`preflight.py:367-370`) refuses any row from `unresolved_intents()` (`repo.py:1040`), and that list includes `abandoned`.
  - `abandoned` is set with `resolved=True` and never changes again.
  - So one abandoned row fails gate 5 on every future session, permanently.
  - The only way out is a human editing the DB.
- Gate 11's abandoned-buy adoption (`reconcile.py`, T057) can never run, because gate 5 stops the session first.
  - Since T052 it also has nothing to adopt: an unsent order cannot have filled.
- The original "abandoned-uncertain" case (sent, outcome unknown) no longer becomes `abandoned`.
  - It stays `sent`, and later recovery resolves it (T052).
  - Gate 5 still refuses it while it is unresolved. That is correct.

**Real problem:** not gate order. A certain non-order wedges every later session forever.

**Options:**
- **A. Gate 11 adopts automatically, before gate 5.**
  - Solves nothing real: there is nothing to adopt.
  - Reordering gates touches the most safety-critical part.
- **B. Keep today's behaviour (human).**
  - Every abandoned unsent order causes a permanent outage until someone edits the DB.
- **C (recommended). Gate 5 stops counting `abandoned` rows with `sent_at IS NULL`.**
  - These are resolved non-orders.
  - `sent`, `pending`, `filled_unannotated` and any legacy `abandoned` row with `sent_at` set still block, so a human looks at those.
  - Small and contained: one predicate plus tests. Gate order is unchanged.

**Acceptance if C:**
- A seeded abandoned row with null `sent_at` lets gate 5 pass.
- A seeded abandoned row with `sent_at` set still fails gate 5.
- `sent` and `filled_unannotated` rows still fail gate 5.
- The session report still lists the abandoned row, so it stays visible.
- Both suites pass.

## Decision (Boss, 2026-11-07): Option C, plus a gate-11 rule (latest wins)

1. **Gate 5:** `repo.unresolved_intents()`, or a gate-5-specific predicate, no longer counts `status='abandoned' AND sent_at IS NULL`.
   - `abandoned` rows with `sent_at` set still count.
   - `pending`, `sent` and `filled_unannotated` rows still count.
2. **Gate 11:** `resolve_abandoned_intent_adoptions` and `apply_reconciliation` never match a broker position to an abandoned intent whose `sent_at IS NULL`.
   - That position stays an unmatched discrepancy, and gate 11 fails closed.
3. **Visibility:** the session report or gate-5 detail still lists ignored abandoned-unsent ids, so they remain visible.

**Acceptance:**
- Gate 5 passes with a seeded abandoned row whose `sent_at` is null.
- Gate 5 fails with a seeded abandoned row whose `sent_at` is set.
- Gate 5 fails with a `sent` row, and with a `filled_unannotated` row.
- Gate 11 does not adopt a broker position against an abandoned-unsent intent, and it fails with an unmatched discrepancy.
- Gate 11 adoption against an abandoned row whose `sent_at` is set keeps today's behaviour.
- Both suites pass, and `git diff --check` is clean.
