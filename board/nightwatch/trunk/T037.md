## Design (PM decisions)
1. **Safety rails.**
   - Assert demo at start and abort otherwise.
   - Positions are created by the script only, at the configured `strategy.min_order_size` in SCHG (the cheapest legal size). Step 4 uses `max(2.5 × min_order_size, min)`, so a half-units partial close stays above the minimum.
   - Never touch a position the script did not open in this run.
   - Persist each request id to the run report **before** the POST.
   - Never resend a close. A step that fails is recorded and the script moves on, or stops when later steps depend on it.
   - Close everything the script opened at the end. If it can't, list the position ids in the report for the PM.
2. **Steps:**
   1. **Full close.** Open a fresh position; read portfolio and balance; `close_position(rid, pid, iid, None)`. Capture the request body and the acknowledgment.
   2. **Order-id lookup.** `lookup_close_order(order_id)`, then `poll_order_to_terminal(order_id=..., kind="close")`, then a fresh portfolio read (position gone?) and a balance read (actual cash change).
   3. **referenceId probe.** `lookup_order(reference_id=rid_from_step1)`. Record success, 404 or shape verbatim. A success counts only if the order and position match step 1.
   4. **Partial close.** Open a fresh position; `close_position(rid, pid, iid, units_to_deduct=units/2)`; close-route poll; portfolio read. Same position id kept? Units reduced by the requested amount? Capture all position and execution fields.
   5. **Lost response.** Open a fresh position. Send the close through a wrapper that lets the POST complete but discards its response, after persisting rid. Then recover with GETs only: the referenceId lookup and a portfolio diff. Assert exactly one close POST for that position.
3. **Fixture sanitizing:**
   - remove the `Authorization`, `x-api-key`, `x-user-key` headers and any `token`/`accessToken` keys at any depth;
   - replace account ids with `ACCOUNT`;
   - keep numbers and shapes exact;
   - pseudonymize order, position and reference ids consistently (`ORDER_1`...).
   - The script refuses to write a fixture that still contains a key matching `/token|secret|key|auth/i` with a non-placeholder value.
4. **CLI:** `python tools/demo_close_experiment.py --config ... --secrets ... --steps 1,2,3,4,5 --dry-plan`. `--dry-plan` prints the planned calls with no network. The script never reads secrets itself; it goes through `load_config`.
5. **Offline tests:** with an `httpx.MockTransport` fake, cover:
   - refusal on the real environment;
   - request ids persisted before the POST (report written before the transport sees it);
   - the step 5 wrapper sends exactly one POST;
   - the sanitizer strips headers and nested tokens and refuses leftovers;
   - `--dry-plan` makes no requests;
   - cleanup closes only positions the script opened.
