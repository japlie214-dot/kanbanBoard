# T018 — S6c-3: every session that creates a session row ends with one Telegram report, and the next run time is persisted

## Outcome
After `run_session` decides its result, a wrapper does two things:
1. It persists `next_run_at` = the next close minus 45 minutes on the session row.
2. It sends one Telegram message that carries the status, the full outcome reason ("would have done ...; arming refused: ...; snapshot ...") and the next run.

This covers every path that created a session: preflight failure, rerun/signal/decide failure, and `would_have_done`. A Telegram failure never changes the session result. `nightwatch run` builds the notifier.

## Why
- project.md S6: an unarmed dry run must report to the boss's phone. Today `run_session` has no notifier, and `_cmd_run` builds none (jack: `cli.py:71–100`). Boss approved real messages to the phone 2026-10-08.
- `next_run_at` exists in the schema (`schema.sql:79`) and in `finish_session`, but no caller sets it. The Telegram `/next` reply (`notify/commands.py:283–287`) therefore says "no scheduled run known yet" (no test asserts it).
- Wake = T-45 (project.md S6 design call). Kotlin owns the alarms and will read this value later. There is no OS scheduler on the desktop.

## Context (jack inventory 2026-10-08, read; P = `app/src/main/python/nightwatch`)
- `P/engine/session.py` `run_session(*, host, config, repo, client, trading_date, tiingo, wait=True, sleep_until=_sleep_until) -> SessionResult`. `SessionResult(session_id, status, failed_gate, reason)`.
- It has 9 return points:
  - `refused_armed`: no session row;
  - `already_ran`: the existing row, no finish;
  - `preflight_failed`, `rerun_failed`, `signal_failed` and 3 × `decide_failed`: `finish_session(state="aborted", outcome=reason)`;
  - `would_have_done`: `finish_session(state="finished", outcome=reason)`.
- `Repo.finish_session(session_id, state, outcome=None, error=None, next_run_at=None)` (`db/repo.py:859–867`) sets `finished_at`. The update allowlist in `update_session` includes `next_run_at` (`repo.py:831–839`).
- `P/market/calendar.py:235` `next_close_minus(minutes: int, after: datetime | None = None) -> datetime`. It returns an aware America/New_York datetime strictly after `after`. It skips weekends and holidays and honours early closes. It has 8 tests.
- `P/notify/telegram.py`:
  - `TelegramNotifier(config: TelegramConfig, repo: Repo, *, environment="demo", client=None, sleep=time.sleep)`.
  - `send(text, *, parse_mode=None, event="message", session_id=None, trading_date=None) -> Notification`: it catches Telegram errors, records `failed` and does not raise. Repo errors and unexpected exceptions can escape. Disabled or missing credentials give `skipped`.
  - It splits at 4096 characters.
  - Typed methods tag `[DEMO]`/`[REAL]`. Raw `send` does not.
  - It has `close()` and context-manager support.
- Tests: `tests/test_notify_telegram.py` has `FakeClient`/`FakeResponse`/`_configured_telegram`/`_no_sleep`. The `repo` fixture is in `conftest.py:65–71`.

## Scope
- `P/engine/session.py`: rename the current body to `_run_session_core` and add a reporting wrapper.
- `P/cli.py`: build and close the notifier.
- New `tests/test_session_report.py`. Update the existing session tests only where the signature change requires it.

## Out of scope

- Inbound commands (T019).

## Design (PM decisions)
1. **Rename** the existing `run_session` to `_run_session_core` with an identical signature and body. Make no edits inside it.
2. **New `run_session`**: the same keyword parameters plus `notifier: "TelegramNotifier | None" = None` and `now: Callable[[], datetime] = lambda: datetime.now(timezone.utc)`. It returns the same `SessionResult` the core returned, unchanged.
   - `result = _run_session_core(...)` passes every original argument through.
   - If `result.status == "already_ran"`, return `result` immediately. There is no report and no write: a repeated trigger must not spam the boss.
   - `next_run = next_close_minus(45, after=now())`, then `next_iso = next_run.astimezone(timezone.utc).isoformat(timespec="seconds")`.
   - If `result.session_id is not None`: `repo.update_session(result.session_id, next_run_at=next_iso)`. Wrap it in `try/except Exception`, and on failure log a warning and continue. Do **not** call `finish_session` again, because that would reset `finished_at`.
   - If `notifier is not None`: `text = format_session_report(result, trading_date=trading_date, environment=..., next_run_at=next_iso)`, then `notifier.send(text, event="session_report", session_id=result.session_id, trading_date=trading_date.isoformat())`. Wrap it in `try/except Exception`, and on failure log a warning. The result never changes.
   - Return `result`.
3. **`format_session_report(result: SessionResult, *, trading_date: date, environment: str, next_run_at: str) -> str`** is pure:
   ```
   [DEMO] NIGHTWATCH 2026-10-08 session 12: would_have_done
   <result.reason>
   next run: 2026-10-09T19:15:00+00:00
   ```
   - The tag is `f"[{environment.upper()}]"`.
   - `session {id}` becomes `no session` when `session_id` is None.
   - If `failed_gate` is not None, append ` (gate {failed_gate})` to the status line.
   - `reason` None is rendered as `(no reason)`.
   - Plain text, no parse_mode, so the reason's characters cannot break Markdown.
4. **The environment string** comes from the same source the notifier already uses. The CLI passes the identical value to both. Use exactly `config.environment.value` (precheck: same as `_cmd_telegram_test`, `cli.py:248–250`).
5. **CLI `_cmd_run`**: build `TelegramNotifier(config.telegram, repo, environment=config.environment.value)` and pass it as `notifier=`. Close it in the existing `finally`, next to `client.close()`. The CLI prints nothing extra: the audit row is in `notifications`. The CLI change is limited to building, passing and closing the notifier.
6. Why this shape:
   - The core keeps one responsibility: the session logic.
   - The wrapper owns side reports, so all 7 session-row paths are covered at one point instead of 9 edits.
   - Notifier failure isolation applies the same principle as T017 (snapshot never changes status) to Telegram.

## Plan
1. `session.py`: rename to `_run_session_core`; add `format_session_report` and the new `run_session` wrapper. Imports: `timezone`, `next_close_minus`, and a plain runtime import of `TelegramNotifier` (precheck: `preflight.py:124` already imports it; no cycle).
2. `cli.py`: notifier build, pass and close.
3. `tests/test_session_report.py`:
   - `format_session_report`: status line, the gate suffix, `no session`, `(no reason)`, and the env tag;
   - wrapper with a fake core result for each of `would_have_done`, `preflight_failed` (gate 10) and `decide_failed`: exactly 1 `notifier.send` call (one logical report; `send` may split text over 4096 characters into chunks, which is accepted) with the event `session_report`; the session row's `next_run_at` equals the expected UTC ISO for a fixed `now`. Use `now = 2026-10-08T14:00Z` (a Thursday, regular close), so `next_run_at == "2026-10-08T19:15:00+00:00"`;
   - `now` after T-45 on that day gives the next trading day;
   - `already_ran`: 0 sends, `next_run_at` unchanged;
   - `refused_armed` (session_id None): 1 send containing `no session`, no DB write;
   - a notifier whose `send` raises `RuntimeError`: the result is unchanged and `next_run_at` is still persisted;
   - `notifier=None`: no error, and `next_run_at` is persisted;
   - `finished_at` is unchanged by the wrapper (read the row before and after).

   To get fake core results, run the real core through the existing session test fakes where it is cheap. Otherwise monkeypatch `session._run_session_core`.
4. Run Prove.

## Ripple effects
- The `run_session` signature gains 2 optional kwargs → existing callers (cli, tests) are unaffected. Grep the callers.
- `next_run_at` is now set → the `/next` reply changes from "no scheduled run known yet" to `next run: ...`. Intended. The test for `_next_reply`, if any, may need no change; check it.
- One more Telegram send per session → shares Telegram's rate limits. There is one message per day, so negligible.
- The CLI now sends a real Telegram message on `python -m nightwatch.cli run` (no `nightwatch` launcher on PATH) when credentials are present → the PM's live runs will message the boss's phone. Intended: that is the S6 outcome.
