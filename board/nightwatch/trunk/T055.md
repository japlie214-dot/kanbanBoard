# T055: Crash recovery before gate 5 (audit G05)

## Outcome
After a process dies mid-session, the next armed session does the following before it trades:
- recovers the unresolved orders without resubmitting any buy or close;
- marks the dead session finished, with outcome `crashed_recovered` or `crashed_unresolved`;
- then continues through the gates normally.

## Why
Today a crash after a possible send needs manual DB repair, for two reasons:
- On the same date, the session returns `already_ran` (session.py:415-422) before it reaches recovery.
- On the next date, gate 5 fails (preflight.py:360-366). Recovery only runs at gate 11 (session.py:128-143, 167, wired at 529-534), which comes after gate 5.

## Context
- The line numbers come from the 2026-11-06 readiness audit at HEAD 21c06ba (project.md). The builder re-verifies every line before editing.
- The existing session lock is Android-entry only (android_entry.py:33-56, 97). `run_session` (session.py:962-979) and the CLI (cli.py:74-91) take no lock.
- The recovery helpers scan all sessions, not one session id (executor.py:704-715, close_executor.py:464-507).
- Buy recovery can send TP-clear PATCHes (executor.py:247-250, 633-638, 674-678).

## Scope
- `app/src/main/python/nightwatch/engine/session.py`: the shared lock in `run_session` and the pre-gate recovery step.
- `app/src/main/python/nightwatch/engine/preflight.py`: gate 5 refuses unresolved orders.
- `app/src/main/python/nightwatch/db/repo.py`: the `finalize_crashed` API and the unresolved predicate.
- `app/src/main/python/nightwatch/android_entry.py`: change only the same-date pre-engine return, so it defers to engine recovery. Build after T054 is committed.
- Tests: a new `tests/test_session_crash_recovery.py`, plus `tests/test_android_entry.py` for the entry change.

## Out of scope
- Executor and close-executor logic.
- Kotlin.
- T056 fill finalization.
- Engine deadlines.

## Design
The amendments below win where they differ.
1. Before the same-date dedupe and gate 1, while holding the shared session lock:
   - Find the unfinished session rows.
   - Run the existing `recover_unfinished_closes` and `recover_unfinished` once each.
   - Attribute the results to each crashed session by the intents' `session_id`.
   - Call `finalize_crashed(session_id, outcome)` for each one, with the fixed outcome label `crashed_recovered` or `crashed_unresolved`.
2. `crashed_unresolved` (any order still unresolved) sets HALT with a redacted reason. Gate 5 refuses while any unresolved order remains.
3. Same-date crashed session: after it is finalized, today's run still returns `already_ran`. There is never a second trading pass on the same date.
4. Recovery uses the armed write client only for what it already does, including TP clears. A dry session only reports.

## Plan
Shared lock, then the repo API, then the session step, then the gate-5 rule, then the android_entry handoff, then tests, then both suites.

## Ripple effects
- Gate 5 gains an unresolved-order rule.
- The HALT path is reused.
- Notifications gain the crash labels.
- The CLI and Android now share the engine lock.

## Watch
- Never call `execute_*` in this step.
- Take the lock first.
- A dry session does no recovery, HALT or crashed-row mutation.
- An empty `still_unresolved` report is not proof that nothing is unresolved: check the predicate in the DB.

## Acceptance
1. **Crash after send, filled:** the fake broker reports the order filled. The next-date armed session recovers it, finalizes it as `crashed_recovered` and passes gate 5. Recovery submits zero buys or closes (TP PATCHes are counted separately and allowed).
2. **Order still unresolved at the broker** (lookup missing, lookup raises, pending intent, or abandoned-uncertain): the session finalizes as `crashed_unresolved`, HALT is set, gate 5 refuses, and nothing trades.
3. **Same-date rerun through the real armed Android entry** (post-T054): recovery runs, then `already_ran`, with no buys.
4. **Dry session with a crashed row:** it reports the row. Recovery makes no recovery, HALT or crashed-row writes; the normal dry session-row writes still happen.
5. **Lock:**
   - A concurrent second `run_session` is refused while the lock is held.
   - A stale lock older than 50 minutes is taken over, and an audit event records it.
   - The CLI path acquires the lock.
6. Both full suites pass from the baseline, and `git diff --check` is clean.

## Amendments after precheck (2026-11-06; latest wins)
- **F1-F3, paths:** the scope paths are under `app/src/main/python/nightwatch/`, as listed above.
- **F4, lock contract:**
  - `run_session` acquires a shared session lock in the host lock dir, covering both the CLI and the Android entry. Recovery runs only while holding it.
  - A lock older than 50 minutes is stale. It may be taken over, with an audit record.
  - The lock replaces the unsupported claim that holding the lock proves the owner is dead.
- **F5, Android:** after T054 lands, android_entry's pre-engine same-date return (android_entry.py:105-119) defers to engine recovery when today's row is unfinished. android_entry.py is in scope, and this ticket is built after T054 is committed.
- **F6, guarantee:** recovery never resubmits a buy or a close. The existing TP-clear PATCHes in recovery remain possible; under T053 they are alert-only.
- **Unresolved predicate:** pending, sent and unknown intents are unresolved, and so is an abandoned-uncertain one (executor.py:509-525 can abandon an unknown buy). Tests cover:
  - a missing lookup;
  - a lookup that raises;
  - a pending intent;
  - abandonment.
- **Attribution:** the helpers scan all sessions. Run them once, attribute the results per crashed session by `session_id` from intents, and finalize each crashed session from its own rows.
- **Gate 5:** it already accepts `state='finished'` (repo.py:824-830). The new rule refuses unresolved orders. Crash labels live in `outcome`, and state stays `finished`.
- **Dry:** the recovery step does no recovery, HALT or crashed-row mutation. The normal dry row writes (session row and gate checks) stay.
- **Acceptance 3** runs through the real armed entry.
- **Identifiers:** the corrupted names (`already_ran`, `recover_unfinished*`, `finalize_crashed`) are restored.
