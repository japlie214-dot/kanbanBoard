# T047 — A pre-order network failure finishes the session cleanly and the acceptance runner reports send risk from the DB

## Outcome
- If market data cannot be fetched after the close−30 wake, the armed or dry session ends as `aborted`, with reason `market data: <ExceptionType>: <message>` and status `market_data_failed`. The session row is finished, not left in `preflight`.
- Any other exception raised after the session row exists, while the session has **zero intents**, also finishes the row as `aborted`, with reason `aborted before orders: <ExceptionType>: <message>`. If an intent exists, the exception propagates as today, keeping today's uncertain semantics.
- Market-data reads get a bounded retry for transient network errors.
- `tools/demo_acceptance.py` failure evidence derives `orders_may_have_been_sent` from the run DB instead of assuming `true`. It also reports the exception type, and the message only through the existing sanitizer.

## Why
T039 live run, 2026-10-30, `data/acceptance_20261030T163714557833Z`:
- Preflight passed at 16:37 UTC, and the session slept until close−30 (19:30 UTC).
- `fetch_market_inputs` then hit an eToro network error (SSL EOF), and `run_session` raised.
- The `sessions` row was left with `state='preflight'`, `outcome` NULL and `finished_at` NULL. There were zero intents, orders and decisions.
- `evidence/result.json` said `status: null, orders_may_have_been_sent: true`. The PM had to inspect the working DB by hand to learn that nothing was sent.

## Design
1. **Bounded retry around the post-sleep fetch.** Wrap the call at :474 in a loop of at most 3 attempts, 20 s apart, using the session's existing `sleep_until`/host clock so tests can inject time.
   - Retry only on `EtoroNetworkError`. Non-network eToro errors (validation, auth) are not retried.
   - Never start an attempt later than `session_close_datetime(trading_date) − 25 min`, the T040 entry upper bound, and never wait past it.
   - These are reads only, so a retry has no send risk. A separate pre-fetch connectivity probe is **not** added: it would be the same reads with no extra information, and a probe that passes does not stop the real fetch from failing.
   - After the last failure: `return abort("market_data_failed", f"market data: {type(exc).__name__}: {exc}", 10)`.
2. **Pre-order safety net.** In `_run_session_core`, after `s = repo.create_session(...)`, wrap the remaining body so that any unexpected `Exception`:
   - (a) reads `repo.get_intents(s.id)`. If that read itself fails, re-raise the original exception (treat it as uncertain).
   - (b) if the list is empty, calls `abort("aborted_before_orders", f"aborted before orders: {type(exc).__name__}: {exc}")`. Recovery text and HALT text append as in `abort`.
   - (c) otherwise re-raises the original exception unchanged.
   - Existing explicit `abort`/`SessionResult` returns are untouched. `BaseException` (KeyboardInterrupt) is not caught.
3. **Messages.** The `<message>` is `str(exc)`, truncated to 300 characters. eToro errors are already path-redacted by the client (`/***REDACTED***`). No new redaction is needed in the session, because the DB is local.
4. **`demo_acceptance.py` failure evidence.** In the except path:
   - If `started` is false, keep `orders_may_have_been_sent: false`.
   - Otherwise open the working DB **read-only** (`sqlite3.connect(f"file:{db}?mode=ro", uri=True)`, where `db = fresh_home_for(created) / "data" / "nightwatch.db"`). Count rows in `intents`, `orders` and `tp_clears`. Value: `true` if any count > 0, if the DB is missing, or if the read raises; otherwise `false`.
   - Add `"exception_type": type(exc).__name__`, always.
   - Add `"exception_message"` only as `Sanitizer(...)`'s output for `str(exc)` with the same config-derived secrets used for evidence. If the sanitizer cannot be built or raises, omit the field. Keep the :430 rule: unsanitized text never escapes.
   - Keep `WARNING` and the exit codes unchanged.

   - exactly 3 fetch attempts, with injected waits of 20 s;

## Amendments after precheck (2026-10-30, PM decisions; latest wins; HEAD now 25e332f with T045 committed)

- **Anchor fix:** `fetch_market_inputs` is `session.py:53-75`.
- **G1 (broker writes per invocation):** `_run_session_core` keeps an invocation-local `broker_write_attempted` marker. Recovery sets it before any broker write: TP clears on older sessions, and any recovery PATCH or POST. Retry (Design 1) and `aborted_before_orders` (Design 2) apply only when this session has zero intents **and** `broker_write_attempted` is false. Otherwise the exception propagates as today, with uncertain semantics. Add 3 older-session TP controls:
  - a recovery TP clear attempted, then a fetch failure: propagates, no retry;
  - the same with an unexpected exception: propagates;
  - recovery with no write (lookup only), then a fetch failure: clean abort.
- **G2 (sanitize):** any arbitrary exception message is passed through the existing redaction, seeded with config discovery, **before** the 300-character truncation. If sanitization fails, store `<ExceptionType>` only. Tests check the stored DB outcome, `SessionResult.reason` and the emitted notification text, each with a planted secret redacted.
- **G3 (cutoff semantics):** the guarantee is an entry cutoff, not a hard bound on inner requests.
  - Check the host clock before each outer attempt, after each injected sleep, and after a successful fetch.
  - If the clock is past close−25, or there isn't room for the 20 s wait plus another attempt, abort with `market_data_failed` and a reason that names the cutoff.
  - Inner client retries are not deadline-bound; that is out of scope.
  - Acceptance 1 becomes "up to three logical attempts, only when time allows". Add cases:
    - a fetch starting at close−25+ε: cutoff abort, no attempt;
    - a failure at close−25−30 s: no second attempt;
    - a fetch that succeeds after close−25: cutoff abort, not decide.
- **G4 (Android):** add `market_data_failed` and `aborted_before_orders` to `android_entry.py` `_STATUSES` (:59) and its mapping (:132). `android_entry.py` and `tests/test_android_entry.py` are in scope. Tests:
  - first wake: the new status is reported, not `error`;
  - next wake on the same date: `previous_unfinished`.
- **G5 (acceptance runner):**
  - Returned failure results also get a DB-derived `orders_may_have_been_sent`. That covers a non-zero exit from `run_session` without an exception, not only the except path.
  - `exception_type` is set only for caught exceptions.
  - End-to-end tests with a fake `run_session` cover both new statuses.
  - DB-count safeguards:
    - a missing, malformed or locked DB counts as true unless a read succeeds;
    - no `Repo.open`: raw read-only sqlite only, connection always closed;
    - an initialized but empty DB counts as false;
    - any order row counts as true, and any `tp_clears` row counts as true;
    - a sanitizer failure omits the message.
- **G6 (safety-net wording):** the net catches exceptions that escape the existing handlers. The tests:
  - zero-intent injection at `repo.record_price_window_fingerprint` or `repo.insert_decision` gives `aborted_before_orders`;
  - a post-intent control injected at the final `finish_session` propagates;
  - executor-error handling stays unchanged.
- **Size:** still one builder pass; no split needed.
