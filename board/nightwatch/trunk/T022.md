# T022 — Every session reports the UPRO+SCHG interval result. Alert A is loud. Alert C and an integrity mismatch write HALT before the alert.

## Outcome
After the T017 snapshot, `_run_session_core` computes `compute_interval` (T010) against the previous snapshot and appends one interval line to the outcome.
- `integrity`, or `alert_c`: it writes the HALT flag through a new atomic writer, carrying the reason, the time and the source, **before** anything is sent.
- The `run_session` wrapper (T018) then sends, after the normal report, one loud message per condition:
  - `ALERT A`;
  - `ALERT C — HALT set`;
  - `INTEGRITY — HALT set`;
  - `INCOMPLETE`.
- The decision summary in the report is grouped per side and symbol, so a 136-intent day stays one line.

## Why
- The boss's decisions (T010 ticket and its history): A at −$500 is alert-only, C at −$50 sets HALT, a units change (integrity) sets HALT, incomplete is loud with no HALT, and the boss resumes via Telegram.
- 2026-10-09 live: the report listed 136 intents one by one and was split across several Telegram messages.

## Design (PM decisions)
1. **`P/engine/halt.py`**, one responsibility: the HALT flag file.
   - `write_halt(host: Host, *, reason: str, source: str, now: datetime | None = None) -> Path`:
     - `path = host.halt_flag_path()`; create the parent directory.
     - If `path` already exists, **do not overwrite**: return `path`. The first cause wins; nothing is lost.
     - Otherwise write the JSON `{"reason": reason, "source": source, "set_at": <UTC ISO seconds>}` plus a newline to `path.with_name(path.name + ".tmp")`. Flush, `os.fsync`, then `os.replace(tmp, path)`.
     - Errors propagate (the caller decides).
   - `read_halt(host) -> dict | None`: None if absent. If present, parse JSON; if unparseable (the old plain-text flag), return `{"reason": <text stripped>, "source": "unknown", "set_at": None}`.
2. **`cli.set_halt(host)`** becomes `return write_halt(host, reason="halted by nightwatch.cli halt", source="cli")`. Its signature and docstring stay. `clear_halt` is unchanged. The Telegram `/halt` keeps calling `set_halt` (source "cli" there is acceptable until T019, which owns the command sources).
3. **Config:** `RiskConfig.max_unexplained_loss_usd: float | None = 50.0`, with the positive check like `max_daily_loss_usd`. The loader reads `[risk].max_unexplained_loss_usd` (absent gives 50.0; None/"" gives None). TOML: add `max_unexplained_loss_usd = 50.0` with a comment: "alert C: market-unexplained loss since last session; sets HALT (boss 2026-10-07/09)". Extend the `RiskConfig` docstring (`config.py:598–600` already says daily loss is alert-only; precheck) with: "max_daily_loss_usd = alert A threshold, alert only; max_unexplained_loss_usd = alert C threshold, sets HALT".
4. **`SessionResult`** gains `interval: "IntervalResult | None" = None` (a default, so every existing constructor still works).
5. **Decision summary** (:398–400): group the intents by `(side, symbol)` in first-seen order:
   - with amounts: `f"{side} {symbol} {n}x ${each:.2f} = ${total:.2f}"`, where `each` is shown only if all amounts are equal, else `f"{side} {symbol} {n} orders = ${total:.2f}"`;
   - intents without an amount (lot sells): `f"{side} {symbol} {n} lot(s)"`.

   Join with `"; "`. `would have done {len(d.intents)} intent(s): ...` is unchanged otherwise.
6. **In `_run_session_core`, the snapshot block becomes:**
   ```text
   prev = repo.latest_snapshot()            # BEFORE insert
   pnl = client.get_pnl(); snap = build_snapshot(...); sid = repo.insert_snapshot(snap)
   reason += snapshot line (unchanged)
   interval = _interval_for(prev, snap, client=client, managed_ids=..., config=config, today=trading_date)
   reason += "; " + format_interval(interval)
   if interval.state == "integrity" or interval.alert_c:
       try: write_halt(host, reason=<first reason or "alert C residual ...">, source="session")
            reason += "; HALT set"
       except Exception as e: reason += f"; HALT persistence failed: {type(e).__name__}: {e}"; halt_error = str(e)
   ```
   - The whole block stays inside the existing `try/except` that yields `snapshot failed`. If the snapshot fails, `interval` stays None and no HALT is written. Document that: no snapshot means no comparison.
   - `managed_ids = frozenset(mi.instrument_ids[s] for s in config.symbols.traded)` (UPRO, SCHG).
   - `finish_session(..., error=halt_error)` when the HALT write failed (else as today).
   - Return `SessionResult(..., interval=interval)`.
7. **`_interval_for(prev, snap, *, client, managed_ids, config, today) -> IntervalResult`** (module-level, testable):
   - `prev is None` → `compute_interval(None, snap, ...)` (no_baseline).
   - History: `start = prev.taken_at[:10]`, `end = today.isoformat()`. `rows = client.get_trade_history(start_date=start, end_date=end)`. On any exception, `closed = None`.
   - Else keep rows with `instrument_id in managed_ids` and (`close_date is None` or `close_date > prev.taken_at`, compared as UTC datetimes like T010's `_utc`). Dedupe by `position_id` (keep the first).
   - Map each to `ClosedLot(str(r.position_id), r.instrument_id, r.units, r.profit, r.fees, r.open_date, r.close_date)`.
   - A row whose `close_date` is None makes the history "pending": pass `closed=None` (T010 then reports incomplete).
   - `entry_marks = exit_marks = {}` (S7 supplies them; boss-accepted 2026-10-09).
   - `loss_alert_usd = config.risk.max_daily_loss_usd if not None else float("inf")`; `residual_halt_usd = config.risk.max_unexplained_loss_usd if not None else float("inf")`.
8. **`format_interval(r: IntervalResult) -> str`** (pure):
   - `no_baseline`: `"interval: no baseline (first snapshot)"`.
   - Else `f"interval: {r.state}, P&L {pnl}, {pct}, residual {res}"` with money as `$-1,234.56` (or `n/a`) and pct `-7.14%` (or `n/a`).
   - Then, if `r.reasons`: `"; reasons: " + " | ".join(r.reasons[:5])` and `" (+N more)"` if more.
9. **Wrapper `run_session`**, after the existing `session_report` send, only if `notifier is not None and result.interval is not None`. Each message is sent with `notifier.send(text, event=<event>, session_id=..., trading_date=...)`, each in its own `try/except Exception` with a warning log:
   - `alert_a` → event `alert_a`, text `f"[{ENV}] ALERT A — UPRO+SCHG P&L {pnl} since last session (threshold -${max_daily_loss_usd:,.0f}). Alert only, trading continues."`
   - `alert_c` → event `alert_c`, text `f"[{ENV}] ALERT C — HALT set. Loss not explained by market: residual {res} (threshold -${max_unexplained_loss_usd:,.0f}). Next session stops at gate 1 until you /resume."` If the outcome contains `HALT persistence failed`, the text is instead `f"[{ENV}] ALERT C — HALT persistence FAILED: ..."`, with the error, and says the next session is NOT protected.
   - `state == "integrity"` → event `integrity`, text `f"[{ENV}] INTEGRITY — HALT set. " + " | ".join(reasons[:5]) + " Next session stops at gate 1 until you /resume."` Same failure variant.
   - `state == "incomplete"` → event `interval_incomplete`, text `f"[{ENV}] INCOMPLETE P&L check — no HALT. " + " | ".join(reasons[:5])`.
   - `ENV = config.environment.value.upper()`.
   - HALT is written in the core, before the wrapper runs, so it always happens before these sends.
10. **DESIGN.md:** rewrite §6.C (starts :809, halt text :816) to "Daily loss: alert A (P&L ≤ −max_daily_loss_usd) is alert-only; alert C (market-unexplained residual ≤ −max_unexplained_loss_usd) and a units-integrity mismatch set HALT. See NIGHTWATCH T010/T022." In §6.I (starts :986, daily-loss text :991), replace "the daily loss guard (§6.C) tripping" with "alert C or a units-integrity mismatch (§6.C)".
11. **Why this shape:**
    - HALT writing lives in the core, next to the data, and before any network send, so a Telegram failure cannot skip it.
    - Messaging stays in the wrapper (T018's single responsibility).
    - The atomic writer is shared with the CLI and with T019.
