# T039 — A demo-only acceptance runner drives one armed session against the eToro demo account and captures the evidence

## Outcome
A new tool, `tools/demo_acceptance.py`, runs one armed T038 session (`run_session`) against the **demo** account. It uses a dedicated, freshly created `NIGHTWATCH_HOME` per run, so the production DB is never touched. It writes an evidence bundle to a new run directory. `--dry-plan` prints what would happen and makes **no network calls**. The PM runs it live during market hours, after T037.

## Why
- T038 (commit `34e9e3e`) wired closes then buys into the armed session. It is proven offline only. Consultant plan step F: one live demo acceptance before any further scope (G, Android wiring, real account).
- T037's experiment proves the raw broker contracts. F proves the whole session path on top of them: preflight, recovery, decision, closes, sale effects, cash reread, buys, snapshot and alerts.

## Design
1. **CLI:** `--config PATH --secrets PATH [--date YYYY-MM-DD] [--no-wait] [--dry-plan] [--seed-db PATH]`.
2. **Refusals:** each one exits 2 before any client is created and sends nothing.
   - **Not demo:** `config.etoro.environment` is not demo → "acceptance refused: etoro.environment must be demo".
   - **Not armed:** `config.is_armed` is false (live run) → "acceptance refused: not armed (mode=live and NIGHTWATCH_ARM required)".
   - **Run dir already exists:** "acceptance refused: run dir exists".
   - **Home is the real one:** the resolved `NIGHTWATCH_HOME` equals the default/production home.
3. **Fresh home:**
   - Create `data/acceptance_<UTC stamp>/home/` and set `NIGHTWATCH_HOME` to it before calling `get_host()`.
   - `--seed-db` copies the given DB into the fresh home first. This is the only way to start with existing lots, and the copy is read-only on the source.
4. **Run:**
   - Same wiring as `cli._cmd_run`: `Repo.open(default_db_path(host))`, then `EtoroClient(config.etoro, role="write", repo=repo)`, then `TelegramNotifier`, then `TiingoClient`, then `run_session(...)`.
   - Close every client in `finally`.
5. **Evidence:** written to `data/acceptance_<stamp>/evidence/`.
   - `result.json`: status, session_id, failed_gate, reason, exit code.
   - `tables/<table>.json` for every table above. Rows are filtered to that session where the table has a `session_id`; otherwise all rows.
   - `report.md`: a human summary listing preflight gates, intents, orders and fills, close observations, sale_effects applied, bucket changes and the snapshot.
   - The `Sanitizer` is applied to every file. Copy the pattern, don't import it, so T037 can change independently.
6. **Exit code:**
   - 0 if status is in `executed|would_have_done`;
   - 1 for any other status;
   - 2 for a refusal.
7. **`--dry-plan`:**
   - Needs no secrets and no network.
   - Prints the planned steps, the run dir it would create, and every refusal check that can be evaluated from the config if `--config` is given.
   - Constructs no client; tests monkeypatch `httpx` and socket to fail loudly.
8. **No retries and no loops.** One session per invocation.

## Precheck amendments (2026-10-26)
Binding. Where these conflict with earlier text, these win. Scope stays `tools/demo_acceptance.py` and `tests/test_demo_acceptance.py` only; `session.py`, executors, repo, config, CLI and strategy stay untouched.

**A1 Host isolation (F1).** Setting `NIGHTWATCH_HOME` is not enough: `host.py:144-159` builds the host at import. The runner builds `DesktopHost(fresh_home)` and installs it with `set_host`. Before any accessor that creates directories and before any `Repo.open`, it checks that the realpath of the resolved DB is under the realpath of `fresh_home` and not under the default or inherited production home; otherwise it refuses with exit 2. It passes `host=` explicitly everywhere and restores the previous host and environment in `finally`. Regression: import the runner first, then invoke it with the real host and repo wiring (no mocked `get_host`) while a production-home sentinel is in place; assert the production DB is never opened or created.

**A2 Evidence sanitizer (F2).** A new sanitizer lives in the tool; the experiment's class is not copied unchanged. It:
- decodes JSON-text columns (`raw_json` and every other column holding JSON) and sanitizes them recursively;
- discovers identifiers across the whole evidence set before any file is rendered;
- redacts free text, reasons, notification bodies and errors, and the Markdown report;
- redacts `chat_id` and any Telegram bot-token URL;
- fails closed before writing: either the whole sanitized bundle is written, or none of it is (only a minimal sanitized failure record).
The working DB under `home/` is not evidence and is never attached. Synthetic tests: JSON inside a string, an account id appearing only in text, a token-bearing error URL, identifier ordering across files, and sanitizer failure after orders were sent.

**A3 No seeding (F3).** `--seed-db` is removed. Every run uses a fresh home. The Live run section above is rewritten accordingly.

**A4 Evidence content (F4).** With a fresh DB, export every row of every table (no session filtering), including `lot_annotations` and `tp_clears`. Capture before and after copies of buckets, strategy state and annotations. Write `manifest.json` listing tables, row counts and the phases observed (closes, sale effects, buys, TP clears, snapshot).

**A5 Exit codes (F5).** The raw session status is reported separately. Exit 0 only when status is `executed` or `would_have_done` AND every acceptance check passes: every close intent confirmed with its sale effect applied, every buy intent filled, a `post_execution` snapshot present, and no unresolved intents. Otherwise exit 1. Refusals exit 2. Every exception path (config, constructor, session, evidence write) writes minimal sanitized evidence and exits nonzero.

**A6 Telegram isolation (F6).** `run_session` polls inbound commands only when `notifier is not None` (`session.py:786-792`). The runner passes a capture notifier: it records outbound messages into the evidence and sends nothing externally, and its inbound side returns no updates and never acknowledges an offset. The builder reads `notify/poll.py` and provides exactly the methods `process_pending` calls. Inbound-command acceptance is excluded. Test: the runner never reaches a real get-updates or offset acknowledgement. If no existing parameter allows this without editing `session.py`, the builder blocks and reports.

**A7 Retries (F7).** Line 65 is narrowed to: one `run_session` call per invocation, with no runner-level retry or resubmission. The existing bounded reads, polls, waits and TP-clear behaviour stay as they are.

**A8 Account boundary (F8).** Gate 7 deliberately issues read-only GETs to both the demo and real portfolio endpoints; that is expected and not bypassed. The guarantee is no real-account trading, not zero real-endpoint requests. The runner refuses (exit 2) unless `base_url` equals the default eToro HTTPS origin.

**A9 Dry plan (F9).** `--dry-plan` never calls `load_config` with secrets: it uses a config-only parse, or no config. It prints every arming prerequisite (live mode, `NIGHTWATCH_ARM`, risk limits, `max_orders_per_session`, fixed exit mode, demo environment, base URL). Tests forbid client construction, socket access, secret loading and filesystem mutation on both the no-config and explicit-config branches.

**A10 Cleanup and reruns (F10).** Register cleanup immediately after each successful construction (client, notifier, repo); test constructor, session and export failures. Print a warning that a fresh-home rerun is not recovery after an uncertain send: the existing-session check is DB-local (`session.py:382-388`).
