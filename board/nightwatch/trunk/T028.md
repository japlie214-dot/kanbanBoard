# T028 — `execute_buys` sends SCHG "cash to core" buys one at a time, records every step durably, annotates each fill, and clears its take-profit with read-back. It never resubmits.

## Outcome
A new `P/engine/executor.py` (replacing the TODO stub) with `execute_buys(...) -> ExecutionReport`. For each SCHG open intent, in order, up to `max_orders`:
1. persist the intent, then send the buy;
2. persist the order and poll it to a terminal state;
3. on a fill: read the broker position, write the lot annotation, clear the take-profit (each attempt persisted first) and confirm by read-back.

An ambiguous outcome stops execution and is never retried by resubmitting. A take-profit that cannot be cleared is reported so the session (T030) can set HALT (boss decision B). New config `risk.max_orders_per_session`. New table `tp_clears`.

## Why
- S7 plan item 5 ("narrow buy executor"), approved 2026-10-10. Boss: the app removes the TP after every buy; if it cannot, HALT and alert, never auto-sell (decision B).
- Real account (2026-10-09 read): 219 of 221 UPRO/SCHG positions carry a TP at about 11x, and a TP fill closes a lot behind the app's back.
- Consultant (2026-10-10): persist before send; recover by reference, never resubmit; annotate the actual fill; track TP clearing durably.

## Design (PM decisions)
1. **Types** (frozen dataclasses in `executor.py`):
   - `ExecutedBuy(intent: LadderIntent, intent_id: int, request_id: str, order_row_id: int | None, order_id: str | None, outcome: str, position_id: str | None, fill_amount_usd: float | None, detail: str)`. `outcome` ∈ `filled | rejected | unresolved`.
   - `ExecutionReport(results: tuple[ExecutedBuy, ...], stopped: str | None, deferred: tuple[LadderIntent, ...], tp_failed: tuple[str, ...], followups: tuple[str, ...])`.
   - `stopped`: why execution ended early, or None. `deferred`: intents not attempted. `tp_failed`: position ids whose TP is not confirmed cleared. `followups`: human lines (e.g. "position P not visible in portfolio").
2. **Signature:** `execute_buys(*, repo: Repo, client: EtoroClient, session_id: int, trading_date: date, intents: Sequence[LadderIntent], instrument_ids: Mapping[str, int], spy: Any, max_orders: int, deadline: datetime, now: Callable[[], datetime] = lambda: datetime.now(timezone.utc), sleep: Callable[[float], None] = time.sleep) -> ExecutionReport`. `spy` is the decision's SPY context object with attributes `ath`, `close`, `drawdown`, `tier` (= `inputs.spy`).
3. **Guards, before any HTTP:**
   - any intent with `side != "open"` or `symbol != "SCHG"` or `amount is None or amount <= 0` → `ValueError("S7-3a executes SCHG opens only: ...")`;
   - `max_orders < 1` → `ValueError`;
   - `now() >= deadline` → return `ExecutionReport((), "past submission deadline", tuple(intents), (), ())`.
4. **Per intent**, `n` = 1-based index; `sequence = repo.next_intent_sequence(session_id)` (computed per intent, so it never collides with earlier intents of that session). Stop **before** starting the next one when: attempted count == `max_orders` (the rest go to `deferred`; **`stopped` stays None**, the ceiling is a normal outcome), `now() >= deadline` (`stopped = "past submission deadline"`), or a previous result was not `filled` (`stopped` = its detail). Everything not attempted goes to `deferred`.
   1. `rid = new_request_id()`. `intent_id = repo.insert_intent(Intent(session_id, rid, sequence, "SCHG", "buy", instrument_id=instrument_ids["SCHG"], book="catapult", amount_usd=intent.amount, reason=intent.reason))`. Then `repo.set_intent_status(intent_id, "sent")`.
   2. `try: order_id = client.place_buy_order(rid, instrument_id, intent.amount)`.
      - **Definitely not accepted** only when the exception is `EtoroAuthError`, `EtoroRateLimitError`, or an `EtoroValidationError` whose `status_code` is **not None** (a real 4xx from the broker). Then `set_intent_status(intent_id, "rejected", resolved=True)`; outcome `rejected`, detail `f"buy refused: {type(e).__name__}: {e}"`; stop.
      - **Everything else is ambiguous**: timeout, network, 5xx, an `EtoroValidationError` with `status_code` None (the 2xx-without-order-id case, which may be a live order), or any other exception. Call `client.recover_by_reference_id(rid)` **once**, inside its own try/except (an error counts as None).
        - A non-None result `r` means the broker has the order: continue with `order_id = r.order_id` (it may be None), `recovered = True`, and the poll in step 4 uses `reference_id=rid`.
        - None → outcome `unresolved`, the intent stays `sent`, detail `f"buy outcome unknown ({type(e).__name__}); broker lookup found no order yet; NOT resubmitted"`; stop.
   3. `order_row_id = repo.insert_order(Order(intent_id, session_id, rid, "SCHG", "buy", instrument_id=..., order_id=order_id, reference_id=rid, submitted_at=<utc iso>))`.
   4. `poll = client.poll_order_to_terminal(order_id=order_id, reference_id=rid)` in try/except (pass both so the poll can fall back to the reference id). An exception, or `poll.timed_out and not poll.order.is_terminal` → outcome `unresolved`, detail "order not terminal (timeout/error); NOT resubmitted; if the last status was 5 (partially filled) a live partial position may exist without an annotation"; stop; the intent stays `sent`.
   5. `res = poll.order`. `repo.update_order_status(order_row_id, last_status=res.status.value, status_history=[res.status.value], terminal_status=res.status.value if res.is_terminal else None, fill_price=res.fill_price, fill_units=res.fill_units, fill_amount_usd=res.fill_amount_usd, position_id=res.position_id, order_id=res.order_id or order_id, error=res.reject_reason)`.
      - Not `res.is_filled` → `set_intent_status(intent_id, "rejected", resolved=True)`; outcome `rejected`, detail `f"order ended {res.status.name}: {res.reject_reason}"`; stop.
      - `res.is_filled` → `set_intent_status(intent_id, "filled", resolved=True)`; outcome `filled`. A partial status (5, 9, 10) adds "partial fill" to the detail.
   6. **After a fill:** `pid = res.position_id`. If `pid` is None → followup `"order {order_id} filled but no position id"`, no annotation, no TP clear, continue the loop (the outcome stays filled).
   7. **Read the position:** up to 10 attempts: `pos = next((p for p in client.get_portfolio() if p.position_id == pid), None)`. On a miss, `sleep(3.0)` and retry (a failed `get_portfolio` call counts as a miss). Still missing → followup `"position {pid} not visible in portfolio after 30 s: annotation and TP clear skipped"`; add `pid` to `tp_failed` (TP unverified); continue the loop. Gate 11 will flag the unannotated position at the next session; that is the intended safety net.
   8. **Annotation** (`entry_date` is the broker's raw `openDateTime`, as adoption does at `adopt.py:446` and reconcile at `reconcile.py:433`, because the re-link key is instrument + entry_date + entry_amount; fall back to the trading date only if the broker date is None): `repo.insert_lot_annotation(LotAnnotation(position_id=pid, symbol="SCHG", book="catapult", entry_date=pos.open_date or trading_date.isoformat(), entry_amount=pos.amount, origin="app", entry_context_source="derived", entry_reference_spy=spy.close, entry_spy_ath=spy.ath, entry_spy_close=spy.close, entry_spy_drawdown=spy.drawdown, entry_tier=spy.tier, bucket_id=None, entry_order_id=order_row_id, is_open=True))`. If it raises → followup with the error text; continue to the TP step anyway.
   9. **TP clear.** Helper `_tp_absent(pos) -> bool` = `pos.is_no_take_profit or (pos.take_profit_rate is not None and pos.take_profit_rate <= 0.0)`. **Do not use `find_broker_take_profits`** for this (it reports nothing when the rate is missing, which would count a missing rate as cleared). A missing rate with `is_no_take_profit` False is **not confirmed**. Up to `TP_ATTEMPTS = 3` attempts (module constants `TP_ATTEMPTS = 3`, `TP_READBACK_TRIES = 7`, `TP_READBACK_SLEEP = 3.0`, `READ_TRIES = 10`, `READ_SLEEP = 3.0`):
      - **If `_tp_absent(pos)` already**: `tp_id = repo.insert_tp_clear(order_row_id, pid, new_request_id(), 1)` then `repo.set_tp_clear_status(tp_id, "cleared", "already no TP at open")`, and skip the PATCH.
      - Else for `attempt` in 1..3: `rid_tp = new_request_id()`; `tp_id = repo.insert_tp_clear(order_row_id, pid, rid_tp, attempt)` (status `pending`, committed **before** the call).
        - `try: ack = client.clear_take_profit(rid_tp, pid)`.
          - `except (EtoroValidationError, ValueError) as e` → definite refusal: `repo.set_tp_clear_status(tp_id, "failed", f"refused: {type(e).__name__}: {e}")`; **stop attempts** (no retry).
          - `except Exception as e` → ambiguous: `set_tp_clear_status(tp_id, "failed", f"error: ...")`; go to the next attempt (the PATCH is idempotent).
          - success → `set_tp_clear_status(tp_id, "sent", detail=f"ack status {ack.status_code} op {ack.operation_id}")`.
        - **Read-back:** up to `TP_READBACK_TRIES`: `sleep(TP_READBACK_SLEEP)`, `cur = <position pid from get_portfolio()>` (a miss or an error means not confirmed this round); confirmed when `cur is not None and _tp_absent(cur)` → `set_tp_clear_status(tp_id, "cleared", resolved)`; stop attempts.
        - Not confirmed after the tries → `set_tp_clear_status(tp_id, "failed", "TP still present after read-back")`; next attempt.
      - If never `cleared` → add `pid` to `tp_failed`.
   10. Continue with the next intent (a `filled` result never stops the loop by itself).
5. **Report:** `results` in order; `deferred` = intents not attempted; `stopped` as above.
6. **Persistence table** `P/db/migrations/008_tp_clears.sql`:
   ```sql
   CREATE TABLE IF NOT EXISTS tp_clears (
     id INTEGER PRIMARY KEY AUTOINCREMENT,
     order_id INTEGER NOT NULL REFERENCES orders(id),
     position_id TEXT NOT NULL,
     request_id TEXT NOT NULL UNIQUE,
     attempt INTEGER NOT NULL,
     status TEXT NOT NULL CHECK (status IN ('pending','sent','cleared','failed')),
     detail TEXT,
     created_at TEXT NOT NULL,
     resolved_at TEXT
   );
   CREATE INDEX IF NOT EXISTS idx_tp_clears_position ON tp_clears(position_id);
   ```
   Just add the file; `migrate()` applies every version above the current one.
   - Repo methods: `insert_tp_clear(order_row_id: int, position_id: str, request_id: str, attempt: int) -> int` (status `pending`, `created_at` from the module function `utcnow()` in `repo.py:53`, commit; `Repo` has no `utcnow` method), `set_tp_clear_status(tp_clear_id: int, status: str, detail: str | None = None) -> None` (sets `resolved_at` from `utcnow()` for `cleared` and `failed`; commit), `next_intent_sequence(session_id: int) -> int` (`COALESCE(MAX(sequence), 0) + 1` over that session's intents), `list_tp_clears(position_id: str | None = None) -> list[dict]` (for tests/reports, ordered by id).
7. **Config:** `RiskConfig.max_orders_per_session: int | None = None` with the check `>= 1` when set (ConfigError otherwise). The loader reads `[risk].max_orders_per_session`. TOML: `max_orders_per_session = 1` with the comment "S7-3a safety ceiling: orders submitted per session (boss plan 2026-10-10); raise in S7-3b". Docstring updated.
8. **Why this shape:**
   - the executor is one module with injected client, repo and clock, so every failure is testable offline;
   - every write has its id persisted first (consultant);
   - there is no resubmit anywhere (T028 never calls `place_buy_order` twice for one intent);
   - the TP PATCH is the only retried write, because it is idempotent;
   - HALT stays out of the executor (one responsibility), which only reports `tp_failed`.

## Watch

- Do not retry the TP PATCH on a definite refusal.
