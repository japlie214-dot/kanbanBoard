# Operator-supervised adoption apply step on the device

## Outcome

An operator can adopt existing SCHG/UPRO broker positions into lot_annotations on the phone: dry-run plan shown first, apply only on an explicit operator action, idempotent, per home (demo now, real later).

## Scope

market/adopt.py, a new device runner under android-probe python/probe, Kotlin trigger, tests.

## Acceptance

Readiness audit 2026-11-07 G02: run_adoption_backfill is only ever called with dry_run=True (adopt.py:471-556, tools/adopt_backfill_runner.py:281); no device or CLI path writes. Deliver: on-device fetch of the home's portfolio + Tiingo SPY bars, dry plan persisted/shown, explicit apply (button or command, never automatic, never inside a session), account-bound marker so a plan from one account can't be applied to another; tests incl. weekend open-date resolution. Proof: manual demo SCHG positions adopted, then Monday-style session passes gate 11.

## Prove

Both pytest suites green; git diff --check clean; QA observes acceptance; device proof where the ticket says so.

## Design
Device runner `probe/adopt_apply.py` with plan(home) and apply(home, plan_id), explicit set_host(DesktopHost(home)) like T067. The plan is persisted as JSON in the home (plan_id, created_at, environment, account marker taken from the portfolio read, positions fingerprint, AdoptionPlan.report()). apply refuses on a missing or stale plan (>30 min), on an account or environment mismatch, or when the portfolio fingerprint changed; otherwise run_adoption_backfill(dry_run=False). Kotlin: MainActivity gets "Plan adoption (demo)" and "Apply adoption (demo)" buttons, with apply behind a confirm dialog. It is never called from a session, alarm or command.
