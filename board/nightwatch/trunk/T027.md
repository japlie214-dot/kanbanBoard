# T027 — Adoption stamps `entry_reference_spy` with the SPY close of the position's open date, so adopted UPRO lots can feed the decision

## Outcome
`market/adopt.py` builds each adopted `LotAnnotation` with `entry_reference_spy = context.close`. That is the SPY close on the trading date of the position's `openDateTime`, the same reconstructed value already stored as `entry_spy_close`. Positions whose date the SPY history does not cover stay **unresolved**, as today, so armed operation stays blocked for them. `build_ladder_inputs` keeps raising on a None reference (fail closed).

## Why
- Boss decision C (2026-10-10): use the SPY close on the open date. Where history is missing, block.
- jack-S7: adopted annotations set `entry_reference_spy=None` (`adopt.py:441–462`). `engine/session.py:231–245` raises `DecideInputError` for any UPRO annotation with a None reference, so every adopted UPRO lot would block every decision.

## Context (PM read 2026-10-10; P = `app/src/main/python/nightwatch`)
- `P/market/adopt.py` ~:425–462: if the SPY series does not cover the trading date, `plan.unresolved.append(UnresolvedPosition(...))` and continue. Else `plan.to_adopt.append(LotAnnotation(..., entry_context_source=DEFAULT_ENTRY_CONTEXT_SOURCE, entry_reference_spy=None, entry_spy_ath=context.ath, entry_spy_close=context.close, entry_spy_drawdown=context.drawdown, entry_tier=context.tier, ...))`.
- `entry_context_source` documents provenance (migration 005). Precheck: what values exist, and whether a distinct value should mark a reconstructed reference.

## Scope
- `P/market/adopt.py` (one field, plus a comment).
- `tests/test_market_adopt.py`.

## Out of scope
- Running adoption on any account (S4 / bootstrap).
- `build_ladder_inputs`.
- SCHG lots: the field is set for all adopted lots, harmless for SCHG. Precheck confirms nothing reads it for SCHG.

## Design
- `entry_reference_spy=context.close`, with the comment: "Boss decision C 2026-10-10: reconstructed reference = SPY close on the open date (same history as entry_spy_close). Uncovered dates stay unresolved above, never guessed."
- Keep `entry_context_source` unchanged, **unless** precheck shows that the source value explicitly claims the reference was recorded live. In that case report it; do not invent a new enum value.

## Plan
1. Edit as designed.
2. Tests:
   - an adopted UPRO position with covered history → `entry_reference_spy == entry_spy_close == the SPY close of that date`;
   - an uncovered date → still in `unresolved`, not adopted;
   - existing adoption tests: update only the assertions that expected None for this field, and list them.
3. Prove.

## Ripple effects
- Adopted rows now carry a reference → `build_ladder_inputs` accepts them. The tier and budget attribution for adopted lots then use the open-date close. That is the boss's intent.
