# T046 — The dry-run session is skipped on low power, and the power and HALT/scheduling rules have JVM unit tests

## Outcome
- Before `PyBridge.runSessionDry` is called, `WakeService` skips the session unless the phone is charging or its battery capacity is a valid 0–100 value ≥ 30.
- A JVM unit-test source set (`android-probe/app/src/test`) with injected fakes proves the power truth table and T045's HALT latch and scheduling transitions.
- Dry run only, never armed. Device behaviour stays unverified until the Z10 proof.

## Why
This is split out of T045 by the PM after the T045 precheck (corrections 4, 5 and 8). `DesktopHost` reports power gates as satisfied (`android_entry.py:3`), so the phone has no power gating. The Kotlin side also has no tests at all: there is no `app/src/test`.

## Out of scope

## Design
**D1 — predicate.** `shouldRunSession(charging, capacityPct) = charging || (capacityPct in 0..100 && capacityPct >= 30)`. A capacity of −1 or out of range counts as low.

**D2 — gate.**
- In `WakeService`, after T045's HALT check and right before `PyBridge.runSessionDry`.
- On skip:
  - log `SESSION_SKIPPED_POWER battery=<pct> charging=<bool>`;
  - post a failure notification;
  - make no Python call;
  - finalize normally inside the same try/catch structure.
- The defaults are constants: threshold 30, and charging always allows the run.

**D3 — JVM tests, plain JUnit with fakes (no Robolectric):**
- the power truth table: charging true or false × capacity −1, 0, 29, 30, 100, 101;
- the HALT latch, per T045 A1/A2:
  - `halt` latches, cancels the alarm and posts the notification;
  - a latched state suppresses every alarm mode, market included;
  - boot reconciles a present file into the latch before rescheduling;
  - `resume` clears only when the file is confirmed absent;
  - a failed delete keeps the latch;
  - a failed file creation still latches;
- scheduling, per T045 A3:
  - permission denied or `SecurityException` returns failure;
  - `KEY_MARKET_NEXT` is persisted only on success and cleared on cancel or failure;
  - a mode switch cancels the old alarm even when market scheduling fails.
