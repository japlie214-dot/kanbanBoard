# T004 — Second probe intent into a running app process loads the wrong config path

## Outcome
Any probe intent delivered to an already-running `MainActivity` uses `files/nightwatch_config`, or refuses clearly.
## Context (observed 2026-09-25 15:21 UTC)
After the T6 run, `am start ... --ez run_live_probe true --es sections D` was delivered to the running instance ("intent has been delivered to currently running top-most instance"). Runner logged `NOTE: NIGHTWATCH_HOME is only read the first time nightwatch.host is imported in this process` and failed `ConfigError('config file not found: /data/data/com.nightwatch.etoro/config/config.toml')`. Section D produced no output. After `am force-stop` the same command worked.
## Why it matters
The real session engine will run inside a long-lived process. A config path fixed at first import is a hidden state dependency; a wrong path must never fall back silently.
## Next
Precheck: where `nightwatch.host` reads `NIGHTWATCH_HOME`, and which probe path imported it first (T6 runner?). Then design.
