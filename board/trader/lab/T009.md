# Mandate headline cannot read as a pass on a large absolute loss or with gates not run

## Outcome

The mandate headline distinguishes a relative gate verdict from an absolute investment loss. It says PASSED, FAILED or INCOMPLETE for the five relative gates, identifies those not run, and puts any absolute loss beside the verdict. A run missing gates cannot pass the headline. An absolute loss does not add or change a gate.

## Why

Review 2026-11-12, finding F6: a synthetic path that lost 63 percent showed three green gates, because every gate is relative to SSO and UPRO on the same path, and gates G4 and G5 are never run by the web lab yet do not count against the result.

**Boss decision still open (decision 2 in `project.md`): headline only, or also an absolute-loss gate.** This design is the headline-only option, which the PM recommends: the gates are deliberately relative ("better than holding the leveraged fund"), and an absolute floor would fail every strategy in a crash path, including a correct one. If the Boss chooses the gate, it is one more field and one comparison on top of this design (see "If the Boss chooses the gate").

## Out of scope

## Requirements

1. Three verdicts: PASSED only when all five gates were evaluated and all are true; FAILED when any evaluated gate is false; INCOMPLETE otherwise.
2. The gates not run are named wherever the verdict is shown.
3. Growth of 1 dollar and maximum drawdown over the whole run are shown wherever the verdict is shown.
4. A run that ended below its starting capital is visibly marked as a loss, whatever the gates say.
5. `passed`, `gates_passed`, `gates_total` and the exit code of `--enforce-mandate` behave exactly as today.

## Design

**`metrics/score.py`** `MandateResult`:

```python
    # appended after the existing fields, with defaults so existing constructors keep working
    final_growth: Optional[float] = None      # ending equity / starting equity
    max_drawdown: Optional[float] = None      # most negative peak-to-trough, as a negative fraction

    GATE_NAMES = ("G1 return", "G2 risk score", "G3 anti-gaming", "G4 PBO", "G5 path robustness")   # class constant, not a field

    @property
    def gates_not_run(self) -> list[str]      # names whose gate value is None, in order
    @property
    def status(self) -> str:
        # "FAILED" if any evaluated gate is False
        # "PASSED" if all five are True
        # "INCOMPLETE" otherwise
```

`GATE_NAMES` must not become a dataclass field: declare it with `ClassVar`.

**`simulator_run/mandate.py`**: `run_mandate_check` computes `final_growth = equity.iloc[-1] / equity.iloc[0]` and `max_drawdown = (equity / equity.cummax() - 1).min()` from the equity series it already receives, and returns the result with those two fields set (`dataclasses.replace`). Non-finite values become `None`. Print-out: the result line becomes

```
  Result: INCOMPLETE (3/3 evaluated gates passed; not run: G4 PBO, G5 path robustness)
  Absolute: $1 became $0.37, max drawdown -63.0%
```

with `PASSED (5/5 gates)` and `FAILED (n/m evaluated gates passed)` in the other cases. `enforce` still uses `result.passed`.

**`replay_runner.py`**: the tape's `mandate` dict is `asdict(mandate_result)` plus `"status": mandate_result.status` and `"gates_not_run": mandate_result.gates_not_run`.

**`web/server.py`**: the run summary gains `status` and `max_drawdown` from the tape's `mandate` (absent on old tapes: `None`).

**Page**:

- The "Gates" tile leads with the verdict word: PASSED green, FAILED red, INCOMPLETE in the dim text colour with an amber left edge (add one CSS variable). Under it the five chips as today, and for INCOMPLETE the line "Not run: G4 PBO, G5 path robustness."
- The "Drawdown" tile shows two numbers: "now" (playhead) and "worst" (`mandate.max_drawdown`).
- The "What $1 became" tile turns red, with the word "loss", when the run's final growth is below 1. This uses the final frame, not the playhead, so scrubbing cannot hide it.
- Saved-run rows show the verdict word and worst drawdown.
- Tapes recorded before this change have no `status`: compute it in the page from the five gate values with the same three rules, and show "worst" as "n/a".

**If the Boss chooses the gate**: add `max_loss_limit: Optional[float]` to the check (for example -0.50), a sixth value `g6_absolute_loss = max_drawdown >= limit`, include it in `status`, and show it as a sixth chip. Not built here.

Why this shape: the verdict becomes a three-way word computed in one place and stored in the tape, so the page, the list and the command line cannot disagree; the existing boolean keeps its meaning for scripts that depend on it.
