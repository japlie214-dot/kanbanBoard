# Replays are kept across restarts and can be listed and reopened

## Outcome

A replay recorded in the lab is still available after the server restarts, and the lab can list past replays with strategy, market type, dates, seed and headline result. Replays recorded before this change are listed with id, time and size only; their seed was never stored and cannot be recovered.

## Why

Review 2026-11-12, finding F5: the server deletes every saved replay at startup and offers no list, so no run can be found again. The dashboard ticket (T006) needs a run list to open from.

## Context

Facts at `repos/etoro_trader` HEAD `8505b62`:

- `web/server.py:45-55` `lifespan`: if `REPORTS_DIR / "replays"` exists it is removed with `shutil.rmtree`, then recreated; `_runs` is cleared.
- `web/server.py:132-154` `create_replay`: runs `run_replay(ReplayConfig(...))` and writes the tape to `REPORTS_DIR / "replays" / f"{tape['tape_id']}.json"` with `json.dump(..., allow_nan=False)`; returns `{"tape_id": ...}`.
- `web/server.py:92-98` `ReplayRequest`: `strategy`, `data_source`, `start`, `end`, `seed`, `params`.
- A tape (`simulator_run/replay_runner.py:235-248`) has top-level keys `tape_id`, `strategy`, `data_source`, `start`, `end`, `tickers`, `strategy_metadata`, `indicator_columns`, `frames`, `mandate`, `benchmarks`, `equity_curve`, `harness_diagnostic_log`. It does not store the seed. `frames[i]["account"]["equity"]` is the account equity; `frames[i]["orders"]` is a list; `mandate["cagr"]` and `mandate["sso_cagr"]` are floats. Starting capital is fixed at 10000.0 (`replay_runner.py:126`).
- A 5-year synthetic tape is about 20 MB (measured in the review), so listing must not open tapes.
- Tape id format: `replay_YYYYMMDDTHHMMSS_xxxxxx`, UTC, so ids sort by creation time to the second. Two replays made in the same second sort by their hex suffix, which is arbitrary.
- `mandate["cagr"]` and `mandate["sso_cagr"]` are always floats (`metrics/score.py:165-176`, `metrics/risk_bundle.py:98-110`); never `None`. Nothing guards them against NaN on a broken equity curve.
- `create_replay` maps `ValueError` to HTTP 400 before its general 500 handler (`web/server.py:150-154`). `json.dump(..., allow_nan=False)` raises `ValueError` on NaN.
- `reports/replays/` is already ignored by git (`.gitignore:75`).
- After T001, `web/server.py` has `_TAPE_ID`, `_safe_child` and `REPORTS_DIR` read at call time.

## Scope

- `repos/etoro_trader/web/server.py`
- `repos/etoro_trader/tests/test_web_replay_store.py` (new)

## Out of scope

The page (`web/static/`). `simulator_run/replay_runner.py` (the tape format stays as it is). Automatic retention or size limits. The legacy `/api/run*` routes and `_runs`.

## Requirements

1. Startup never deletes anything under `REPORTS_DIR / "replays"`.
2. Each new replay gets a small summary file beside its tape.
3. `GET /api/replays` lists saved replays newest first without reading any tape file.
4. `DELETE /api/replay/{tape_id}` removes that tape and its summary and nothing else.
5. Tapes written before this change (no summary file) still open and still appear in the list.

## Design

All in `web/server.py`.

**Summary file.** Name: `{tape_id}.meta.json` in the same folder. It cannot be fetched or deleted through the tape routes, because `.meta` does not match `_TAPE_ID`. Content, written by `create_replay` right after the tape:

```python
frames = tape["frames"]
meta = {
    "tape_id": tape["tape_id"],
    "strategy": tape["strategy"],
    "data_source": tape["data_source"],
    "start": tape["start"],
    "end": tape["end"],
    "seed": req.seed,
    "params": req.params,
    "created_utc": <ISO 8601 UTC, seconds precision, from datetime.now(timezone.utc)>,
    "frames": len(frames),
    "orders": sum(len(f["orders"]) for f in frames),
    "final_growth": frames[-1]["account"]["equity"] / 10000.0 if frames else None,
    "cagr": tape["mandate"]["cagr"],
    "sso_cagr": tape["mandate"]["sso_cagr"],
    "tape_bytes": <size of the tape file after writing>,
}
```

Write the tape first, then the summary. Non-finite `final_growth`, `cagr` or `sso_cagr` are written as `null` (check with `math.isfinite`), so the summary write cannot fail on NaN. If building or writing the summary still raises any exception, including `ValueError`, delete the tape and return **500** explicitly: wrap the summary step in its own `try` so it does not fall into the existing `ValueError` to 400 handler. This covers handled failures only; a process kill between the two writes leaves a tape without a summary, which the list shows as `"summary": "missing"`.

**Helper.**

```python
def _replay_dir() -> Path:
    path = REPORTS_DIR / "replays"
    path.mkdir(parents=True, exist_ok=True)
    return path
```

Used by `create_replay`, `get_replay`, the list and the delete.

**`GET /api/replays`** returns `{"replays": [...], "total_bytes": int}`.

- Iterate `_replay_dir().glob("replay_*.json")`; keep only files whose stem fully matches `_TAPE_ID` (this skips `*.meta.json`).
- For each tape: if `{stem}.meta.json` exists and parses as a JSON object, use it; otherwise use `{"tape_id": stem, "created_utc": <parsed from the id>, "tape_bytes": <file size>, "summary": "missing"}` with the other fields absent. A summary file that fails to parse is treated as missing; it is not an error for the whole list.
- Sort by `tape_id` descending. Replays made in the same second have no defined order between them; that is accepted. `total_bytes` is the sum of tape file sizes.
- Tape files are never opened here; only `stat()`.

**`DELETE /api/replay/{tape_id}`**: `path = _safe_child(_replay_dir(), tape_id, _TAPE_ID, "tape", ".json")`; 404 if it does not exist; `unlink` the tape, then the summary with `missing_ok=True`; return `{"deleted": tape_id}`.

**`lifespan`**: becomes `_replay_dir()` plus the existing `_runs.clear()`. Remove the count, the `rmtree` and its log line. Remove the `shutil` import if nothing else uses it.

Route order: declare `GET /api/replays` as its own path; it does not collide with `/api/replay/{tape_id}`.

Why a sidecar file and not a field inside the tape: listing must not parse 20 MB files, and the tape format is consumed by 26 study scripts that should not change.

## Ripple effects

- Replays now accumulate on disk at about 4 MB per replayed year → the folder grows without limit → not bounded here: `total_bytes` makes the growth visible and the delete route makes it manageable by hand; a retention rule is a later decision for the Boss.
- `reports/replays/` keeps user data across restarts → already ignored by git (`.gitignore:75`, checked 2026-11-13). No `.gitignore` change.
- Page behaviour: `index.html` loads a tape named in the URL hash on load; after this change such links keep working across restarts. No page edit.
- Study scripts call `run_replay` directly and never touch the server → unaffected.

## Watch

- **Tests must never touch the real `reports/` folder.** Patch `web.server.REPORTS_DIR` to `tmp_path` before creating any `TestClient`.
- Do not run a real replay per test where a planted file will do: a replay takes seconds. One test may run a short real synthetic replay (`std_band_ladder_v2`, 2010-01-01 to 2010-03-31, seed 4, the same case `tests/test_web_replay_v05.py` uses) to prove the summary is written from real output; the rest plant small files.
- `allow_nan=False` is already used for the tape. Write the summary with `allow_nan=False` too, after replacing non-finite numbers with `None`. Add a test: a planted non-finite `cagr` produces `null` in the summary, not an error.
- "Restart" in a test means: leave the first `TestClient` context, create a second one on the same patched folder.
- A summary file must never be returned by `GET /api/replay/{id}`; cover it with a test (`replay_..._abcdef.meta` is a 400).
- Windows: close file handles before `unlink`.

## Acceptance

1. Record a replay, end the app, start it again on the same folder: `GET /api/replay/{id}` returns the tape.
2. `POST /api/replay` writes `{id}.json` and `{id}.meta.json`; the summary holds every field in Design with `seed` and `params` equal to the request.
3. `GET /api/replays` returns one row per tape, newest first, and `total_bytes` equal to the sum of tape sizes. With tape files replaced by invalid JSON of the same names the list still succeeds (proof that tapes are not parsed).
4. A tape with no summary file appears with `"summary": "missing"` and opens normally. A tape with a corrupt summary file is listed the same way.
5. `DELETE /api/replay/{id}` returns 200, removes both files, and a second call returns 404. Other tapes remain.
6. `DELETE` with a malformed id (`..%5Cx`, `replay_20260101T000000_abcdef.meta`) returns 400 and removes nothing.
7. `GET /api/replay/replay_20260101T000000_abcdef.meta` returns 400.
8. Starting the app with existing files in the replay folder leaves them byte-identical.
9. `tests/test_web_server_paths.py` and `tests/test_web_replay_v05.py` still pass.
