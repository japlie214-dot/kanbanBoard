# Lab dashboard page: strategy in action, portfolio and history in the reference-video style

## Outcome

The lab opens on a dashboard where the user picks a strategy and market, runs it, and sees on one screen what 1 dollar became, when the strategy held leveraged lots, what it holds at a chosen date, and every order with its reason, in the dark chart style of the reference video. Saved runs can be reopened from a list.

## Why

Boss, 2026-11-12: "I need dashboard to see the strategy on action and portfolio and history", in the style of the reference video. Review finding F5: the current page opens on an almost empty chart, is 15,929 px tall, keeps no runs and shows raw errors.

## Requirements

1. `GET /` serves the dashboard. `GET /vcr` serves the old page unchanged.
2. The dashboard makes no request to any other host: no remote font, script or style.
3. One run is shown at a time, with a playhead. Everything on the page except the run list reflects the run at the playhead.
4. Every chart title names the kind of market that produced it.
5. A failed run shows one plain sentence, never a stack trace or driver text.

## Design

Three static files, no build step, no library. The chart is drawn on a `<canvas>` by the page's own code, as in the prototype. Font stack: `Montserrat, "Segoe UI", system-ui, sans-serif` with no `@font-face` and no link, so the page uses Montserrat only where it is installed and never fetches it.

**Colours and roles** (CSS variables in `lab.css`, fixed across the page): background `#0a0a0c`, panel `#111114`, line `#26262b`, text `#f4f4f5`, dim `#8b8b93`; SPY white `#ffffff`; strategy teal `#2dd4bf`; UPRO orange `#f97316`; SSO purple `#a78bfa`; SCHG gold `#eab308`; gain green `#22c55e`; loss red `#ef4444`; order dot `#f4f4f5` with a dark outline.

**Layout** (desktop, 1280 px): left column 260 px, main column the rest.

- Left column, top to bottom: title "Strategy Lab"; Strategy select; Market segmented control; Start and End dates; Seed; "Run strategy" button; status line; "Saved runs" list.
- Main column: headline strip (5 tiles); path chart card with legend and the play controls; a two-column row with Portfolio and History cards.
- At widths below 900 px: one column, left column first, headline strip wraps to 2 per row, Portfolio and History stack. No horizontal page scroll at 400 px; tables scroll inside their own card.

**Market control.** Options come from one constant in `lab.js` so later tickets add to it:

```js
const MARKETS = [
  {value: "real",      label: "History",     title: "The History We Lived"},
  {value: "synthetic", label: "Null (GARCH)", title: "Null Market (GARCH): no edge should survive"},
];
```

Default selection: `synthetic` (it needs no data file). The Seed field is disabled when the market is `real`.

**Headline strip.** Five tiles: "What $1 became" (equity at playhead / 10000, two decimals, large); "CAGR" (`mandate.cagr`, whole run, labelled "whole run"); "vs SSO" (`(cagr - sso_cagr) * 100` in percentage points, green or red); "Drawdown" (`account.drawdown` at playhead); "Gates" (G1 to G5, each `pass`, `fail`, or `not run` when `null`; `not run` is dim, never green).

**Path chart.** Title from `MARKETS` by `tape.data_source` (unknown value: the raw value). A small tag at the top right: strategy key, market label, seed when known (from the run-list row; absent for legacy runs), and `data_info.first_date..last_date` when present. "LOG SCALE" pill at the top left toggles log and linear and shows the current mode. Series, all as growth of 1 dollar, drawn up to the playhead: SPY (`prices.SPY.c / first`), strategy (`equity / 10000`, thicker), UPRO, SSO, SCHG (`benchmarks[sym] / 10000`). Legend entries are buttons that hide or show a series; SCHG starts hidden. Grey bands behind the lines for every stretch of frames where `account.positions` holds at least one position whose symbol is in `LEVERAGED = ["UPRO", "SSO"]`. A dot on the strategy line at each frame with at least one order, up to the playhead. A dashed vertical cursor at the playhead. Year ticks on the x axis, dollar ticks on the y axis. Hovering the chart shows the date and the strategy's value at that frame in the status tag; clicking the chart moves the playhead there.

**Play controls.** Play/Pause button, a range input over the frames, a speed select (1x, 4x, 16x: 1, 4 or 16 frames per 30 ms tick), the playhead date. A newly opened or newly run tape opens with the playhead on the **last** frame, so the whole path is visible. Pressing Play at the last frame restarts from frame 0.

**Portfolio card.** One row per held symbol at the playhead: lots (count of positions), value, share of equity, unrealised result (signed, coloured); then Cash and Equity rows. Empty: "No positions on this date."

**History card.** Orders from the playhead backwards, newest first: date, action and symbol, units, price, realised result, reason. Fixed-height scroll area (260 px) with a sticky header. Render at most 500 rows; when more exist, a last row says how many older orders are not shown. Empty: "No orders yet."

**Saved runs.** Loaded from `GET /api/replays` on page load and after every run or delete. Each row: strategy, market label, start to end, growth (`final_growth`, "x" suffix), created time; legacy rows show the tape id and "no summary". The opened run is highlighted. Clicking a row opens that tape and sets the left-column controls to that run's strategy, market, dates and seed. Each row has a delete button; delete asks for confirmation with the browser's `confirm`, calls `DELETE`, refreshes the list, and clears the main column if the deleted run was open. Under the list: total size in MB.

**Page load.** Fetch strategies and runs. If a tape id is in the URL hash (`#replay_...`), open it. Otherwise open the newest saved run. If there are none, the main column shows an empty state: "No runs yet. Choose a strategy and press Run strategy." Opening a run sets the hash.

**Running.** "Run strategy" posts to `/api/replay`, disables the button, and shows "Running… N s" counting up every second. On success: refresh the list, open the new tape. On failure: status shows one sentence. For HTTP 400 use the server's `detail` text, first line only, at most 200 characters. For any other failure show "The run failed inside the lab. See the server log for details." Network failure: "Cannot reach the lab server."

**Text safety.** Strategy keys, reasons and any server text are inserted with `textContent` or escaped; no server string goes into `innerHTML` unescaped.

**`web/server.py`.** `GET /` returns `lab.html`; add `GET /vcr` returning `index.html` (the existing handler body). Keep the "not found" fallback text for each. No other change.

Why this shape: no dependency to download, so it works offline and the old page's internet dependency is not repeated; one constant list for markets and one for colours so T004 and T007 extend the page rather than rewrite it.
