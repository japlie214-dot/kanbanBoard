# Dashboard shows the alternative-histories fan chart and summary

## Outcome

From the dashboard the user runs N alternative histories and sees a fan of thin lines with one sentence stating the median, worst and best result and how many paths beat each benchmark. Clicking a line opens that history as a full replay.

## Why

Boss, 2026-11-12: synthetic market test data "like in the video". The video's central chart is "10,000 Alternative Histories": a dense fan of thin translucent lines with the median stated in words (review report section 8, row "Many paths").

## Requirements

2. A separate action runs many paths for the current controls. The page stays usable while it runs and shows progress.
3. The fan chart draws one translucent line per path, on the same scale mode as the path chart, with the median path emphasised.
4. One sentence states median, worst and best growth of 1 dollar and, for UPRO and SSO, how many of N paths beat it.

## Design

**Markets** (`lab.js`): add to `MARKETS`

```js
{value: "bootstrap", label: "Alt. histories", title: "One Alternative History"}
```

Keep `synthetic` as the default selection. The user chooses `bootstrap`; do not probe cache availability or infer it from saved replays.

**Block length**: a segmented control under Market, visible only for `bootstrap`: "1 month" (21), "6 months" (126, default), "3 years" (756). Its value is sent as `market_params: {mean_block}` on both the single replay and the job.

**`web/server.py`**: add `market_params: Dict[str, Any] = {}` to `ReplayRequest`; pass it as `synthetic_overrides=req.market_params or None` to `ReplayConfig` in `create_replay`; store it in the T002 summary as `market_params`. Before executing a single replay with `data_source == "synthetic"`, validate the override keys against the dataclass fields of `synthetic.generator.SyntheticConfig` (reuse the existing `dataclasses.fields` import). Any unknown key raises `ValueError("Unknown synthetic market parameter.")` within the existing ValueError-to-400 boundary. Do not broadly catch TypeError from strategy execution. The narrow validation is part of this ticket because forwarding an unknown constructor key currently produces TypeError and a 500. No runner or generator edit is authorized. This makes requirement 6 true for non-default block lengths and acceptance 11 true for invalid synthetic keys.

**Left column**: under "Run strategy" add a number field "Alternative histories" (1 to 500, default 50) and a button "Run N histories". The button is disabled, with a one-line reason under it, when the market is `real` ("Real history has one path. Choose Alt. histories or Null.").

**Fan card**, a new card below the path chart card and above Portfolio and History:

- Title: `"<N> Alternative Histories"` for `bootstrap`, `"<N> Null-Market Paths"` for `synthetic`, with the real N from the result.
- Tag top right: strategy, market label, block length when bootstrap, `seeds <first>..<last>`, dates.
- Canvas, same plotting code as the path chart (reuse its function; do not copy it). Each path: strategy teal at alpha 0.18, width 1. Median path (the path whose `final` is closest to `summary.median`): white, width 2, alpha 1. Worst and best paths: red and green, width 1.2, alpha 0.9. The pill state (log or linear) is shared with the path chart; toggling either redraws both.
- Right-edge labels for median, best and worst: the value as `$x.xx`.
- Under the chart, one sentence built from `summary`:
  `Median: $1 became $M. Worst $W, best $B. Beat UPRO in X of N, SSO in Y of N.`
  and a second, dimmer line: `Typical worst drawdown D%. Passed gates G1 to G3 in G of N. N paths took T.`
  When `summary.invalid` is present and above 0: append `K paths had no valid result.`
- Hover: the nearest path (by vertical distance at the cursor's x) is highlighted and the tag shows its seed and final value. Click: opens that path as a full replay through the existing run flow with `seed = path.seed`, the job's `strategy`, `data_source`, `start`, `end`, `params` and `market_params`; the path chart, portfolio and history then show it, and the fan keeps the clicked path highlighted.
- States: no result yet: "Run N histories to see how this strategy does across many markets." Market `real`: "Real history has one path. Run alternative histories to see the range." Running: progress bar `done / total`, elapsed time, estimated time left from `elapsed / done`, and a Cancel button (calls `DELETE`). Failed: one sentence from `error`. Cancelled: "Cancelled after k of N."
- Saved results: a small select "Earlier many-path runs" filled from `GET /api/paths`, newest first, each as `strategy · market · N · median $M`; choosing one loads it. A delete control beside it, with confirmation.

**Job flow**: `POST /api/paths`; poll `GET /api/paths/{id}` every 2 seconds while `running`; stop polling on any other status. On page load, if `GET /api/paths` shows nothing running the page does not poll. A 409 on start shows "A many-path run is already in progress." and attaches to nothing (the running job id is not exposed by the API; the user waits).

**Realism notice**: the page cannot know the gate result from the API. Keep it simple and honest: a fixed dim line on the fan card for `bootstrap`: "Built from about 16 years of real history since late 2009. It contains no 2008-style crisis." For `synthetic`: "Null market: prices have no memory. A strategy that profits here is suspect." The gate's PASS or FAIL is recorded by the PM in `project.md`; if it is FAIL this ticket does not ship (day plan).

**Text safety and offline**: as T006. No remote request. Server strings inserted with `textContent`.

Why this shape: the fan reuses the path chart's plotting function and the existing run flow for click-through, so there is one chart implementation and one way to open a run.

## Ripple effects

- `ReplayRequest` gains a field with a default → existing callers that omit it behave as before → the T002 summary gains `market_params`; the T006 run list ignores unknown fields. Covered by the added test.
- `synthetic_overrides` was never reachable from the API before → it now is, for both markets → for `synthetic` the GARCH config accepts named overrides (`mu`, `vix_mean`, ...) and raises on unknown names. The page sends `market_params` only for `bootstrap`; for `synthetic` it sends `{}`. An unknown key from a hand-made request surfaces as a 400 sentence. Test that.
- Polling every 2 seconds may continue for roughly 151 to 179 minutes at the builder's measured 18.1 to 21.5 seconds per path for 500 paths, before contention. These measurements are not an execution-time cap. Stop polling when the tab's job ends. Budget roughly 15 to 18 minutes for the 50-path job alone. Both jobs and click-through replays require roughly 19 to 22 minutes before cancellation tests and browser overhead; reserve at least 30 minutes for the full journey.
- Clicking a path starts a real replay (about 10 s for 3 years) while a job may be running → T005's lock makes it wait for the current path. The status line says "Waiting for the running job…" is not knowable from the API; show the normal "Running… N s".
- The fan card adds height → the page must still fit T006's "under two screens" rule at 1280 x 800 with the fan present: fan canvas height 280 px.

## Watch

- One plotting function. If the T006 function cannot take per-series alpha, width and a highlight, extend it; do not fork it.
- 500 paths x 260 points = 130,000 line segments per redraw. Draw the fan once to an offscreen canvas and blit it; redraw the offscreen canvas only on a new result, a resize or a pill toggle. Hover highlights draw on top.
- The median path is chosen by closeness of `final` to `summary.median`; with an even N the median value lies between two paths, so do not look for equality.
- `final` can be `null` for an invalid path: skip it in drawing and in nearest-path search.
- Path curves are thinned to 260 points; the full replay opened by click has every day. Their end values must agree to the cent: compare in the browser journey.
- Never present a `running`, `failed` or `cancelled` job as a result.
- Do not start polling a job id the page did not start.
- No git state changes. No installs. Do not edit `index.html`.
