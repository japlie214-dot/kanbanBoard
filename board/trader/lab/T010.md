## Design

**Version.** New value `0.8.0`: the lab redesign is a new minor version after the page tests' v0.7 naming. `VERSION` holds `0.8.0`. `README.md` status heading reads "Current status (v0.8.0, see VERSION)". The dashboard shows `v` + the value from `GET /api/health` in the left column under the title (one line of `lab.js`, `textContent`); no hard-coded number in the page. `common/version.py` docstring: replace the two "purged" sentences with "Changing the version does not delete anything. Nothing in this repository acts on a version change." **Only after** the builder has proven that (Plan step 1).

**`README.md`.** Rewrite the "Current status" section and the "how to run the lab" part to match what exists: start command, address `http://127.0.0.1:8765/` (dashboard) and `/vcr` (old page); the three markets and what each is evidence for (history: evidence; alternative histories: robustness, built from real blocks 2010 to 2026, no 2008-style crisis; GARCH: null test, profit there is a red flag); real data comes from `scripts/fetch_lab_prices.py` into `data/cache/lab_real/`; saved runs live in `reports/replays/`; how to add a strategy (one file in `harness/strategies/`, files starting `_` are skipped) once T008 has landed; the verdict words from T009. Remove or correct every sentence the check script flags. Keep the prime directive text.

**`AGENTS.md`.** Section 8: one row per top-level folder that exists, plus `web/`, `synthetic/bootstrap.py`, `simulator_run/paths_runner.py`, `scripts/fetch_lab_prices.py`. Section 9: only commands that pass the check; a command that does not exist yet stays in the list prefixed "planned:" . Section 2 (the Boss's verbatim architectural statement) is not edited.

**`doc/architecture_plan_v0.2.0.md`.** Add at the top, under the title, a table "Status on <date>": one row per phase and per named fix (1, 2a, 2b, 2c, 2d, 3...): `done` / `partly` / `not started`, the proving file or ticket, one sentence. Do not rewrite the plan body. Add one line under the 2a exit gate pointing to `board` record: the generic 2-sigma test showed no real rebound on 2010 to 2026; the gate in use is the strategy-signal measure (`project.md`, "Bootstrap realism result").

**`doc/README.md`.** Index line for the plan's status and for the web lab; mark `doc/web_replay_v0.3.0.md` to `v0.5.0.md` as describing the old page at `/vcr`.

**`.gitignore`.** Add under the reports block:

```
reports/paths/
reports/study_*.json
```

**`scripts/check_docs.py`.** Reads `AGENTS.md` and `README.md`; extracts (a) backticked tokens that look like repository paths (contain `/` or end in `.py`, `.md`, `.json`, `.html`, `.toml`, `.txt`) and (b) lines inside fenced code blocks that start with `python `. For each path: exists relative to the repository root, unless the same line contains the word "planned" or the path contains `<` or `*`. For each command: the script file exists; if the script accepts `--help` (it imports `argparse`), run it with `--help` and require exit code 0 within 60 seconds; scripts without `argparse` are checked for existence only and listed as "not run". Also checks that every version string of the form `v?\d+\.\d+\.\d+` in `README.md` headings equals `VERSION`. Prints a table and exits 1 on any failure. No network, no Snowflake: a command whose `--help` would import a Snowflake connection must not connect (imports only).

**`tests/test_docs_match_repo.py`.** Runs `check_docs.main()` and asserts exit 0; asserts `git ls-files` (read-only subprocess) contains neither `1.3` nor `2.0` once the PM has removed them (skip with a clear reason while they are still tracked, so the builder's run is green before the PM's removal).

**Removals (PM, after the Boss's approval).** `git rm 1.3 2.0`; `git rm sandbox/06_git_push.py` only if the Boss approves that file by name. The PM does not open `06_git_push.py`.

Why this shape: the documents are checked by a script that stays in the repository, so they cannot drift silently again; the version has one source and the page reads it.
