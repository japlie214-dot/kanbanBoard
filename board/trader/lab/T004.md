# Alternative histories: block bootstrap of real history as a lab market type

## Outcome

The lab offers a third market type that builds a new price path by reshuffling contiguous blocks of real history, keeping all symbols aligned inside each block, so path-dependent strategies meet realistic rebounds and volatility clusters. A study script measures whether the rebound after sharp falls survives the reshuffle, against real history and against the GARCH market.

## Why

Review 2026-11-12, finding F4, and the project's own measurement (`doc/architecture_plan_v0.2.0.md:108-116`): on GARCH paths the 5-day return after a 2-sigma down close shows no lift (t = 0.14) where real SPY shows +0.72 percentage points (t = 2.86). The Nightwatch strategy buys exactly those falls, so GARCH cannot test it. The August plan's Fix 2a (`:129-138`) specified a stationary block bootstrap; it was never built. The reference video builds its "10,000 alternative histories" the same way, from six-month blocks.

## Requirements

1. `data_source="bootstrap"` returns one frame per lab ticker over the business days of the requested window, with the same columns as the real frames.
2. Same seed, window and block length give identical frames; a different seed gives different frames.
3. Every symbol uses the same sampled source day on every output day.
4. The source is the real cache only. With no cache the T003 message is raised; synthetic data is never bootstrapped.
5. Mean block length is 21, 126 or 756 trading days; default 126.
6. GARCH stays available, unchanged.

## Design

**`synthetic/bootstrap.py`**

```python
MEAN_BLOCKS = (21, 126, 756)

def bootstrap_indexes(n_source: int, n_days: int, seed: int, mean_block: int = 126) -> np.ndarray:
    """Stationary block bootstrap (Politis-Romano): source row index for each output day.

    Indexes are in 1..n_source-1 (row 0 has no previous close). Each day continues the
    current block with probability 1 - 1/mean_block, else jumps to a uniformly random row.
    A block that reaches the last row wraps to row 1.
    """

def block_bootstrap(history: Dict[str, pd.DataFrame], dates: pd.DatetimeIndex,
                    seed: int, mean_block: int = 126) -> Dict[str, pd.DataFrame]:
```

- Random source: `np.random.default_rng(seed)`.
- `history` frames must share one index (the common real dates); raise `ValueError` if lengths differ or fewer than 300 rows.
- One `idx` array for all symbols.
- Per symbol: `ret = close[idx] / close[idx - 1]`; `new_close = close[0] * cumprod(ret)`; `open, high, low = new_close * (source_col[idx] / close[idx])`; every other numeric column that is a level and not a price (`vix`, `vix3m`, `volume` if present) is taken as `source_col[idx]`; any remaining column is copied by `idx` unchanged. Output column order equals the source frame's.
- Output index: `dates`.

`load_prices`: `"bootstrap"` → `load_bootstrap_prices(start, end, seed, (synthetic_overrides or {}).get("mean_block", 126))`. A `mean_block` not in `MEAN_BLOCKS` raises `ValueError("mean_block must be 21, 126 or 756")`. For `"synthetic"`, strip a `mean_block` key before building `SyntheticConfig` is **not** needed: it is only read for `"bootstrap"`; do not pass bootstrap keys to the GARCH loader and do not change the GARCH call. The error text for an unknown data source lists the four values.

**`replay_runner.py`**: `data_info` for `"bootstrap"`: `{"source": "bootstrap", "mean_block": N, "seed": seed, "real_first_date": ..., "real_last_date": ...}`.

**`scripts/study_bootstrap_rebound.py`**

One statistic, applied identically to a close series:

- `r[t] = close[t] / close[t-1] - 1`
- `sigma[t]` = standard deviation of `r` over the 60 days ending at `t-1` (population, `ddof=0`)
- event at `t` when `r[t] < -2 * sigma[t]`
- `f[t] = close[t+5] / close[t] - 1`
- `lift` = mean of `f` on event days minus mean of `f` on all days with a defined `sigma` and `f`

Output, as a table and as JSON at `reports/study_bootstrap_rebound.json`:

1. Real SPY (whole cache): lift, event count, Welch t between event and non-event `f`.
2. Bootstrap, for each mean block in 21, 126, 756: 200 paths (seeds 0 to 199) of 2,520 days, SPY frame only. Per path lift; report the mean lift, its standard deviation across paths, `t = mean / (sd / sqrt(200))`, the mean event count, and the ratio of mean lift to the real lift.
3. GARCH: 200 paths (seeds 0 to 199) of 2,520 days through `load_synthetic_prices`; the same summary.

The script takes `--paths` (default 200) and `--days` (default 2520) so tests can run it small. It prints nothing but the table and the JSON path.

**Exit gate** (reported by the script as PASS or FAIL lines, not enforced in code):

- G-a: bootstrap at mean block 126 has mean lift > 0 with across-path t > 2.
- G-b: that mean lift is between 0.5 and 1.5 times the real lift from row 1.
- G-c: GARCH across-path |t| < 2 **or** its mean lift is below 0.25 times the real lift.

If the real lift itself is not positive on this cache (row 1), the gate is "not applicable" and the script says so; that is a finding for the PM, not a failure of the code.

Why this shape: the index array is the whole method, shared by all symbols, so alignment is true by construction and testable by recomputing it. The study measures real, bootstrap and GARCH with one function, so no number depends on an older script nobody can find.

## Watch

- Index 0 must never be sampled (no previous close). Test the range.
- The wrap goes to row 1, not row 0.
- Do not use `np.random.RandomState` or the global seed.
- Requested windows longer than the source are fine: the bootstrap samples with replacement.
- Tests never touch the real cache or Snowflake: build a fixture cache under `tmp_path` in the T003 layout (random-walk prices for the four tickers, 800 rows, plus vix and vix3m) and point the cache location at it.
- The fixture must make identity testable: assert `out.close[i] / out.close[i-1] == src.close[idx[i]] / src.close[idx[i]-1]` within 1e-12 for every symbol and every `i >= 1`, with `idx` recomputed by `bootstrap_indexes`.
- Realised mean block length: count jumps in `idx` (a jump is `idx[i] != idx[i-1] + 1`, ignoring the wrap case) over 50,000 days; `n_days / (jumps + 1)` within 25 percent of the target for each of the three settings.
- The study must not be slow by accident: the statistic is vectorised; 200 paths of 2,520 days of one symbol should take seconds for the bootstrap. The GARCH generator may be slower; report the wall time.
- Never read, print or log credentials or connection configuration. No git state changes. No installs.
