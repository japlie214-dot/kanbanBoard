# Lab real-market data comes from a local price cache filled once from Snowflake

## Outcome

Choosing real market data in the lab reads a local daily price cache for SPY, SCHG, SSO, UPRO, VIX and VIX3M. The cache is filled by one script from the project's Snowflake tables. A missing cache produces one plain sentence saying how to create it.

## Why

Review 2026-11-12, findings F1 and F4: real data needed a live Snowflake connection on every replay, and the alternative-histories work (T004) needs the whole real history in memory. Boss, 2026-11-13: "the lab may even use the available credential data". So the source is Snowflake, but the lab reads a local copy.

## Context

Facts at `repos/etoro_trader` HEAD `8505b62`:

- `simulator_run/replay_data.py:11-53` `load_real_prices(start, end)`: calls `read_ohlc_from_snowflake(tickers=TICKERS, start, end)`, `read_vix_from_snowflake`, `read_vix3m_from_snowflake` (`data_query/snowflake_store/reader.py:21-75`), lowercases column names, builds one frame per ticker indexed by date with added `vix` and `vix3m` columns (forward-filled), and returns only the dates common to all four tickers. `TICKERS = ["SPY", "SCHG", "SSO", "UPRO"]`.
- The comment at lines 17-18 says real data must never fall back to synthetic or a local cache. This ticket replaces that rule with: real data is the local cache or nothing; it is still never replaced by synthetic data.
- `load_prices(data_source, ...)` at lines 71-82 accepts `"real"` and `"synthetic"` only.
- Snowflake tables: `ETOR_ASSET_PRICES` (columns include DATE, TICKER and OHLC), `ETOR_VIX_DATA`, `ETOR_VIX3M_DATA` (DATE, CLOSE). Exact column lists are not known to the PM; the builder reads them from the first fetch.

## Scope

## Out of scope

`web/server.py` and the page (other tickets are editing them). Any change to the Snowflake reader or writer. Any credential, `.env` or connection file: never opened, printed or copied. Committing price data. The synthetic loader.

## Requirements

1. `data_source="real"` reads the local cache only. It never opens a network connection.
2. `data_source="snowflake"` keeps today's direct behaviour, unchanged.
3. Cache missing or unreadable: `ValueError` whose message is one sentence naming the cache folder and the command to create it. No driver, cryptography or stack text.
4. Requested window outside the cached range, or a ticker with no rows in the window: `ValueError` naming the ticker and the cached range.
5. Real data is never replaced by synthetic data.
6. The tape records where its prices came from and the cached date range.

## Design

**Cache layout**, under `DATA_CACHE / "lab_real"`:

- `ohlc.csv`: the `ETOR_ASSET_PRICES` rows for the four tickers, all dates, column names lowercased.
- `vix.csv`, `vix3m.csv`: all rows, column names lowercased.
- `meta.json`: `{"source": "snowflake", "fetched_utc": ISO 8601, "tables": {...row counts...}, "first_date": "YYYY-MM-DD", "last_date": "YYYY-MM-DD", "tickers": [...]}`. `first_date` and `last_date` are the common range across the four tickers.

CSV, not Parquet: no new dependency and the Boss can open or replace the files by hand (fallback plan C in the day plan).

**`scripts/fetch_lab_prices.py`**: calls the three existing readers with no date filter (`read_ohlc_from_snowflake(tickers=TICKERS)`), lowercases columns, writes the three CSVs to a temporary folder beside the target, writes `meta.json`, then replaces the target folder's files (so a failed fetch leaves an existing cache intact). Prints row counts and the date range, never connection details. On failure prints `fetch failed: <ExceptionTypeName>` and exits 1; it must not print the exception message (it can carry account details).

`load_prices`: `"real"` → `load_real_prices(start, end, "cache")`; `"snowflake"` → `load_real_prices(start, end, "snowflake")`; `"synthetic"` unchanged; error text lists the three values.

`_assemble` must produce, for the same rows, exactly the frames today's code produces (same columns, index type, forward-fill, common-date intersection). Dates in the CSVs parse with `pd.to_datetime`.

**`replay_runner.py`**: add one top-level tape key `"data_info"`: for `"real"`, `real_data_info()`; for `"snowflake"`, `{"source": "snowflake-direct"}`; for `"synthetic"`, `{"source": "synthetic-garch"}`. No other tape change.

Why this shape: one cache read path that T004 (bootstrap) can call for the whole history, and a source that can be swapped by replacing four files.

## Watch

- Tests never touch the real `data/cache` folder or a network: monkeypatch `DATA_CACHE` (wherever `replay_data` reads it) to `tmp_path`, and monkeypatch the Snowflake readers.
- Never open, print or log credential or connection configuration. Do not import `common.config.Config` values into any message.
- Column case: Snowflake returns upper-case names; the cache stores lower-case. A `date` column may arrive as `datetime.date`; write ISO dates.
- Slicing: today's Snowflake path filters by date in SQL; the cache path must slice to the same inclusive window, or results differ.
- Keep the public names `load_real_prices`, `load_synthetic_prices`, `load_prices`, `TICKERS` and their existing positional parameters; scripts import them.
- The fetch replaces files only after all three reads succeed.

## Acceptance

1. With fixture cache files and no network, `load_prices("real", "2020-01-01", "2020-12-31", seed=0)` returns four frames with columns including `close`, `vix`, `vix3m`, on common dates inside the window only.
2. For the same input frames, the cache path and the Snowflake path (readers monkeypatched to return the same rows in upper case) return equal frames.
3. Cache folder absent: `ValueError`, message contains the folder and `python scripts/fetch_lab_prices.py`, and none of `snowflake`, `cryptography`, `Traceback`.
4. A ticker missing from the cache, and a window outside the cached range: `ValueError` naming the ticker or the cached range.
5. No code path from `"real"` reaches the synthetic generator or a Snowflake reader (asserted by monkeypatching both to raise).
6. `run_replay` on fixture real data produces a tape with `data_info.source == "snowflake"` (from meta), `first_date`, `last_date`; on synthetic, `data_info.source == "synthetic-garch"`.
7. `fetch_lab_prices` with patched readers writes three CSVs and `meta.json` with correct counts and range; with a reader raising, exits 1, prints only the exception type name, and leaves a pre-existing cache byte-identical.
8. `tests/test_web_replay_v05.py` still passes; `scripts/ci_import_check.py` passes.
9. Builder report: caller list for `"real"`, the `git check-ignore` result, and whether the API accepts `"snowflake"`.
